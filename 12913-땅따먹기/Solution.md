# [프로그래머스 12913] 땅따먹기 — DP로 "직전 행의 최댓값"만 이어받기

- 문제 번호: 12913
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12913
- 분류: 연습문제
- 사용 자료구조/알고리즘: **DP (동적 계획법)**
- 난이도 체감: Lv.2 (열이 4개로 고정이라 DP 입문용으로 적당)

## 1. 문제 요약

`N`행 `4`열의 `land`에서, 1행부터 한 행씩 내려오며 매 행 한 칸씩 밟는다. **단, 바로 이전 행에서 밟은 열과 같은 열은 이번 행에서 밟을 수 없다.** 마지막 행까지 내려왔을 때 얻을 수 있는 최대 점수를 구한다.

```text
land = [[1,2,3,5],
        [5,6,7,8],
        [4,3,2,1]]
→ 1행 4번째(5) + 2행 3번째(7) + 3행 1번째(4) = 16
```

**제한사항**: 행 수 `N ≤ 100,000`, 열은 항상 4개, 각 점수는 100 이하.

## 2. 접근 아이디어 — "i행 j열을 밟았을 때의 최대 누적 점수"를 정의

`dp[i][j]` = **i행까지 내려왔고, i행에서 j열(0~3)을 밟았다고 가정했을 때의 최대 누적 점수**로 정의한다.

`i`행에서 `j`열을 밟으려면, `(i-1)`행에서는 `j`열이 아닌 다른 열을 밟았어야 한다. 그러니 점화식은:

```
dp[i][j] = land[i][j] + max(dp[i-1][k])   (k ≠ j인 모든 k에 대해)
```

기저 조건은 `dp[0][j] = land[0][j]` (첫 행은 제약이 없으므로 그대로).

최종 답은 마지막 행의 `dp[N-1][0..3]` 중 최댓값이다.

### 손으로 시뮬레이션 — `land = [[1,2,3,5],[5,6,7,8],[4,3,2,1]]`

| 행 | dp[0열] | dp[1열] | dp[2열] | dp[3열] |
|---|---|---|---|---|
| 0행 (기저) | 1 | 2 | 3 | 5 |
| 1행 | `5+max(2,3,5)=10` | `6+max(1,3,5)=11` | `7+max(1,2,5)=12` | `8+max(1,2,3)=11` |
| 2행 | `4+max(11,12,11)=16` | `3+max(10,12,11)=15` | `2+max(10,11,11)=13` | `1+max(10,11,12)=13` |

마지막 행(`2행`)의 최댓값 = `max(16,15,13,13) = 16`. 예상과 일치. (1행 4번째→2행 3번째→3행 1번째로 이어지는 경로가 정확히 이 표의 `1행 3열=12`, `2행 0열=16` 계산 안에 녹아 있다.)

## 3. 코드 (Java)

```java
class Solution {
    public int solution(int[][] land) {
        int[][] dp = new int[land.length][land[0].length];

        for (int i = 0; i < land.length; i++) {
            for (int j = 0; j < land[0].length; j++) {
                int max = 0;
                if (i != 0) {
                    max = getMax(dp[i - 1], j);
                }
                dp[i][j] = land[i][j] + max;
            }
        }

        int answer = 0;
        for (int value : dp[dp.length - 1]) {
            answer = Math.max(answer, value);
        }

        return answer;
    }

    private int getMax(int[] prevRow, int excludeCol) {
        int max = 0;
        for (int i = 0; i < prevRow.length; i++) {
            if (i == excludeCol) continue;
            max = Math.max(max, prevRow[i]);
        }
        return max;
    }
}
```

### 코드 설명

- `dp[i][j]`를 2차원 배열로 그대로 만들어서, 점화식(`land[i][j] + 이전 행에서 j열을 제외한 최댓값`)을 코드로 옮겼다.
- `getMax(prevRow, excludeCol)`: 이전 행(`dp[i-1]`)의 4칸 중 `excludeCol`(지금 밟으려는 열)을 제외한 나머지 3칸의 최댓값을 구한다. 열이 4개뿐이라 이 탐색은 항상 상수 시간(`O(4)`)이다.
- `i == 0`(첫 행)일 때는 `max = 0`으로 시작 — 이전 행이 없으니 제약 없이 `land[0][j]` 그대로가 `dp[0][j]`가 된다.
- 마지막 행의 4칸 중 최댓값이 최종 답.

## 4. 복잡도 분석

- **시간복잡도**: `O(N × 4 × 4) = O(N)` — 행마다 4개 열을 계산하고, 열마다 `getMax`가 `O(4)`. 열 개수가 상수(4)로 고정돼 있어 사실상 선형.
- **공간복잡도**: `O(N × 4) = O(N)` — 매 행의 dp 값을 전부 배열에 저장.

실측(`N = 100,000`, 무작위 데이터): **약 2.3ms**로 매우 여유롭다.

> 참고로 공간은 `O(1)`(직전 행 4칸만 변수로 유지)로도 줄일 수 있다 — [멀리 뛰기(12914)](../12914-멀리뛰기/Solution.md), [피보나치 수(12945)](../12945-피보나치수/Solution.md)에서 쓴 "직전 값만 유지하는 rolling 최적화"와 같은 패턴. 다만 `N ≤ 100,000`, 열 4개 규모에서는 `O(N)` 공간도 전혀 부담이 없어서 지금 코드로도 충분하다.

## 5. 검증

문제 조건을 그대로 재귀로 완전탐색하는 참조 구현(작은 `N`에서만 가능)과 **3,000회 무작위 데이터로 대조 검증**해서 전부 일치함을 확인했다.

## 6. 엣지 케이스

- `N = 1` (한 행뿐): 제약 없이 그 행의 최댓값이 곧 답.
- 모든 칸의 점수가 같은 경우: 어느 열을 밟아도 결과가 같으므로, 매 행 "직전과 다른 아무 열"만 고르면 항상 최댓값에 도달한다 — 이 DP는 그런 경우도 자연스럽게 올바른 값을 낸다.
