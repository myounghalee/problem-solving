# [프로그래머스 12973] 짝지어 제거하기 — 스택으로 풀기

- 문제 번호: 12973
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12973
- 분류: 2017 팁스타운
- 사용 자료구조/알고리즘: **스택(Stack)**
- 난이도 체감: Lv.2 (스택 개념만 알면 어렵지 않음)

## 1. 문제 요약

알파벳 소문자로 이루어진 문자열이 주어진다. 다음 과정을 반복한다.

1. 문자열에서 **같은 알파벳이 연속으로 2개 붙어 있는 짝**을 찾는다.
2. 그 둘을 제거하고, 남은 앞뒤 문자열을 이어 붙인다.

이 과정을 반복해서 문자열을 **완전히 다 지울 수 있으면 1**, 더 이상 지울 게 없는데 문자열이 남아있으면 **0**을 반환한다.

```text
예시) s = "baabaa"
b aa baa → bb aa → aa → (빈 문자열)
```

**제한사항**
- 문자열 길이: 1,000,000 이하의 자연수
- 문자열은 모두 소문자

문자열 길이가 최대 100만이라는 점이 힌트다. `O(n²)` 방식(매번 문자열을 스캔하며 인접 쌍을 지우고 다시 이어 붙이는 방식)으로는 시간 초과가 나기 쉬우므로, **한 번의 순회로 처리할 수 있는 방법**을 찾아야 한다.

## 2. 접근 아이디어 — 왜 스택인가

"연속된 같은 문자 2개를 지운다"는 규칙을 곰곰이 보면, **괄호 짝 맞추기 문제와 완전히 동일한 패턴**이다.

- 문자를 하나씩 앞에서부터 읽어가며 쌓아 올린다(push).
- 방금 읽은 문자가 **바로 직전에 쌓아둔 문자와 같다면**, 그 둘은 서로 "짝"이 되어 사라진다 → 쌓아둔 문자를 꺼낸다(pop).
- 같지 않다면 그냥 계속 쌓는다(push).
- 문자열을 다 읽었을 때 **스택이 완전히 비어있다면** 모든 문자가 짝을 이루어 지워진 것 → `1`.
- 뭔가 남아있다면 더 이상 지울 수 없는 문자가 남은 것 → `0`.

핵심 통찰: 문자열 중간에서 두 문자가 사라지면, 그 바로 양옆에 있던 문자끼리 새롭게 이웃하게 된다. 이건 정확히 스택에서 pop을 했을 때 그 아래에 있던 원소가 새로운 top이 되는 동작과 같다. 그래서 **"직전 문자와 비교"만으로 문자열 전체의 연쇄적인 제거를 O(n)에 시뮬레이션**할 수 있다.

### 손으로 시뮬레이션 — `s = "baabaa"`

| step | 입력 문자 | 동작 | 스택 상태 (아래→위) |
|---|---|---|---|
| 1 | `b` | top 없음 → push | `b` |
| 2 | `a` | top=`b` ≠ `a` → push | `b, a` |
| 3 | `a` | top=`a` == `a` → pop | `b` |
| 4 | `b` | top=`b` == `b` → pop | *(empty)* |
| 5 | `a` | top 없음 → push | `a` |
| 6 | `a` | top=`a` == `a` → pop | *(empty)* |

끝까지 읽었을 때 스택이 비어있으므로 → **1** 반환. 문제의 예시(`b aa baa → bb aa → aa →`)와 정확히 같은 결과를 훨씬 적은 연산으로 얻는다.

### `s = "cdcd"` (실패 케이스)

| step | 입력 문자 | 동작 | 스택 상태 |
|---|---|---|---|
| 1 | `c` | push | `c` |
| 2 | `d` | top=`c` ≠ `d` → push | `c, d` |
| 3 | `c` | top=`d` ≠ `c` → push | `c, d, c` |
| 4 | `d` | top=`c` ≠ `d` → push | `c, d, c, d` |

끝까지 읽어도 스택에 4글자가 그대로 남는다 → **0** 반환.

## 3. 코드 (Java)

```java
class Solution {
    public int solution(String s) {
        char[] stack = new char[s.length()];
        int top = -1;

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (top >= 0 && stack[top] == c) {
                top--;              // 직전 문자와 같으면 짝 → pop
            } else {
                stack[++top] = c;   // 다르면 새로 쌓기 → push
            }
        }

        return top == -1 ? 1 : 0;   // 스택이 비었으면 성공
    }
}
```

### 코드 설명

- `java.util.Stack`이나 `Deque<Character>` 대신 **`char[]` 배열 + `top` 인덱스**로 스택을 직접 흉내냈다. 이유는 세 가지다.
  1. **`Stack`의 동기화(synchronized) 오버헤드**: `java.util.Stack`은 `Vector`를 상속하는데, `push`/`pop`/`peek` 전부 `synchronized` 메서드다. 싱글 스레드에서만 써도 매번 락을 걸고 푸는 비용이 든다. Java 공식 문서도 "LIFO 스택이 필요하면 `Stack` 대신 `Deque`를 쓰라"고 명시할 정도로 잘 알려진 단점이다.
  2. **`Deque<Character>`의 박싱·참조 오버헤드**: `ArrayDeque`는 동기화는 없지만, `char` ↔ `Character` 박싱/언박싱이 매 push/pop마다 일어난다. (참고: `a`~`z`는 아스키 97~122로 JLS가 boxing 캐싱을 보장하는 범위(0~127) 안이라 매번 새 객체가 생성되진 않는다 — 다만 내부적으로 `Character` **객체 참조**를 담는 배열이라 값이 메모리에 연속으로 붙어있지 않고 한 단계 포인터를 더 거쳐야 해서(indirection) 캐시 지역성이 떨어진다.)
  3. **`char[]`는 이 오버헤드가 원천적으로 없음**: 동기화 없음, 박싱 없음, 포인터 참조 없음 — 순수 primitive 배열이라 캐시 지역성이 가장 좋다. `new char[s.length()]`로 처음부터 최대 크기를 잡아두면 배열 재할당(resize)도 아예 발생하지 않는다.
  - 참고로 프로그래머스는 채점이 비교적 널널해서 `Stack`/`Deque`로 짜도 이 문제 자체는 대부분 통과한다. 다만 `n ≤ 1,000,000`이라는 제약이 O(n)을 요구하는 힌트이기도 하고, 경쟁 프로그래밍에서 스택/큐를 배열로 직접 구현하는 건 자주 쓰이는 최적화 패턴이라 여기서도 적용했다.
- `top == -1`이 "스택이 비어있다"는 뜻이므로, 순회가 끝난 뒤 이 값 하나만 확인하면 된다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 문자열을 한 번만 순회하며, 각 문자는 push 또는 pop 중 정확히 한 번의 연산만 받는다.
- **공간복잡도**: `O(n)` — 최악의 경우(짝이 하나도 없는 경우) 스택에 모든 문자가 쌓일 수 있다.

`n ≤ 1,000,000` 제한을 정확히 `O(n)`으로 통과하도록 설계된 문제다.

## 5. 엣지 케이스

- 길이 1인 문자열 (`"a"`): 짝을 이룰 상대가 없으므로 항상 `0`.
- 전체가 하나의 반복 쌍인 경우 (`"aa"`, `"aabb"` 등): 순서대로 다 지워지면 `1`.
- 이미 최적화된 스택 방식은 문자열이 중간에 여러 번 "연쇄적으로" 지워지는 경우(`baabaa`처럼 pop 이후 또 pop이 일어나는 경우)도 자연스럽게 처리한다 — 별도 예외 처리가 필요 없다는 게 이 풀이의 장점이다.
