# [프로그래머스 17687] [3차] n진수 게임 — 자릿수 스트림 + 모듈러 배정

- 문제 번호: 17687
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/17687
- 분류: 2018 KAKAO BLIND RECRUITMENT
- 사용 자료구조/알고리즘: **문자열/진법 변환**, 모듈러 연산
- 난이도 체감: Lv.2 (알고리즘보다 "숫자 단위가 아니라 자릿수 단위로 배정된다"는 규칙을 정확히 이해하는 게 핵심)

## 1. 문제 요약

`0, 1, 2, 3, ...`을 `n`진법으로 바꿔서 **한 자리씩 끊어** 이어붙인 무한한 숫자 스트림을 `m`명이 한 자리씩 돌아가며 말한다. `p`번째 사람(튜브)이 말하게 될 숫자를 앞에서부터 `t`개 이어붙인 문자열을 구한다.

```text
n=2, t=4, m=2, p=1
스트림(2진법, 자릿수 단위): 0,1,1,0,1,1,1,0,0,...
1번 사람이 말하는 자리(홀수 번째): 0,1,1,1 → "0111"
```

**제한사항**: `2≤n≤16`, `0<t≤1000`, `2≤m≤100`, `1≤p≤m`. 10~15는 대문자 `A~F`.

## 2. 접근 아이디어

**핵심은 "숫자 단위"가 아니라 "자릿수(digit) 단위"로 사람이 배정된다는 것**이다 (`10`처럼 두 자리 숫자는 두 사람에게 나뉘어 배정될 수 있음). 그래서:

1. `0, 1, 2, 3, ...`을 `n`진법 문자열로 바꿔 한 글자씩 이어붙인 **하나의 긴 스트림**을 만든다.
2. 스트림의 `idx`번째(1-indexed) 글자를 말하는 사람은 `((idx-1) % m) + 1`번째 사람이다.
3. 이 값이 `p`와 같은 글자들만 순서대로 모으면, 그게 튜브가 말하는 숫자들이다. `t`개가 모이면 멈춘다.

`((idx-1) % m) + 1 == p`는 `idx % m == p % m`과 동치다 (증명: 양변에서 1을 빼고 mod 연산 성질 이용). 코드에서는 이 동치식을 그대로 쓴다.

### 핵심 포인트 — 스트림을 얼마나 만들어야 하는가

`t`개를 모으려면, 최악의 경우(`p=1`) 스트림에서 `p`번째 사람의 글자가 최대 `t`번 나올 때까지 훑어야 하는데, 그 사이에 다른 `m-1`명의 글자도 섞여 있으므로 **전체 스트림 길이는 최대 `t × m`자리**까지 필요할 수 있다. "숫자를 `t`개만 만들면 된다"고 생각하면 부족하다 — 숫자 하나가 여러 자리일 수도 있고, `m`이 커질수록 한 사람에게 배정되는 자리 비율이 줄어들기 때문이다.

## 3. 코드 (Java)

```java
class Solution {
    public String solution(int n, int t, int m, int p) {
        StringBuilder answer = new StringBuilder();
        int idx = 0, i = 0;

        while (answer.length() < t) {
            String num = Integer.toString(i, n);
            for (char c : num.toCharArray()) {
                idx++;
                if (idx % m == p % m) {
                    answer.append(c);
                    if (answer.length() == t) break;
                }
            }
            i++;
        }

        return answer.toString().toUpperCase();
    }
}
```

### 코드 설명

- `i`를 0부터 하나씩 늘려가며 `Integer.toString(i, n)`으로 `n`진법 문자열로 바꾼다. (10~15는 자동으로 소문자 `a~f`로 나오므로 마지막에 `.toUpperCase()`로 변환.)
- `idx`는 스트림 전체에서 지금 읽고 있는 자리가 몇 번째인지 센다 (숫자가 아니라 **자릿수** 기준).
- `answer.length() < t`를 while 조건으로 걸어서, **필요한 만큼만 정확히 모이면 즉시 멈춘다** — "숫자를 몇 개까지 만들지"를 미리 계산하거나 추측할 필요가 없다.

## 4. 복잡도 분석

- **시간복잡도**: 최악의 경우 스트림을 `O(t × m)`자리까지 읽어야 한다. `t ≤ 1000`, `m ≤ 100`이므로 최대 100,000자리 — `n`진법 변환과 문자 순회를 합쳐도 충분히 빠르다.
- **공간복잡도**: 결과 문자열 `O(t)`.

실측(`n=16, t=1000, m=100, p=100`, 최악에 가까운 스케일): **약 2.3ms**.

## 5. 검증

공식 예시 3개 전부 통과했고, `m=100`처럼 참가자가 많은 케이스에서도 올바른 길이·값을 내는 것을 확인했다.

## 6. 엣지 케이스

- `p == m` (마지막 순서): `p % m == 0`이 되어, `idx`가 `m`의 배수일 때만 담긴다 — 공식으로 자연스럽게 처리됨(예시 #3 `p=2, m=2`가 이 케이스).
- `n = 16`일 때 10~15 자리가 나오는 숫자: `Integer.toString(num, 16)`이 소문자로 주므로 `toUpperCase()`를 빠뜨리면 틀린 답이 된다.
- `t`가 매우 작을 때(`t=1`)에도 while 루프가 정확히 필요한 만큼만 돌고 즉시 멈춘다.
