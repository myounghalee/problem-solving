# [프로그래머스 60058] 괄호 변환 — 재귀로 문제 정의를 그대로 옮기기

- 문제 번호: 60058
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/60058
- 분류: 2020 KAKAO BLIND RECRUITMENT
- 사용 자료구조/알고리즘: **재귀(Recursion)**, 괄호 균형 판별
- 난이도 체감: Lv.2 (알고리즘은 문제에 다 나와 있지만, 그대로 코드로 옮기는 과정에서 헷갈리기 쉬움)

## 1. 문제 요약

`(`와 `)`로만 이루어진 **균형잡힌 괄호 문자열**(여는/닫는 개수가 같은 문자열) `p`가 주어진다. 이를 **올바른 괄호 문자열**(짝도 모두 맞는 문자열)로 바꾸는 절차가 문제에 이미 정의되어 있다.

1. 입력이 빈 문자열이면 빈 문자열을 반환한다.
2. `w`를 더 이상 쪼갤 수 없는 균형잡힌 괄호 문자열 `u`와 나머지 `v`로 나눈다.
3. `u`가 이미 올바른 괄호 문자열이면 → `v`를 1단계부터 다시 처리한 결과를 `u` 뒤에 붙여서 반환한다.
4. `u`가 올바른 괄호 문자열이 아니면 →
   - `(` 를 붙이고
   - `v`를 1단계부터 재귀적으로 처리한 결과를 붙이고
   - `)` 를 붙이고
   - `u`의 첫/마지막 문자를 떼고 나머지 괄호 방향을 뒤집어서 붙인다.

**제한사항**: `p`의 길이는 2 이상 1,000 이하의 짝수.

이 문제는 스택 문제인 [짝지어 제거하기(12973)](../12973-짝지어제거하기/Solution.md)처럼 괄호/짝을 다루지만, **한 번의 선형 스캔으로 끝나지 않고 문제 정의 자체가 재귀**라는 점이 다르다. 그래서 핵심은 자료구조 선택이 아니라, **문제에 적힌 절차를 한 줄씩 그대로 함수로 옮기는 것**이다.

## 2. 접근 아이디어

문제 정의를 그대로 3개의 부분 문제로 쪼개면 코드가 된다.

### (1) `w`를 `u`, `v`로 분리하기

앞에서부터 `(`는 +1, `)`는 -1로 세면서 누적하다가, **처음으로 합이 0이 되는 지점까지**가 `u`다. `w`가 균형잡힌 문자열이므로 이 지점은 반드시 존재한다.

### (2) `u`가 "올바른 괄호 문자열"인지 판별하기

`u`를 앞에서부터 읽으며 같은 방식으로 누적하되, **중간에 합이 음수가 되는 순간이 있으면** 닫는 괄호가 먼저 나온 것이므로 올바르지 않다. 끝까지 음수가 없었다면 올바른 문자열이다. (참고: `u`는 이미 균형잡힌 문자열이 보장되므로 최종 합은 항상 0이다.)

### (3) 문제의 4번 케이스 — 뒤집어서 감싸기

`u`가 올바르지 않을 때, `u`의 첫/마지막 문자(`(`, `)`)를 떼어낸 가운데 부분의 **괄호 방향을 전부 반대로 뒤집는다**. 이 부분이 실수하기 가장 쉬운 지점이다.

### 재귀 호출 트레이스 — `p = ")("`

| 단계 | w | u | v | u가 올바른가? | 처리 |
|---|---|---|---|---|---|
| 1 | `")("` | `")("` | `""` | 아니오 (첫 글자부터 `)`) | `"("` + `solution("")` + `")"` + (u 가운데를 뒤집은 것: 가운데가 없으므로 `""`) |
| 2 | `""` (재귀) | - | - | - | 빈 문자열이므로 그대로 `""` 반환 |

최종적으로 `"("` + `""` + `")"` + `""` = `"()"`.

## 3. 코드 (Java)

```java
class Solution {
    public String solution(String p) {
        if (p.isEmpty()) return "";

        int splitIndex = split(p);
        String u = p.substring(0, splitIndex);
        String v = p.substring(splitIndex);

        if (isCorrect(u)) {
            return u + solution(v);
        }

        StringBuilder result = new StringBuilder();
        result.append('(');
        result.append(solution(v));
        result.append(')');

        for (int i = 1; i < u.length() - 1; i++) {
            result.append(u.charAt(i) == '(' ? ')' : '(');
        }

        return result.toString();
    }

    // 균형잡힌 괄호 문자열 p에서, 더 이상 쪼갤 수 없는 첫 조각 u의 끝 인덱스(exclusive)를 찾는다.
    private int split(String p) {
        int balance = 0;
        for (int i = 0; i < p.length(); i++) {
            balance += p.charAt(i) == '(' ? 1 : -1;
            if (balance == 0) return i + 1;
        }
        return p.length();
    }

    // 균형잡힌 괄호 문자열 u가 "올바른 괄호 문자열"인지 판별한다.
    private boolean isCorrect(String u) {
        int balance = 0;
        for (int i = 0; i < u.length(); i++) {
            balance += u.charAt(i) == '(' ? 1 : -1;
            if (balance < 0) return false;
        }
        return true;
    }
}
```

### 코드 설명

- `split()`: 괄호 카운트가 0으로 돌아오는 첫 지점을 찾아 `u`/`v`로 나눈다. 문제에서 말하는 "더 이상 분리할 수 없는 균형잡힌 문자열"이 정확히 이 지점이다.
- `isCorrect()`: 누적 합이 한 번이라도 음수가 되면 즉시 `false` — 닫는 괄호가 여는 괄호보다 먼저 나왔다는 뜻이므로 그 순간 이미 틀렸다고 확정할 수 있다.
- 4번 케이스의 마지막 단계(`u`의 가운데를 뒤집어 붙이는 부분)는 `u.substring(1, u.length() - 1)`을 새 문자열로 만들지 않고, 인덱스 `1`부터 `u.length() - 2`까지 순회하며 바로 반대 문자를 `StringBuilder`에 append하는 방식으로 구현했다 — 불필요한 중간 문자열 생성을 피한다.

## 4. 복잡도 분석

- **시간복잡도**: 재귀 호출마다 `split`/`isCorrect`/뒤집기에서 자기 길이만큼 `O(k)`가 들고, 매 호출은 최소 2글자(`u`의 첫/마지막)를 소비하며 더 짧아진 `v`로 재귀한다. 최악의 경우(예: `")()()()...("`처럼 매번 조금씩만 줄어드는 경우) 재귀 깊이가 `O(n)`까지 갈 수 있어 **전체 O(n²)**. `n ≤ 1,000`이므로 최악이어도 10⁶ 수준이라 시간 제한에 여유롭다.
- **공간복잡도**: 재귀 호출 스택 깊이 최악 `O(n)`, 각 단계에서 생성하는 문자열까지 합쳐 `O(n²)` (substring이 매번 새 문자열을 만들기 때문). 이 역시 `n ≤ 1,000`에서는 문제 없다.

[짝지어 제거하기(12973)](../12973-짝지어제거하기/Solution.md)의 스택 풀이가 O(n)이었던 것과 비교하면 이 문제는 재귀 구조상 O(n²)이 자연스러운 한계다. n이 훨씬 컸다면 최적화가 필요했겠지만, 이 문제의 제약(≤1,000)은 애초에 O(n²)을 허용하도록 설계된 것으로 보인다.

## 5. 엣지 케이스

- 길이 2인 최소 입력 (`"()"`, `")("`) : `"()"`는 그대로, `")("`는 뒤집혀서 `"()"`로 변환된다.
- 이미 올바른 문자열이 주어지는 경우 (`"(()())()"`): 매 단계에서 `u`가 계속 "올바른 괄호 문자열"로 판정되어 3번 케이스만 반복되고, 원래 문자열이 그대로 반환된다.
- `u`가 여러 번 중첩되어 뒤집기가 재귀적으로 겹치는 경우: 재귀 자체가 이를 자동으로 처리하므로 별도 처리가 필요 없다.
