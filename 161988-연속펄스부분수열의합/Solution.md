# [프로그래머스 161988] 연속 펄스 부분 수열의 합 — Kadane's Algorithm으로 풀기

- 문제 번호: 161988
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/161988
- 분류: 연습문제 (별도 카테고리 태그 없음)
- 사용 자료구조/알고리즘: **최대 부분 배열 합 (Kadane's Algorithm)**
- 난이도 체감: Lv.3 (문제를 "부호 변환 + 최대/최소 부분합"으로 환원하는 통찰이 핵심)

## 1. 문제 요약

정수 수열 `sequence`가 주어진다. 이 수열의 **연속 부분 수열**을 하나 골라, 같은 길이의 **펄스 수열**(`[1, -1, 1, -1, ...]` 또는 `[-1, 1, -1, 1, ...]`처럼 1과 -1이 번갈아 나오는 수열)을 각 원소끼리 곱한다. 이렇게 만든 "연속 펄스 부분 수열"의 합이 최대가 되는 값을 구한다.

```text
예시) sequence = [2, 3, -6, 1, 3, -1, 2, 4]
부분 수열 [3, -6, 1] × 펄스 [1, -1, 1] = [3, 6, 1] → 합 10 (최댓값)
```

**제한사항**
- 수열 길이: 1 ≤ 길이 ≤ 500,000
- 원소 값: -100,000 ≤ 원소 ≤ 100,000
- 반환 타입: `long` (값 범위가 `int`를 넘을 수 있음)

길이가 최대 50만이라는 점에서 `O(n)` 또는 `O(n log n)` 알고리즘이 필요하다는 것을 알 수 있다.

## 2. 접근 아이디어 — 왜 Kadane's Algorithm인가

브루트포스로 접근하면 "시작 인덱스 × 끝 인덱스 × 펄스가 +1로 시작하는지 -1로 시작하는지" 세 가지 변수를 모두 고려해야 해서 `O(n²)` 이상이 된다. 여기서 핵심 통찰은 **펄스를 곱하는 연산을 미리 배열에 반영해두면, 이 문제가 결국 "최대 부분 배열 합" 문제로 환원된다**는 점이다.

- 전역 배열 `A`를 다음과 같이 정의한다: `A[i] = sequence[i] * (i가 짝수면 +1, 홀수면 -1)`. 즉 인덱스 0에서 `+1`로 시작하는 펄스를 전체 수열에 미리 곱해둔 배열이다.
- 부분 수열 `[l, r]`에 **인덱스 `l`에서 `+1`로 시작하는 펄스**를 곱한 합은, `l`이 짝수든 홀수든 상관없이 정확히 `A[l..r]`의 구간 합과 같다.
  - `l`이 짝수면: 전역 부호와 로컬 펄스 부호가 정확히 일치 → `A[l..r]`의 합이 곧 원하는 값.
  - `l`이 홀수면: 전역 부호(`A[l]`은 `-sequence[l]`)와 로컬 펄스 부호(`+sequence[l]`로 시작해야 함)가 정반대 → `A[l..r]`의 합에 `-1`을 곱한 것이 원하는 값. 즉 `-A[l..r]`.
- 결국 답은 다음 두 값 중 최댓값이다.
  1. `A`의 **최대 부분 배열 합** — 짝수 인덱스에서 시작하는(또는 부호가 우연히 맞아떨어지는) 펄스 조합의 최댓값.
  2. `A`의 **최소 부분 배열 합에 `-1`을 곱한 값** — 홀수 인덱스에서 시작하는 펄스 조합, 즉 부호가 반전된 경우의 최댓값.
- "부분 배열의 최대/최소 합"은 각각 **Kadane's Algorithm**으로 `O(n)`에 구할 수 있다. 최대와 최소를 각각 한 번씩, 총 두 번의 선형 스캔(사실은 한 번의 루프 안에서 동시에)으로 해결된다.

### 손으로 시뮬레이션 — `sequence = [2, 3, -6, 1, 3, -1, 2, 4]`

먼저 `A[i] = sequence[i] * (i 짝수 ? +1 : -1)`로 변환:

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| sequence[i] | 2 | 3 | -6 | 1 | 3 | -1 | 2 | 4 |
| A[i] | 2 | -3 | -6 | -1 | 3 | 1 | 2 | -4 |

이제 `A`에 대해 Kadane's Algorithm을 최대/최소 동시에 진행한다 (`maxEnd`, `minEnd`는 "현재 인덱스에서 끝나는" 부분합의 최대/최소):

| i | A[i] | maxEnd | maxSoFar | minEnd | minSoFar |
|---|---|---|---|---|---|
| 0 | 2 | 2 | 2 | 2 | 2 |
| 1 | -3 | max(-3, 2-3)=-1 | 2 | min(-3, 2-3)=-3 | -3 |
| 2 | -6 | max(-6, -1-6)=-6 | 2 | min(-6, -3-6)=-9 | -9 |
| 3 | -1 | max(-1, -6-1)=-1 | 2 | min(-1, -9-1)=-10 | -10 |
| 4 | 3 | max(3, -1+3)=3 | 3 | min(3, -10+3)=-7 | -10 |
| 5 | 1 | max(1, 3+1)=4 | 4 | min(1, -7+1)=-6 | -10 |
| 6 | 2 | max(2, 4+2)=6 | 6 | min(2, -6+2)=-4 | -10 |
| 7 | -4 | max(-4, 6-4)=2 | 6 | min(-4, -4-4)=-8 | -10 |

- `maxSoFar = 6` (구간 `A[4..6] = [3, 1, 2]`, 합 6)
- `minSoFar = -10` (구간 `A[1..3] = [-3, -6, -1]`, 합 -10) → `-minSoFar = 10`
- 답: `max(6, 10) = 10` — `minSoFar` 쪽의 구간 `A[1..3]`이 원래 `sequence[1..3] = [3, -6, 1]`에 대응하고, 이는 정확히 문제 예시가 제시한 정답 구간과 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    public long solution(int[] sequence) {
        long maxEndingHere = 0, maxSoFar = Long.MIN_VALUE; // A의 최대 구간 합 (현재까지 / 전체)
        long minEndingHere = 0, minSoFar = Long.MAX_VALUE; // A의 최소 구간 합 (현재까지 / 전체)

        for (int i = 0; i < sequence.length; i++) {
            long a = (i % 2 == 0) ? sequence[i] : -sequence[i]; // 전역 배열 A[i]

            maxEndingHere = Math.max(a, maxEndingHere + a);
            maxSoFar = Math.max(maxSoFar, maxEndingHere);

            minEndingHere = Math.min(a, minEndingHere + a);
            minSoFar = Math.min(minSoFar, minEndingHere);
        }

        return Math.max(maxSoFar, -minSoFar); // 정방향 펄스 최댓값 vs 역방향 펄스 최댓값
    }
}
```

### 코드 설명

- `a`는 위에서 정의한 전역 배열 `A[i]`를 그 자리에서 계산한 값이다. 별도 배열을 만들지 않고 루프 안에서 즉시 계산해 `O(n)` 공간을 `O(1)`로 줄였다.
- `maxEndingHere`/`minEndingHere`는 Kadane's Algorithm의 핵심 점화식이다: "현재 원소 하나만 새로 시작할지, 이전까지의 부분합에 이어붙일지"를 매 스텝 `Math.max`/`Math.min`으로 결정한다.
  - `maxEndingHere = Math.max(a, maxEndingHere + a)`: 지금까지 이어온 합에 `a`를 더하는 게 오히려 손해라면(음수를 계속 끌고 왔다면) `a` 하나로 새로 시작하는 게 낫다.
  - `minEndingHere`도 부호만 반대로 같은 논리다.
- 최대/최소 두 개의 Kadane 상태를 **하나의 루프**에서 동시에 갱신해 배열을 두 번 순회하지 않도록 했다.
- 최종 답은 "0에서 시작하는 정방향 펄스 최댓값"(`maxSoFar`)과 "1에서 시작하는 역방향 펄스 최댓값"(`-minSoFar`) 중 큰 값이다.
- 반환 타입과 중간 변수를 모두 `long`으로 잡은 이유는 원소값이 최대 `100,000`, 길이가 최대 `500,000`이라 이론상 합이 `int` 범위(약 21억)를 넘을 수 있기 때문이다(`50만 × 10만 = 500억`).

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 한 번만 순회하며, 각 인덱스에서 상수 시간 연산만 수행한다.
- **공간복잡도**: `O(1)` — 변환된 배열 `A`를 따로 저장하지 않고 그때그때 계산해서 쓴다.

`sequence.length ≤ 500,000` 제한을 정확히 `O(n)`으로 통과하도록 설계된 문제다.

## 5. 엣지 케이스

- 길이 1인 수열: 펄스는 `[1]` 또는 `[-1]`뿐이라 답은 `Math.abs(sequence[0])`과 같다 — 코드 상으로도 `maxSoFar`와 `-minSoFar` 중 하나가 이 값을 정확히 잡아낸다.
- 모든 원소가 양수인 경우: 짝수/홀수 위치가 번갈아 상쇄되므로, 전체 구간보다 짧은 구간이 답이 될 수도 있다(예: `[1, 1, 1, 1]`의 답은 `1`).
- 모든 원소가 음수인 경우: 부호를 반전시키는 펄스(홀수 인덱스 시작)를 적절히 골라 큰 양수 합을 만들어낼 수 있다 — `minSoFar` 쪽 경로가 이런 케이스를 담당한다.
- 배열 전체가 하나의 부호로만 이루어진 펄스에 정확히 대응하는 경우(예: `sequence`가 이미 `[1,-1,1,-1,...]` 형태): 전체 구간이 곧 최적 구간이 되는 경우도 자연스럽게 처리된다 — 별도 예외 처리가 필요 없다.
