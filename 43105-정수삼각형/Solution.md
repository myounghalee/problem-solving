# [프로그래머스 43105] 정수 삼각형 — DP를 제자리(in-place)에서, O(1) 추가 공간으로

- 문제 번호: 43105
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43105
- 분류: 동적계획법(Dynamic Programming)
- 사용 자료구조/알고리즘: **DP (제자리 갱신)**
- 난이도 체감: Lv.2~3 (알고리즘은 표준적, 삼각형 양 끝(맨 왼쪽/오른쪽) 경계 처리가 실수하기 쉬운 지점)

## 1. 문제 요약

삼각형 모양으로 배치된 숫자들에서, 꼭대기부터 바닥까지 **대각선 왼쪽 또는 오른쪽으로만** 내려가며 거쳐간 숫자의 합이 **최대**가 되는 경로를 구한다.

```text
triangle = [[7],[3,8],[8,1,0],[2,7,4,4],[4,5,2,6,5]] → 30
(7 → 3 → 8 → 7 → 5)
```

**제한사항**: 삼각형 높이 1~500, 숫자는 0~9,999.

## 2. 접근 아이디어

`dp[i][j]` = "`i`번째 행의 `j`번째 칸까지 도달하는 최대 경로 합"이라 하면:

```
dp[i][j] = triangle[i][j] + max(dp[i-1][j-1], dp[i-1][j])
```

`i`번째 행 `j`번째 칸에 도달하는 방법은 이전 행에서 **바로 위(`j-1`, 대각선 오른쪽 이동)** 또는 **오른쪽 위(`j`, 대각선 왼쪽 이동)** 둘 중 하나뿐이다.

### 별도 dp 배열 없이, `triangle` 자체를 누적 합으로 덮어쓰기

`dp[i][j]`를 구하려면 바로 윗줄(`i-1`행)의 값만 있으면 되고, 그보다 위의 행들은 더 이상 필요 없다. 그래서 굳이 `dp`라는 별도 배열을 만들지 않고, **`triangle` 배열 자체를 위에서 아래로 훑으면서 그 칸의 값을 "여기까지의 최대 누적 합"으로 덮어써도 된다** — 한 칸 계산할 때 필요한 `triangle[i-1][...]`은 바로 이전 반복에서 이미 누적 합으로 바꿔둔 값이기 때문이다.

### 경계(맨 왼쪽·맨 오른쪽 칸)는 조건문 대신 별도로 명시 처리

각 행의 **맨 왼쪽 칸**은 이전 행의 왼쪽 위(`j-1`) 칸이 없고, **맨 오른쪽 칸**은 이전 행의 오른쪽 위(`j`) 칸이 없다 — 둘 다 갈 수 있는 경로가 하나뿐이다.

```java
triangle[i][0] += triangle[i - 1][0];       // 맨 왼쪽: 위에서 곧장 내려오는 경로뿐
triangle[i][i] += triangle[i - 1][i - 1];   // 맨 오른쪽: 대각선으로 내려오는 경로뿐
```

가운데 칸들만 `max(왼쪽 위, 오른쪽 위)`를 비교하는 일반 점화식을 적용한다. 조건문으로 "이 칸이 맨 끝인지"를 매번 검사하는 대신, **맨 왼쪽·맨 오른쪽을 루프 밖에서 먼저 처리**해버리는 방식이라 더 명시적이고 읽기 쉽다.

### 손으로 시뮬레이션 — `triangle = [[7],[3,8],[8,1,0],[2,7,4,4],[4,5,2,6,5]]`

`triangle` 배열이 그 자리에서 아래처럼 누적 합으로 덮어써진다.

| 행 | 덮어써진 값 (왼쪽→오른쪽) |
|---|---|
| 0 | `7` |
| 1 | `10, 15` |
| 2 | `18, 16, 15` |
| 3 | `20, 25, 20, 19` |
| 4 | `24, 30, 27, 26, 24` |

마지막 행의 최댓값은 `30`. 정답과 일치.

## 3. 코드 (Java)

```java
import java.util.Arrays;

class Solution {
    public int solution(int[][] triangle) {
        int n = triangle.length;

        for (int i = 1; i < n; i++) {
            triangle[i][0] += triangle[i - 1][0];
            triangle[i][i] += triangle[i - 1][i - 1];
            for (int j = 1; j < i; j++) {
                triangle[i][j] += Math.max(triangle[i - 1][j - 1], triangle[i - 1][j]);
            }
        }

        return Arrays.stream(triangle[n - 1]).max().getAsInt();
    }
}
```

### 코드 설명

- 별도 `dp` 배열 없이 **`triangle`을 그 자리에서 누적 합으로 덮어쓴다** — 한 행씩 아래로 내려가며, 각 칸에 "지금까지의 원래 값" 대신 "여기까지 올 수 있는 최대 경로 합"을 다시 써넣는다.
- 맨 왼쪽(`triangle[i][0]`), 맨 오른쪽(`triangle[i][i]`)은 반복문 밖에서 먼저 처리 — 각각 유일한 경로(`triangle[i-1][0]`, `triangle[i-1][i-1]`)를 그대로 더한다.
- 가운데 칸(`j = 1 ~ i-1`)만 `max(triangle[i-1][j-1], triangle[i-1][j])`로 두 경로 중 큰 쪽을 선택.
- 마지막 행(`triangle[n-1]`)에서 `Arrays.stream(...).max().getAsInt()`로 최댓값을 구한다 — 반복문 대신 스트림 API로 간결하게 표현.

**주의**: 이 방식은 **입력으로 받은 `triangle` 배열 자체를 변형**한다(호출자가 이 배열을 이후에 다시 쓴다면 원본이 훼손됨). 프로그래머스처럼 함수가 한 번 호출되고 끝나는 채점 환경에서는 문제가 되지 않지만, 일반적인 소프트웨어에서 입력 파라미터를 그대로 변형하는 건 부작용(side effect)이라는 점은 인지하고 있는 게 좋다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n²)` — 삼각형의 전체 칸 수가 `1+2+...+n ≈ n²/2`.
- **공간복잡도**: **`O(1)`** 추가 공간 — 별도 `dp` 배열 없이 입력 배열을 그대로 재사용한다. (이전에 별도 `dp[n][n]` 배열을 썼던 버전은 `O(n²)` 공간이 필요했다.)

`n ≤ 500`이면 최대 약 250,000칸으로 여유롭다. 실측(`height=500`, 무작위 데이터): **약 0.09ms** — 배열을 새로 할당하지 않아 이전 버전(약 3ms)보다도 빠르다.

## 5. 검증

작은 삼각형(높이 최대 10)에서 **모든 경로를 완전탐색(재귀)** 하는 참조 구현과 2,000회 무작위 비교해서 전부 일치함을 확인했다. 공식 예시와 높이 1인 엣지 케이스도 통과한다.

## 6. 엣지 케이스

- 높이 1(`[[5]]`): 반복문(`i=1`부터 시작)이 아예 돌지 않고, `triangle[0]`의 값이 그대로 최댓값 → `5`.
- 모든 숫자가 `0`인 경우: 누적 합도 전부 `0` — 정상적으로 `0` 반환.
- 삼각형의 숫자가 전부 같은 경우: 어느 경로를 타도 합이 같으므로 DP가 자연스럽게 처리.
