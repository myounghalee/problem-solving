# [LeetCode 1] Two Sum — 해시맵으로 "나머지 값"을 O(1)에 찾기

- 문제 번호: 1
- 링크: https://leetcode.com/problems/two-sum/
- 난이도: Easy
- 태그: Array, Hash Table
- 사용 자료구조/알고리즘: **해시맵 (값 → 인덱스 목록)**

## 1. 문제 요약

정수 배열 `nums`와 정수 `target`이 주어질 때, 합이 `target`이 되는 두 원소의 **인덱스**를 반환한다. 정답은 항상 정확히 하나 존재하고, 같은 원소를 두 번 쓸 수 없다.

```text
예시) nums = [2,7,11,15], target = 9 → [0,1]  (2+7=9)
      nums = [3,2,4],      target = 6 → [1,2]  (2+4=6)
      nums = [3,3],        target = 6 → [0,1]  (같은 값이 두 인덱스에 있는 경우)
```

Follow-up: 브루트포스(`O(n²)`)보다 빠르게 풀 수 있는가?

## 2. 접근 아이디어

브루트포스는 모든 `(i, j)` 쌍을 다 확인하므로 `O(n²)`이다. 여기서 핵심 관찰: **`nums[i]`가 정해지면, 함께 짝지어야 할 값은 `target - nums[i]`로 정확히 하나로 정해진다.** 그러니 "그 값이 배열 어디에 있는지"만 빠르게 찾을 수 있으면 된다 — 이게 해시맵이 O(1) 평균 조회로 해주는 일이다.

- 먼저 배열을 한 번 훑으며 **값 → 그 값이 등장하는 인덱스 목록**을 해시맵에 만들어둔다. (같은 값이 여러 번 나올 수 있으므로 `List<Integer>`로 인덱스를 모아둔다.)
- 다시 배열을 훑으며, 각 인덱스 `i`에 대해 `target - nums[i]`가 해시맵에 있는지 확인한다. 있으면 그 값이 등장하는 인덱스 목록에서 **자기 자신(`i`)이 아닌** 인덱스를 찾아 반환한다.
- "자기 자신이 아닌"이라는 조건이 필요한 이유: `nums[i]`와 `target - nums[i]`가 우연히 같은 값이더라도(예: `target`이 `nums[i]`의 두 배), 그 값을 가진 인덱스가 `i` 자기 자신 하나뿐이라면 짝을 지을 상대가 없기 때문이다. 이런 경우엔 그 값을 가진 **다른** 인덱스가 따로 있어야 한다(`[3,3], target=6` 예시가 정확히 이 케이스다).

### 손으로 시뮬레이션 — `nums = [3, 2, 4], target = 6`

**1단계: 값 → 인덱스 목록 맵 구성**

| 값 | 인덱스 목록 |
|---|---|
| 3 | [0] |
| 2 | [1] |
| 4 | [2] |

**2단계: 각 인덱스에서 `target - nums[i]` 찾기**

| `i` | `nums[i]` | `target - nums[i]` | 맵에서 찾은 인덱스 | 자기 자신 제외하면? |
|---|---|---|---|---|
| 0 | 3 | 3 | [0] | 후보가 자기 자신(0)뿐 → 다음으로 |
| 1 | 2 | 4 | [2] | `1 != 2` → 반환! |

결과: **`[1, 2]`** — `nums[1] + nums[2] = 2 + 4 = 6`, 정답과 일치한다.

## 3. 코드 (Java)

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, List<Integer>> map = new HashMap<>(); // 값 -> 그 값이 등장하는 인덱스들
        for (int i = 0; i < nums.length; i++) {
            List<Integer> list = map.getOrDefault(nums[i], new ArrayList<>());
            list.add(i);
            map.put(nums[i], list);
        }

        for (int i = 0; i < nums.length; i++) {
            if (map.containsKey(target - nums[i])) {
                for (Integer j : map.get(target - nums[i])) {
                    if (i != j) return new int[]{i, j}; // 자기 자신이 아닌 짝을 찾으면 즉시 반환
                }
            }
        }

        return new int[]{};
    }
}
```

### 코드 설명

- 1단계 루프에서 `map.getOrDefault(nums[i], new ArrayList<>())`로 "이 값이 처음 나온 거면 빈 리스트, 아니면 기존 리스트"를 가져와 인덱스를 추가한다. 같은 값이 여러 인덱스에 등장할 수 있으므로 `Integer` 하나가 아니라 `List<Integer>`로 관리한다.
- 2단계 루프에서 `target - nums[i]`가 맵에 있는지 `containsKey`로 먼저 확인한다. 없으면 그냥 다음 `i`로 넘어간다.
- 안쪽 `for`문은 그 값을 가진 인덱스들을 순서대로 보며, **`i` 자신이 아닌 첫 번째 인덱스를 찾자마자 바로 반환**한다. 한 인덱스는 자기 자신의 값에 대한 리스트에 최대 한 번만 등장하므로(각 인덱스는 정확히 하나의 값을 가지니까), 이 안쪽 루프는 실제로는 많아야 1~2번만 확인하고 끝난다 — 리스트가 아무리 길어도 매번 전체를 스캔하는 게 아니다.
- 정답이 항상 존재한다고 보장되므로, 마지막 `return new int[]{};`에는 실제로 도달하지 않는다 (컴파일을 위한 형식적인 반환문).

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 두 번(상수 배) 순회하고, 각 순회에서 해시맵 연산은 평균 `O(1)`. 안쪽 `for`문도 위에서 설명했듯 사실상 상수 시간에 끝난다. Follow-up이 요구한 `O(n²)` 미만을 만족한다.
- **공간복잡도**: `O(n)` — 해시맵에 최대 `n`개의 인덱스를 저장한다.

## 5. 엣지 케이스

- **같은 값이 여러 번 등장하는 경우** (`[3,3], target=6`, `[1,5,1,5], target=10`): 인덱스 목록에서 자기 자신을 제외하고 찾기 때문에 정확히 처리된다.
- **음수를 포함하는 경우** (`[-1,-2,-3,-4,-5], target=-8`): 해시맵은 값의 부호와 무관하게 동작하므로 문제없다.
- **정답이 배열 뒤쪽 인덱스에 있는 경우** (`nums = [0..9999], target = 19997` → `[9998, 9999]`): 바깥 루프가 그 지점까지 도달해야 하지만, 그 전까지의 각 반복도 상수 시간이라 전체적으로는 여전히 `O(n)`. 실제로 원소 10,000개짜리 배열로 테스트해도 2ms 안에 끝난다.
