# [LeetCode 3319] K-th Largest Perfect Subtree Size in Binary Tree — post-order DFS로 "완전 이진 서브트리"만 골라내기

- 문제 번호: 3319
- 링크: https://leetcode.com/problems/k-th-largest-perfect-subtree-size-in-binary-tree/
- 난이도: Medium
- 태그: Tree, Depth-First Search, Sorting, Binary Tree
- 사용 자료구조/알고리즘: **post-order DFS + 실패 신호(`-1`) 전파 + 정렬**

## 1. 문제 요약

이진 트리의 루트 `root`와 정수 `k`가 주어질 때, **완전 이진 트리(perfect binary tree)** 형태인 서브트리들 중 `k`번째로 큰 크기를 반환한다. 그런 서브트리가 `k`개 미만이면 `-1`을 반환한다.

완전 이진 트리란 모든 리프가 같은 레벨에 있고, 모든 부모 노드가 자식을 정확히 2개씩 가지는 트리를 말한다. 트리 **전체**가 완전 이진 트리일 필요는 없다 — 트리 안의 어떤 노드를 루트로 삼았을 때 그 서브트리만 완전하면 그 크기가 후보에 포함된다.

```text
예시)     5
         / \
        3   6
       / \ / \
      5  2 5  7
     / \    / \
    1  8   6  8

완전 이진 서브트리: 5(자식 1,8) 크기3, 5(자식 6,8) 크기3, 리프 6개(1,8,2,6,8,7) 각 크기1
-> 크기 목록 [3,3,1,1,1,1,1,1], k=2 -> 3
```

## 2. 접근 아이디어

핵심은 **모든 노드**에 대해 "이 노드를 루트로 하는 서브트리가 완전 이진 트리인가?"를 판단하고, 맞다면 그 크기를 모아두는 것이다. 이를 한 번의 post-order DFS로 처리한다.

`dfs(node)`의 반환값을 이렇게 설계한다.

- `node`가 `null`이면 `-1`(불완전 신호)을 반환한다.
- `node`가 리프(자식이 둘 다 없음)면, 자식이 없다는 조건이 "모든 리프가 같은 레벨", "모든 부모가 자식 2개" 둘 다 공허하게 참이므로 **항상 완전**하다. 크기 `1`을 리스트에 기록하고 `1`을 반환한다.
- 그 외의 경우, **왼쪽·오른쪽 자식이 있든 없든 무조건 재귀로 내려가서** `left = dfs(node.left)`, `right = dfs(node.right)`를 구한다. (여기서 자식이 없으면 `dfs(null) = -1`이 나온다.)
  - `left`나 `right` 중 하나라도 `-1`이면, 그 자식 서브트리가 이미 불완전(혹은 애초에 자식이 없음)했다는 뜻이므로 현재 노드도 **무조건** 불완전 → `-1` 반환.
  - 둘 다 `-1`이 아니고 `left == right`(양쪽 서브트리 크기가 같음 = 양쪽 다 완전하고 높이도 같음)면, 현재 노드도 완전 → 크기 `left + right + 1`을 리스트에 기록하고 반환.
  - 그 외(크기가 다름)에는 불완전 → `-1` 반환.

여기서 가장 중요한 설계 포인트는 **"이 노드 자신이 완전한지 판단하는 것"과 "자식을 순회하는 것"을 분리**했다는 점이다. 자식이 하나뿐이라 현재 노드 자신은 완전할 수 없어도, 그 자식(혹은 그 자식의 자식) 안에는 완전 이진 서브트리가 얼마든지 숨어있을 수 있다. 그래서 자식 존재 여부와 무관하게 **항상 양쪽으로 내려가서 순회 자체는 빠짐없이** 하고, "완전 여부" 판정에서만 `-1`(불완전 신호)을 특별 취급한다.

전체 크기 리스트를 다 모은 뒤에는 내림차순으로 정렬해서 `k`번째 값을 꺼내면 된다. 리스트 크기가 `k`보다 작으면 `-1`.

### 손으로 시뮬레이션 — `root = [7,4]` (자식이 하나뿐인 경우)

```text
  7
 /
4
```

| 호출 | 내용 | 결과 |
|---|---|---|
| `dfs(4)` | 리프 → `list`에 `1` 추가 | `1` |
| `dfs(null)` (7의 오른쪽 자식) | `null` → 불완전 신호 | `-1` |
| `dfs(7)` | `left=dfs(4)=1`, `right=dfs(null)=-1` → 하나라도 `-1`이면 무조건 불완전 | `-1` |

`7` 자신은 자식이 하나뿐이라 완전할 수 없지만, 그 왼쪽 자식 `4`는 리프라서 완전 이진 서브트리(크기1)로 정상적으로 `list`에 기록된다. 최종 `list = [1]`이므로 `k=1` → `1`.

## 3. 코드 (Java)

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;
    TreeNode() {}
    TreeNode(int val) { this.val = val; }
    TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val;
        this.left = left;
        this.right = right;
    }
}

class Solution {

    List<Integer> list;

    public int kthLargestPerfectSubtree(TreeNode root, int k) {
        list = new ArrayList<>();
        dfs(root);
        list.sort(Comparator.reverseOrder());
        if (list.size() < k) return -1;
        return list.get(k - 1);
    }

    private int dfs(TreeNode root) {
        if (root == null) return -1; // 없는 자식은 불완전 신호로 취급

        if (root.left == null && root.right == null) {
            list.add(1); // 리프는 항상 완전 이진 트리(크기 1)
            return 1;
        }

        int left = dfs(root.left), right = dfs(root.right); // 자식 유무와 무관하게 항상 순회
        if (left == -1 || right == -1) return -1; // 한쪽이라도 불완전하면 현재 노드도 불완전
        if (left == right) { // 양쪽 다 완전 + 크기(높이)까지 같아야 완전
            int val = left + right + 1;
            list.add(val);
            return val;
        }

        return -1;
    }
}
```

### 코드 설명

- `list`는 완전 이진 서브트리의 크기를 모으는 클래스 필드다. `kthLargestPerfectSubtree`가 호출될 때마다 새 `ArrayList`로 초기화하므로, 같은 `Solution` 인스턴스를 여러 번 호출해도 이전 호출의 상태가 남지 않는다.
- `dfs(null) = -1`이 이 풀이의 핵심 장치다. 자식이 없는 자리를 "불완전"으로 취급함으로써, 자식이 하나뿐인 노드(`left`, `right` 중 하나가 `null`)를 `left == right` 비교 한 줄로 자연스럽게 걸러낼 수 있다 (`null`이 아닌 자식의 크기와 `-1`이 같을 수 없으므로).
- `if (left == -1 || right == -1) return -1;`을 **`left == right` 비교보다 먼저** 검사하는 순서가 중요하다. 이 순서를 지키지 않으면, 양쪽 자식이 서로 다른 이유로 불완전한데 우연히 같은 값(예: 과거 버전에서 `0`)을 반환해 "같다"고 오판하는 버그가 생긴다.
- 리프가 아닌 노드는 **자식이 있든 없든 무조건** `dfs`를 호출한다. 이렇게 해야 "현재 노드 자신은 완전할 수 없어도, 그 자식 서브트리 안에는 완전한 것이 있을 수 있다"는 경우를 놓치지 않는다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n log n)` — DFS로 모든 노드를 한 번씩 방문하는 데 `O(n)`, 이후 `list`를 정렬하는 데 `O(n log n)` (`n`은 노드 개수, 최대 2,000).
- **공간복잡도**: `O(n)` — 최악의 경우(모든 리프가 완전 이진 서브트리) `list`에 최대 `n`개에 가까운 값이 쌓이고, 재귀 호출 스택도 트리 높이만큼 사용한다.

## 5. 엣지 케이스

- **노드가 하나뿐인 트리**: 그 노드가 리프이므로 완전 이진 트리, 크기 1. `list = [1]`, `k=1`이면 `1`.
- **자식이 하나뿐인 노드가 섞여 있는 경우** (`root = [7,4]` 등): 그 노드 자신은 완전할 수 없지만, 존재하는 자식 쪽은 계속 순회해서 그 안의 완전 서브트리를 놓치지 않는다.
- **`k`가 완전 이진 서브트리 개수보다 큰 경우**: `list.size() < k`에서 바로 `-1`.
- **완전 이진 서브트리가 여러 개 있고 크기가 같은 경우**: 정렬 후 중복 값도 각각 하나의 순위로 세므로(서로 다른 값 `k`개가 아니라, 정렬된 리스트의 `k`번째 원소), `[3,3,1,...]`에서 `k=2`면 두 번째 `3`이 답이 된다.

## 6. 겪었던 실수 (디버깅 기록)

1. **불완전 신호(`0`, 나중엔 `-1`)를 일반 숫자처럼 비교**: 처음 버전은 자식이 둘 다 있을 때만 재귀로 내려갔고, 그 외에는 `0`을 반환했다. 그런데 `left == right`로 완전 여부를 판단하다 보니, **양쪽 자식이 각각 다른 이유로 불완전한데 둘 다 `0`을 반환해서 "같다"고 잘못 판정**되는 경우가 생겼다 (예: `[1,2,3,4,null,null,5]` 형태처럼 양쪽 다 자식이 하나뿐인 트리). → `left == right`를 비교하기 **전에** `left == -1 || right == -1`을 먼저 걸러내도록 순서를 바꿨다.
2. **자식이 하나뿐인 노드에서 순회 자체가 멈춤**: 위 수정 이후에도, `dfs`가 "자식이 둘 다 있을 때만" 재귀 호출을 하도록 되어 있어서, 자식이 하나뿐인 노드를 만나면 **그 존재하는 자식 쪽으로도 아예 내려가지 않고** 곧장 실패를 반환했다. 그 결과 `root = [7,4]`처럼 루트가 자식을 하나만 가진 트리에서, 리프인 `4`(그 자체로는 완전 이진 트리, 크기 1)가 한 번도 방문되지 않아 `list`가 비어버렸고, LeetCode 채점에서 Wrong Answer가 났다. → "이 노드 자신이 완전한지 판단하는 것"과 "자식을 순회하는 것"을 분리해서, 자식 유무와 무관하게 **항상** `dfs(root.left)`, `dfs(root.right)`를 호출하도록(단, `dfs(null) = -1`) 구조를 바꿨다.

두 실수 모두 "이 노드 자체는 조건을 만족 못 하니 더 볼 필요 없다"고 성급히 순회를 생략한 데서 비롯됐다 — 노드 자신의 결과와, 그 노드가 자식들을 계속 탐색해야 한다는 사실은 별개라는 점이 포인트다.
