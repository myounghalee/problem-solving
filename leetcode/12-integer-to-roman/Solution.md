# [LeetCode 12] Integer to Roman — 자릿수 하나씩 떼어내며 조회 테이블로 변환하기

- 문제 번호: 12
- 링크: https://leetcode.com/problems/integer-to-roman/
- 난이도: Medium
- 태그: Hash Table, Math, String
- 사용 자료구조/알고리즘: **자릿수 분해(모듈러 연산) + `List<String>` + 조회 배열**

## 1. 문제 요약

`1 <= num <= 3999`인 정수를 로마 숫자 문자열로 변환한다. 로마 숫자는 자릿값(천/백/십/일)마다 독립적으로 규칙이 정해져 있고, 4·9로 시작하는 자릿값은 "감산 표기법"(`IV`, `IX`, `XL`, `XC`, `CD`, `CM`)을 쓴다.

```text
예시) 3749 → "MMMDCCXLIX"  (3000=MMM, 700=DCC, 40=XL, 9=IX)
      58   → "LVIII"        (50=L, 8=VIII)
      1994 → "MCMXCIV"       (1000=M, 900=CM, 90=XC, 4=IV)
```

핵심 포인트: **자릿값마다 규칙이 완전히 독립적**이다 — 700을 만들 때 40이나 9와 상호작용할 일이 없다. 즉 이 문제도 [Integer to English Words(273번)](../273-integer-to-english-words/Solution.md)처럼 "숫자를 자릿수 단위로 쪼개서 처리한다"는 같은 패턴으로 접근할 수 있다.

## 2. 접근 아이디어

`num`을 10으로 나눈 나머지로 **한 자리씩** 떼어내며 처리한다. 로마 숫자는 `I`(1) `V`(5) `X`(10) `L`(50) `C`(100) `D`(500) `M`(1000) 7개 기호가 **1, 5 배율로 반복되는 패턴**이라는 점이 핵심이다 — 일의 자리는 `I`/`V`, 십의 자리는 `X`/`L`, 백의 자리는 `C`/`D`, 천의 자리는 `M`(그 위 5배 기호는 없음)으로, 자릿수가 하나 올라갈 때마다 조회 배열에서 **인덱스가 정확히 2칸씩** 이동한다.

- 조회 배열 `unit = {I, V, X, L, C, D, M}`을 만들어두면, 일의 자리는 `unit[0]`(`I`)/`unit[1]`(`V`), 십의 자리는 `unit[2]`(`X`)/`unit[3]`(`L`), 백의 자리는 `unit[4]`(`C`)/`unit[5]`(`D`), 천의 자리는 `unit[6]`(`M`)을 가리킨다. 자릿수 인덱스 `u`를 0에서 시작해서 자릿수를 하나 처리할 때마다 **2씩** 증가시키면 이 대응이 자동으로 맞아떨어진다.
- 한 자리 숫자(`0~9`)를 로마 숫자로 바꾸는 규칙은 5를 기준으로 나뉜다:
  - `0~3`: 기본 기호를 그 수만큼 반복 (`III` = `I`×3)
  - `4`: 감산 표기법 (`IV`)
  - `5~8`: 5의 기호 + 기본 기호 반복 (`VIII` = `V` + `I`×3)
  - `9`: 감산 표기법, 한 자리 위 기호까지 사용 (`IX`)
- **자릿수가 0인 경우, 결과에 아무 글자도 안 붙이지만 자릿수 인덱스(`u`)는 반드시 2 증가시켜야 한다.** 이걸 놓치면 그다음 0이 아닌 자릿수가 엉뚱하게 낮은 단위의 기호를 가져다 쓰게 된다 (예: `1000`인데 천의 자리를 처리할 때 `u`가 안 넘어가 있으면 `M` 대신 `I`가 나옴). [273번 문제](../273-integer-to-english-words/Solution.md)에서도 똑같은 패턴의 버그를 겪었던 지점이다.
- `num`을 10으로 나누며 처리하므로 **낮은 자리부터** 결과가 만들어진다. 최종 문자열은 리스트를 **뒤에서부터** 이어붙여야 높은 자리(천의 자리)가 앞에 오는 올바른 순서가 된다.

### 손으로 시뮬레이션 — `num = 1005`

| 반복 | `no` (자릿수) | `u` | 처리 | `list` |
|---|---|---|---|---|
| 1 | `5` (일의 자리) | `0` | `a=1, b=0` → `unit[1]`="V" | `["V"]` |
| 2 | `0` (십의 자리) | `2` | 아무것도 안 붙임 | `["V"]` |
| 3 | `0` (백의 자리) | `4` | 아무것도 안 붙임 | `["V"]` |
| 4 | `1` (천의 자리) | `6` | `a=0, b=1` → `unit[6]`="M" | `["V", "M"]` |

`u`는 자릿수가 0이든 아니든 매 반복 2씩 증가한다(2 → 4 → 6). 마지막에 리스트를 뒤에서부터(`"M"`, `"V"`) 이어붙이면 **`"MV"`** — 정답과 일치한다.

## 3. 코드 (Java)

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public String intToRoman(int num) {
        char[] unit = {'I', 'V', 'X', 'L', 'C', 'D', 'M'}; // 자릿값별 기호 (2칸씩 묶어서 사용)
        List<String> list = new ArrayList<>(); // 낮은 자리부터 순서대로 쌓임

        int u = 0; // 지금 처리 중인 자릿수의 unit 배열 인덱스 (일=0, 십=2, 백=4, 천=6)
        while (num > 0) {
            int no = num % 10; // 가장 낮은 한 자리
            num = num / 10;

            if (no != 0) {
                StringBuilder sb = new StringBuilder();
                int a = no / 5, b = no % 5; // a: 5 이상인지, b: 5를 뺀 나머지(감산 표기법 판단용)
                if (b < 4) {
                    if (a == 1) sb.append(unit[u + 1]); // 5 이상이면 5의 기호부터
                    for (int i = 0; i < b; i++) sb.append(unit[u]); // 나머지는 기본 기호 반복
                } else {
                    sb.append(unit[u]).append(unit[u + a + 1]); // 4 또는 9: 감산 표기법
                }
                list.add(sb.toString());
            }
            u += 2; // no가 0이든 아니든 자릿수 인덱스는 매번 이동
        }

        StringBuilder sb = new StringBuilder();
        for (int i = list.size() - 1; i >= 0; i--) { // 높은 자리부터 나오도록 역순 순회
            sb.append(list.get(i));
        }
        return sb.toString();
    }
}
```

### 코드 설명

- `unit` 배열은 `I V X L C D M`을 순서대로 담고 있다. 한 자릿값이 `unit[u]`(기본 기호)와 `unit[u+1]`(5배 기호) 두 개를 쓰므로, 자릿수가 하나 올라갈 때마다 `u`를 2씩 옮기면 정확히 다음 자릿값의 기호 쌍을 가리키게 된다.
- `a = no / 5`, `b = no % 5`로 한 자리 숫자를 분해한다. `a`는 "5 이상인지"(0 또는 1), `b`는 5를 기준으로 한 나머지다. `b < 4`(즉 나머지가 0~3)면 일반적인 반복 표기, `b == 4`(원래 자리 숫자가 4 또는 9)면 감산 표기법이 필요하다는 뜻이다.
  - 감산 표기법 분기(`sb.append(unit[u]).append(unit[u + a + 1])`)에서 `a`가 0이면(원래 숫자 4) `unit[u + 1]`(한 자리 위 5배 기호, 예: `V`)까지, `a`가 1이면(원래 숫자 9) `unit[u + 2]`(한 자리 위 기본 기호, 예: `X`)까지 참조해 `IV`/`IX` 패턴을 만든다.
- `if (no != 0) { ... } u += 2;` 구조가 핵심이다. 자릿수가 0이라 몸통을 건너뛰어도 `u += 2`는 조건문 **바깥**에 있어서 항상 실행된다 — 이전에 `continue`로 건너뛰다가 인덱스 증가까지 같이 스킵됐던 버그를 이 구조 자체로 원천 차단한다.
- 낮은 자리부터 만들어진 `list`를 마지막에 뒤에서부터 순회하며 이어붙여 올바른 순서(천→백→십→일)로 완성한다.

## 4. 복잡도 분석

- **시간복잡도**: `O(log num)` — `num`을 10으로 계속 나누므로 반복 횟수는 자릿수(최대 4자리, `num ≤ 3999`)에 비례. 각 반복은 상수 시간.
- **공간복잡도**: `O(1)` — 결과 문자열 길이도 최대 자릿수에 비례하는 상수 수준(최대 15자, `MMMDCCCLXXXVIII` = 3888).

## 5. 엣지 케이스

- **자릿수 중간에 0이 낀 경우** (`1005`, `1000`, `2000`): 0인 자릿수는 아무 글자도 안 붙지만, 인덱스는 반드시 넘어가야 그다음 자릿수가 올바른 기호를 쓴다.
- **감산 표기법이 필요한 모든 경우** (`4, 9, 40, 90, 400, 900`): `b == 4` 분기가 정확히 이 값들을 잡아낸다.
- **최댓값 `3999`**: 4자리 전부가 채워지는 경우 (`MMMCMXCIX`).
- **최솟값 `1`**: 한 자리, 감산 없는 단순 반복 케이스 (`I`).
