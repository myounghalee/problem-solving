# [LeetCode 36] Valid Sudoku — 행·열·박스를 한 번의 순회로 동시에 검사하기

- 문제 번호: 36
- 링크: https://leetcode.com/problems/valid-sudoku/
- 난이도: Medium
- 태그: Array, Hash Table, Matrix
- 사용 자료구조/알고리즘: **인덱스 변환 + `HashSet` 중복 검사**

## 1. 문제 요약

`9 x 9` 스도쿠 판에서 **이미 채워진 칸들만** 보고 규칙 위반이 없는지 판정한다.

1. 각 **행**에 숫자 중복이 없을 것
2. 각 **열**에 숫자 중복이 없을 것
3. 아홉 개의 **3 x 3 박스** 각각에 숫자 중복이 없을 것

빈 칸 `'.'`은 검사 대상이 아니고, "유효한 판"이 "풀 수 있는 판"을 뜻하지도 않는다. 지금 놓인 숫자들이 규칙을 어기지 않았는지만 보면 된다.

## 2. 접근 아이디어

가장 먼저 떠오르는 건 행 9번, 열 9번, 박스 9번 — 총 세 번에 걸쳐 판을 훑는 방식이다. 정확하지만 판을 세 바퀴 돈다.

여기서 쓴 방법은 **바깥 루프 한 번에 세 가지를 동시에 처리**한다. 핵심은 `i`를 세 가지 의미로 겹쳐 쓰는 것이다.

- `i`번째 **행**을 검사할 때 → `board[i][j]` (`j`가 0→8로 열을 훑음)
- `i`번째 **열**을 검사할 때 → `board[j][i]` (인덱스만 뒤집으면 됨)
- `i`번째 **박스**를 검사할 때 → 아래 인덱스 변환식

즉 `i`는 "지금 몇 번째 행/열/박스를 보는 중인가"이고, `j`는 "그 안의 몇 번째 칸인가"다. 셋 다 검사 대상이 9개씩이라 하나의 루프에 얹을 수 있다.

`row`, `col`, `block` 세 개의 `HashSet`을 `i`가 바뀔 때마다 새로 만들면, 각 집합은 "현재 보고 있는 행/열/박스 안에 이미 나온 숫자들"을 담게 된다. 넣으려는 숫자가 이미 있으면 곧바로 `false`다.

### 박스 인덱스 변환 — 이 문제의 핵심

`i`번째 박스의 `j`번째 칸이 판 위의 어느 좌표인지 구해야 한다. 박스에 이렇게 번호를 매긴다고 하자.

```text
박스 0 | 박스 1 | 박스 2
-------+--------+-------
박스 3 | 박스 4 | 박스 5
-------+--------+-------
박스 6 | 박스 7 | 박스 8
```

- 박스 `i`는 **박스 좌표** `(i / 3, i % 3)`에 있다. 박스 4라면 `(1, 1)` — 가운데 박스.
- 박스 좌표에 3을 곱하면 그 박스의 **왼쪽 위 칸**이 나온다. 박스 4의 시작점은 `(3, 3)`.
- 박스 안에서 `j`번째 칸은 그 시작점으로부터 `(j / 3, j % 3)`만큼 떨어져 있다.

두 개를 더하면 최종 좌표다.

```java
행 = 3 * (i / 3) + (j / 3)
열 = 3 * (i % 3) + (j % 3)
```

**`i`에는 `/3`과 `%3`이, `j`에도 `/3`과 `%3`이 쓰이는데 짝이 엇갈린다는 점**이 헷갈리는 이유다. 행 쪽은 `i / 3`과 `j / 3`, 열 쪽은 `i % 3`과 `j % 3`으로 같은 연산끼리 짝을 이룬다고 외우면 덜 틀린다.

### 손으로 확인 — 박스 5 (`i = 5`)

`i = 5` → 박스 좌표 `(5/3, 5%3) = (1, 2)` → 시작점 `(3, 6)`. 우측 중단 박스가 맞다.

| `j` | `j/3`, `j%3` | 좌표 |
|---|---|---|
| 0 | 0, 0 | (3, 6) |
| 1 | 0, 1 | (3, 7) |
| 2 | 0, 2 | (3, 8) |
| 3 | 1, 0 | (4, 6) |
| 4 | 1, 1 | (4, 7) |
| ... | ... | ... |
| 8 | 2, 2 | (5, 8) |

`(3,6)`부터 `(5,8)`까지 정확히 3x3 영역을 덮는다.

## 3. 코드 (Java)

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public boolean isValidSudoku(char[][] board) {

        Set<Integer> row;
        Set<Integer> col;
        Set<Integer> block;
        for (int i = 0; i < 9; i++) {
            row = new HashSet<>();   // i번째 행에 나온 숫자들
            col = new HashSet<>();   // i번째 열에 나온 숫자들
            block = new HashSet<>(); // i번째 박스에 나온 숫자들
            for (int j = 0; j < 9; j++) {
                if (check(board[i][j], row)) return false;
                if (check(board[j][i], col)) return false;
                if (check(board[(j / 3) + 3 * (i / 3)][(j % 3) + 3 * (i % 3)], block)) return false;
            }
        }

        return true;
    }

    // 위반이면 true. 빈 칸은 위반 아님, 이미 나온 숫자면 위반, 처음이면 기록
    private boolean check(char val, Set<Integer> set) {
        if (val == '.') return false;
        if (set.contains(val - '0')) return true;
        set.add(val - '0');
        return false;
    }
}
```

### 코드 설명

- **세 집합을 `i` 루프 안에서 새로 만드는 것**이 중요하다. `i`가 바뀌면 다른 행/열/박스로 넘어가므로 이전 기록이 남아 있으면 안 된다. 반대로 `j` 루프 안에서는 계속 누적되어야 중복을 잡을 수 있다.
- `check` 메서드로 "빈 칸 건너뛰기 → 중복 확인 → 기록" 세 단계를 묶어, 행·열·박스 세 곳에서 똑같은 로직을 재사용한다. 이게 없으면 같은 코드가 세 번 반복된다.
- `check`는 **"위반이면 `true`"**를 반환한다. 호출부가 `if (check(...)) return false;`로 읽혀 "걸리면 즉시 실패"라는 흐름이 그대로 드러난다. 반대로 "정상이면 `true`"로 두면 호출부마다 `!`가 붙어(`if (!check(...))`) 이중 부정이 되므로, 지금 방향이 읽기 편하다. 다만 이름이 `check`라 어느 쪽이 참인지 모호해지는 건 사실이라, `isDuplicate`처럼 참일 때의 의미가 드러나는 이름이 더 낫다.
- `board[j][i]`는 `board[i][j]`의 인덱스를 뒤집은 것으로, 같은 `j` 루프 안에서 열을 위에서 아래로 훑는다. 행과 열을 한 루프에서 동시에 처리할 수 있는 이유다.
- `val - '0'`으로 문자를 정수로 바꿔 `Set<Integer>`에 넣는다. `Set<Character>`에 문자 그대로 넣어도 결과는 같다.
- 위반을 발견하면 **즉시 `return false`**로 빠져나간다. 남은 칸을 더 볼 이유가 없다.

## 4. 복잡도 분석

- **시간복잡도**: `O(1)` — 판 크기가 `9 x 9`로 고정이라 항상 81칸의 3배인 243번의 `check` 호출로 끝난다. 입력 크기에 따라 변하는 값이 없다. (판을 `n x n`으로 일반화하면 `O(n^2)`이고, 이는 모든 칸을 최소 한 번은 봐야 하므로 최적이다.)
- **공간복잡도**: `O(1)` — 집합 세 개가 각각 최대 9개의 숫자만 담는다.

## 5. 엣지 케이스

- **전부 빈 칸**: 검사할 숫자가 하나도 없으므로 `true`.
- **완성된 정답 스도쿠**: 81칸이 모두 채워져 있어도 규칙 위반이 없으므로 `true`.
- **박스에서만 걸리는 판**: 행도 열도 겹치지 않는데 같은 박스 안에서만 중복인 경우 (아래 6절).
- **같은 숫자가 여러 번 등장하되 위반은 아닌 경우**: 예를 들어 `5`가 판 전체에 9번 나와도, 서로 다른 행·열·박스에 흩어져 있으면 유효하다. "숫자별 전체 등장 횟수"를 세는 방식으로 접근하면 여기서 틀린다.

검증: 무작위로 생성한 판 **30만 개**(유효한 판 약 16만 개 포함)를 독립 구현한 기준 답과 교차 비교해 전부 일치했다. 9개 박스 각각에 박스 전용 중복을 심은 판도 모두 정확히 걸러냈다.

## 6. 흔한 함정 — 박스 검사를 빼먹었는지 확인하려면

박스 인덱스 변환식은 이 문제에서 가장 틀리기 쉬운 부분인데, **문제의 공식 예제만으로는 그 오류가 드러나지 않는다.**

LeetCode 예제 2는 좌측 상단 박스에 `8`이 두 번 있어 무효인 판이다. 그런데 이 판은 **0번 열에도 `8`이 두 번** 있다.

```text
예제 2의 0번 열: 8 6 . 8 4 7 . . .
                 ↑       ↑
```

즉 박스 검사를 통째로 지워도, 혹은 인덱스 변환식이 틀려 엉뚱한 칸을 봐도, 열 검사가 대신 잡아주기 때문에 `false`가 나온다. **예제를 통과했다는 사실이 박스 검사가 맞다는 증거가 되지 못한다.**

박스로만 걸리는 판을 직접 만들어야 한다. 가장 단순한 형태는 같은 박스 안의 대각선 두 칸에 같은 숫자를 놓는 것이다.

```java
// (0,0)과 (1,1) — 행도 다르고 열도 다르지만 같은 3x3 박스
char[][] boxOnly = toBoard(
        "5........",
        ".5.......",
        ".........",
        ".........", ".........", ".........",
        ".........", ".........", ".........");
// 행·열만 검사하면 true, 박스까지 검사해야 false
```

더 확실하게는 **9개 박스 각각에 같은 함정을 심어** 전부 잡히는지 보면 된다. 인덱스 변환식이 특정 박스에서만 어긋나는 경우까지 걸러낼 수 있다.

```java
for (int bi = 0; bi < 9; bi++) {
    char[][] b = emptyBoard();
    int r0 = 3 * (bi / 3), c0 = 3 * (bi % 3);
    b[r0][c0] = '7';
    b[r0 + 1][c0 + 1] = '7'; // 같은 박스, 다른 행·열
    assert !sol.isValidSudoku(b) : "박스 " + bi + " 놓침";
}
```

**교훈: 여러 조건을 검사하는 문제에서는 "그 조건 하나만 위반하는" 최소 입력을 조건마다 따로 만들자.** 다른 조건이 대신 잡아주면 버그가 숨는다.

## 7. 이런 방법도 있다 — 인덱스 변환 없이 박스 처리하기

박스 인덱스 변환식이 부담스럽다면, **칸을 훑으면서 그 칸이 속한 박스 번호를 역으로 계산**하는 방법이 있다. 집합 27개를 미리 만들어두고 한 칸당 세 번 기록하는 방식이다.

```java
class Solution {
    public boolean isValidSudoku(char[][] board) {
        boolean[][] row = new boolean[9][9];   // row[행][숫자-1]
        boolean[][] col = new boolean[9][9];   // col[열][숫자-1]
        boolean[][] box = new boolean[9][9];   // box[박스번호][숫자-1]

        for (int i = 0; i < 9; i++) {
            for (int j = 0; j < 9; j++) {
                if (board[i][j] == '.') continue;
                int d = board[i][j] - '1';     // 0~8
                int b = (i / 3) * 3 + j / 3;   // (i,j)가 속한 박스 번호
                if (row[i][d] || col[j][d] || box[b][d]) return false;
                row[i][d] = col[j][d] = box[b][d] = true;
            }
        }
        return true;
    }
}
```

여기서는 변환의 방향이 반대다. 3절 코드가 **박스 번호 → 좌표**를 구했다면, 이 코드는 **좌표 → 박스 번호**(`(i / 3) * 3 + j / 3`)를 구한다. 후자가 더 짧고 직관적이라 실전에서 더 자주 쓰인다.

**비교:**

| | 인덱스 변환 (위 3.의 코드) | 좌표 → 박스 번호 |
|---|---|---|
| 판 순회 | 행/열/박스를 겹쳐 한 바퀴 | 각 칸을 정확히 한 번 |
| 변환식 | `3*(i/3)+j/3`, `3*(i%3)+j%3` | `(i/3)*3 + j/3` 하나 |
| 자료구조 | `HashSet` 3개(매 `i`마다 재생성) | `boolean[9][9]` 3개(재생성 없음) |
| 각 칸 방문 횟수 | 3회 (행·열·박스에서 한 번씩) | 1회 |
| 해싱 비용 | 있음 | 없음 (배열 인덱싱) |

둘 다 `O(1)`이고 판이 81칸뿐이라 실측 차이는 무의미하다. 다만 `boolean[9][9]` 버전은 해싱과 박싱이 없고 집합 재생성도 없어 상수 배가 작다. 앞서 [3번 문제](../3-longest-substring-without-repeating-characters/Solution.md)에서 `HashSet<Character>` 대신 `int[128]`이 빨랐던 것과 같은 이유다.
