# [LeetCode 189] Rotate Array — 여분 배열에 인덱스를 매핑해서 옮겨 담기

- 문제 번호: 189
- 링크: https://leetcode.com/problems/rotate-array/
- 난이도: Medium
- 태그: Array, Math, Two Pointers
- 사용 자료구조/알고리즘: **여분 배열(Extra Array) + 인덱스 매핑**

## 1. 문제 요약

배열 `nums`를 오른쪽으로 `k`칸 회전시켜야 한다. 새 배열을 반환하는 게 아니라 `nums` 자체를 제자리(in-place)에서 수정한다.

```text
예시) nums = [1,2,3,4,5,6,7], k = 3 → nums = [5,6,7,1,2,3,4]
      nums = [-1,-100,3,99], k = 2 → nums = [3,99,-1,-100]
```

> 처음엔 "1칸 회전을 `k`번 반복"하는 브루트포스로 풀었는데, 시간복잡도가 `O(n*k)`라 `n`, `k`가 모두 `10^5`에 가까우면 연산이 `10^10`에 달해 **Time Limit Exceeded**가 났다. 아래는 그 문제를 해결한 `O(n)` 풀이다.

## 2. 접근 아이디어

핵심은 "회전 후 배열에서, 원래 배열의 어느 원소가 어느 자리로 가는가"를 **인덱스 계산만으로 바로 알아낼 수 있다**는 점이다. 굳이 한 칸씩 밀어보지 않아도 된다.

오른쪽으로 `k`칸 회전한 결과는, 원본 배열을 **뒤에서부터 `k`개**와 **앞에서부터 `n-k`개**로 잘라서 순서를 바꿔 이어붙인 것과 같다.

```text
원본:        [ 앞쪽 (n-k개) | 뒤쪽 (k개) ]
회전 후:      [ 뒤쪽 (k개)  | 앞쪽 (n-k개) ]
```

그래서 다음과 같이 처리한다.

1. `nums`를 그대로 복사한 `copy` 배열을 만든다 (원본 값을 덮어쓰기 전에 보존).
2. `k`가 `nums.length`보다 클 수 있으므로 먼저 `k %= nums.length`로 줄인다 — 한 바퀴(`n`칸) 회전은 원래 자리로 돌아오는 것과 같기 때문이다.
3. `copy`의 **뒤쪽 `k`개**(`copy[n-k]` ~ `copy[n-1]`)를 `nums`의 **맨 앞부터** 채워 넣는다.
4. 이어서 `copy`의 **앞쪽 `n-k`개**(`copy[0]` ~ `copy[n-k-1]`)를 그 뒤에 채워 넣는다.

한 바퀴만 순회하면서 값을 정해진 위치에 옮겨 담기만 하면 되므로, 별도의 회전 연산을 반복할 필요가 없다.

### 손으로 시뮬레이션 — `nums = [1,2,3,4,5,6,7]`, `k = 3`

`n = 7`, `k %= n` → `k = 3` (변화 없음). `copy = [1,2,3,4,5,6,7]`.

**1단계 — `copy`의 뒤쪽 3개(`copy[4..6]`)를 `nums[0..2]`에 복사**

| i (copy 인덱스) | copy[i] | index (nums 쓰기 위치) | nums 상태 |
|---|---|---|---|
| 4 | 5 | 0 | [5,_,_,_,_,_,_] |
| 5 | 6 | 1 | [5,6,_,_,_,_,_] |
| 6 | 7 | 2 | [5,6,7,_,_,_,_] |

**2단계 — `copy`의 앞쪽 4개(`copy[0..3]`)를 `nums[3..6]`에 복사**

| i (copy 인덱스) | copy[i] | index (nums 쓰기 위치) | nums 상태 |
|---|---|---|---|
| 0 | 1 | 3 | [5,6,7,1,_,_,_] |
| 1 | 2 | 4 | [5,6,7,1,2,_,_] |
| 2 | 3 | 5 | [5,6,7,1,2,3,_] |
| 3 | 4 | 6 | [5,6,7,1,2,3,4] |

최종 `nums = [5,6,7,1,2,3,4]` — 정답과 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int[] copy = nums.clone();       // 원본 값 보존용 복사본
        int index = 0;                    // nums에 다음으로 쓸 위치
        k = k % nums.length;              // k가 배열 길이보다 클 경우를 대비해 축소
        for (int i = nums.length - k; i < nums.length; i++) { // copy의 뒤쪽 k개
            nums[index++] = copy[i];
        }
        for (int i = 0; i < nums.length - k; i++) {           // copy의 앞쪽 n-k개
            nums[index++] = copy[i];
        }
    }
}
```

### 코드 설명

- `copy`는 `nums`를 덮어쓰기 시작하기 전에 원본을 그대로 떠둔 스냅샷이다. `nums` 자체를 바로 읽고 쓰면 아직 안 읽은 값을 덮어쓸 위험이 있으므로, 읽기는 항상 `copy`에서만 한다.
- `k %= nums.length`를 먼저 하지 않으면, 두 번째 `for`문의 범위(`nums.length - k`)가 음수가 되어 배열 범위를 벗어날 수 있다.
- 첫 번째 `for`문은 "회전 후 맨 앞에 와야 할 값들"(원본의 뒤쪽 `k`개)을, 두 번째 `for`문은 "그 다음에 이어질 값들"(원본의 앞쪽 `n-k`개)을 순서대로 옮겨 담는다. `index`는 두 루프에 걸쳐 계속 이어지며 `nums`를 처음부터 끝까지 한 번만 채운다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — `copy` 생성에 `O(n)`, 두 `for`문을 합쳐도 `nums`를 한 번만 순회한다.
- **공간복잡도**: `O(n)` — 원본과 같은 크기의 `copy` 배열을 추가로 사용한다. (문제의 O(1) 공간 조건은 만족하지 않지만, 시간복잡도 문제였던 브루트포스를 O(n)으로 개선했다.)

## 5. 엣지 케이스

- **`k = 0`**: `k %= n`을 해도 `0`. 첫 번째 `for`문은 `i`가 `nums.length`부터 시작해 `nums.length`보다 작다는 조건을 만족하지 않으므로 실행되지 않고, 두 번째 `for`문이 배열 전체를 그대로 복사한다 — 결과적으로 원본과 동일.
- **`k`가 `nums.length`의 배수**(예: `k = n`): `k %= n`으로 `0`이 되어 위와 동일하게 처리된다.
- **`nums.length = 1`**: `k %= 1`은 항상 `0`이 되어 배열이 그대로 유지된다.
- **`k > nums.length`**: `k %= nums.length`로 먼저 줄이기 때문에 범위를 벗어나지 않고 정상 동작한다.

## 6. 다른 풀이 — 배열 뒤집기(Reverse) 3번으로 O(1) 공간에 풀기

이 문제는 "가능한 한 여러 방법을 찾아보라"는 follow-up이 있다. 위 풀이는 `O(n)` 공간을 쓰는데, **추가 배열 없이 `O(1)` 공간**만으로도 `O(n)` 시간에 풀 수 있는 방법이 있다 — 배열을 세 번 뒤집는 방식이다.

### 아이디어

오른쪽으로 `k`칸 회전한 결과는 "전체를 뒤집은 뒤, 앞 `k`개와 뒤 `n-k`개를 각각 다시 뒤집은 것"과 같다.

```text
원본:            [1,2,3,4,5,6,7]         (k=3)
① 전체 뒤집기:    [7,6,5,4,3,2,1]
② 앞 k개 뒤집기:  [5,6,7,4,3,2,1]         (인덱스 0~2만 다시 뒤집음)
③ 뒤 n-k개 뒤집기: [5,6,7,1,2,3,4]         (인덱스 3~6만 다시 뒤집음)
```

전체를 한 번 뒤집으면 순서가 반대로 되면서 "뒤쪽 `k`개가 앞으로 온다"는 목표는 달성되지만, 그 `k`개 내부와 나머지 부분의 내부 순서도 함께 뒤집혀버린다. 그래서 두 구간을 부분적으로 한 번씩 더 뒤집어서 내부 순서만 원래대로 되돌려주는 것이다.

### 코드 (Java)

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k %= n;                      // k가 배열 길이보다 클 경우를 대비해 축소
        reverse(nums, 0, n - 1);     // ① 전체 뒤집기
        reverse(nums, 0, k - 1);     // ② 앞 k개만 다시 뒤집기
        reverse(nums, k, n - 1);     // ③ 뒤 n-k개만 다시 뒤집기
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            int temp = nums[left];
            nums[left] = nums[right];
            nums[right] = temp;
            left++;
            right--;
        }
    }
}
```

### 복잡도

- **시간복잡도**: `O(n)` — 세 번의 뒤집기를 합쳐도 각 원소는 상수 번만 이동한다.
- **공간복잡도**: `O(1)` — `reverse`에서 쓰는 임시 변수 `temp` 외에 추가 자료구조가 없다.

여분 배열 방식과 시간복잡도는 같지만(`O(n)`), 공간을 `O(n)`에서 `O(1)`로 줄였다는 점이 차이다. `k = 0`이면 `reverse(nums, 0, -1)`이 호출되는데, `left(0) < right(-1)`이 거짓이라 아무 일도 하지 않고 바로 반환되어 안전하다.
