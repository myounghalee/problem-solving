# [LeetCode 122] Best Time to Buy and Sell Stock II — 국소 최고점마다 이익을 확정하며 훑기

- 문제 번호: 122
- 링크: https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/
- 난이도: Medium
- 태그: Array, Dynamic Programming, Greedy
- 사용 자료구조/알고리즘: **한 번의 순회(단일 패스) + 그리디**

## 1. 문제 요약

[121번(한 번만 사고팔기)](../121-best-time-to-buy-and-sell-stock/Solution.md)과 달리, 이번엔 **거래 횟수 제한이 없다**. 동시에 두 주를 들고 있을 수만 없을 뿐, 원하는 만큼 사고팔아서 총 이익을 최대화한다.

```text
예시) prices = [7,1,5,3,6,4] → 7   (1에 사서 5에 팔고(+4), 3에 사서 6에 팔면(+3), 합 7)
      prices = [1,2,3,4,5]   → 4   (1에 사서 5에 팔면 4, 나눠 사고팔아도 합은 동일)
      prices = [7,6,4,3,1]   → 0   (계속 하락만 하므로 거래할 이유가 없음)
```

## 2. 접근 아이디어

거래 횟수 제한이 없으므로, 그래프상에서 **가격이 오르는 구간(골짜기 → 봉우리)마다 한 번씩 사고팔면** 그 구간의 상승분을 전부 이익으로 챙길 수 있다. 반대로 가격이 내려가는 구간은 아예 손대지 않으면 손해를 볼 일이 없다.

이 문제는 121번에서 쓰던 "지금까지의 최저가 `min`"과 "그 최저가 기준 최대 이익 `tmp`"를 그대로 활용하되, **국소 최고점(local peak)을 만날 때마다 그동안 쌓인 이익을 확정하고 새로 시작**한다는 점이 다르다.

- `min`: 현재 구간(마지막으로 이익을 확정한 지점 이후)에서 지금까지 본 가격 중 최솟값.
- `tmp`: `min`에 사서 오늘 팔았을 때 얻을 수 있는, 현재 구간에서의 최대 이익.
- `ans`: 지금까지 확정된 이익의 총합.

매 날짜 `i`(1부터 시작)마다:

1. `tmp`를 "오늘 팔았다면"의 이익(`prices[i] - min`)과 비교해 갱신한다.
2. `min`을 오늘 가격으로 갱신한다(더 낮은 가격이 나왔으면 최저가 후보 교체).
3. **오늘이 국소 최고점인지 확인**한다 — 오늘 가격이 내일 가격보다 높다면(`prices[i] > prices[i+1]`), 내일부터는 가격이 떨어지므로 오늘 파는 게 이 구간에서 최선이다. 그동안 쌓인 `tmp`를 `ans`에 더해 확정하고, 오늘 가격을 다음 구간의 `min`으로 삼아 `tmp`를 `0`으로 리셋한다.
4. 마지막 날(`i == prices.length - 1`)에는 다음 날이 없어 "국소 최고점" 판정을 할 수 없으므로, 그때까지 쌓인 `tmp`를 무조건 `ans`에 더해 마무리한다.

리셋 시 `min`을 그날의 가격(국소 최고점)으로 설정하는 게 언뜻 이상해 보일 수 있지만, 국소 최고점 다음 날은 반드시 가격이 더 낮으므로(그래서 리셋이 일어난 것) 바로 다음 반복에서 `min`이 그 더 낮은 값으로 즉시 교체된다 — 일시적으로 `min`이 부정확해 보이는 순간에도 `tmp` 계산 결과가 음수라 `0`으로 클리핑되기 때문에 실제 이익 계산엔 영향이 없다.

### 손으로 시뮬레이션 — `prices = [7,1,5,3,6,4]`

시작: `min = 7`, `ans = 0`, `tmp = 0`

| i | prices[i] | tmp = max(tmp, prices[i]-min) | min 갱신 | 다음날과 비교 (prices[i] > prices[i+1]?) | 리셋 시 ans / min |
|---|---|---|---|---|---|
| 1 | 1 | max(0,1-7=-6)=0 | min(7,1)=1 | 1 > 5? 아니오 | - |
| 2 | 5 | max(0,5-1=4)=4 | min(1,5)=1 | 5 > 3? **예** | ans=0+4=4, min=5, tmp=0 |
| 3 | 3 | max(0,3-5=-2)=0 | min(5,3)=3 | 3 > 6? 아니오 | - |
| 4 | 6 | max(0,6-3=3)=3 | min(3,6)=3 | 6 > 4? **예** | ans=4+3=7, min=6, tmp=0 |
| 5(마지막) | 4 | max(0,4-6=-2)=0 | min(6,4)=4 | 마지막 날 → 무조건 확정 | ans=7+0=7 |

최종 `ans = 7` — 정답과 일치한다. (1에 사서 5에 판 `+4`와 3에 사서 6에 판 `+3`이 각각 국소 최고점 `5`, `6`에서 확정됐다.)

## 3. 코드 (Java)

```java
class Solution {
    public int maxProfit(int[] prices) {
        int min = prices[0]; // 현재 구간에서 지금까지의 최저가
        int ans = 0;          // 확정된 이익의 총합
        int tmp = 0;          // 현재 구간에서 min에 사서 오늘 팔았을 때의 최대 이익
        for (int i = 1; i < prices.length; i++) {
            tmp = Math.max(tmp, prices[i] - min); // 오늘 팔았을 때의 이익과 비교
            min = Math.min(min, prices[i]);        // 최저가 갱신

            if (i < prices.length - 1) {
                if (prices[i] > prices[i + 1]) {   // 오늘이 국소 최고점(내일은 하락)
                    ans += tmp;                     // 지금까지의 이익을 확정
                    min = prices[i];                // 다음 구간 기준점으로 설정 (바로 다음 반복에서 실제 최저가로 교체됨)
                    tmp = 0;
                }
            } else {
                ans += tmp;                         // 마지막 날은 무조건 확정
            }
        }
        return ans;
    }
}
```

### 코드 설명

- `min`과 `tmp`는 "마지막으로 이익을 확정한 지점 이후" 구간만을 기준으로 계속 갱신된다. 국소 최고점에서 `ans`에 더해 확정하고 나면, 그 시점부터 다시 새 구간이 시작되는 셈이다.
- `prices[i] > prices[i+1]`이라는 조건은 "오늘이 상승세의 끝(꼭짓점)"이라는 뜻이다. 이 시점에 팔지 않으면 내일 가격이 떨어져 손해를 보므로, 그리디하게 바로 확정 짓는다.
- 리셋 직후 `min = prices[i]`는 이론적으로만 보면 아직 정확한 최저가가 아니지만, 다음 반복에서 `prices[i+1] < prices[i]`이므로 `min`이 즉시 올바른 값으로 갱신되고, 그사이에 계산되는 `tmp`는 어차피 음수라 `0`으로 유지되어 결과에 영향을 주지 않는다.
- 마지막 날은 "다음 날"이 없어 국소 최고점 판정이 불가능하므로 별도 분기(`else`)에서 무조건 `ans`에 더해준다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 한 번만 순회한다.
- **공간복잡도**: `O(1)` — `min`, `ans`, `tmp` 세 변수만 사용한다.

참고로 이 문제의 가장 널리 알려진 풀이는 "매일 전날보다 가격이 올랐으면 그 차액을 전부 더한다"(`sum += max(0, prices[i] - prices[i-1])`)는 훨씬 단순한 그리디다. 이 풀이는 그것과 결과적으로 동일한 값을 내지만, "국소 최고점마다 구간을 끊어서 확정 짓는다"는 관점으로 접근한 것이 차이다 — 어느 한 상승 구간(골짜기~봉우리) 안에서는 중간 등락과 무관하게 "구간의 최저가에 사서 최고가에 파는 이익"이 "그 구간 안의 매일 상승분을 다 더한 것"과 정확히 같기 때문에 두 방식의 결과는 항상 일치한다.

## 5. 엣지 케이스

- **배열 길이가 1**: 루프가 한 번도 안 돌아 `ans = 0`을 그대로 반환한다 — 거래할 날이 하루뿐이면 이익을 낼 수 없으므로 옳다.
- **계속 하락하는 경우**(`[7,6,4,3,1]`): 매번 `prices[i] - min`이 `0` 이하라 `tmp`가 계속 `0`이고, 리셋이 일어나도 더해지는 값이 `0`이라 최종 `ans = 0`.
- **평탄 구간(같은 값이 연속)**(`[3,3,3,3]`): `prices[i] > prices[i+1]`이 항상 거짓(같으므로)이라 리셋이 일어나지 않고, `tmp`도 계속 `0`이라 `ans = 0`.
- **국소 최고점이 여러 번 나오는 경우**(`[1,4,2,5,7,3,8]`): 리셋이 여러 번 일어나며 각 상승 구간(`1→4`, `2→7`, `3→8`)의 이익이 각각 확정되어 합산된다(검증 결과 `13`).
