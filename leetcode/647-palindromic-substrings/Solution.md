# [LeetCode 647] Palindromic Substrings — 팰린드롬 판정 DP 테이블로 개수 세기

- 문제 번호: 647
- 링크: https://leetcode.com/problems/palindromic-substrings/
- 난이도: Medium
- 태그: Two Pointers, String, Dynamic Programming
- 사용 자료구조/알고리즘: **구간 DP (팰린드롬 여부 테이블)**

## 1. 문제 요약

문자열 `s`가 주어질 때, `s` 안에 있는 팰린드롬 부분 문자열(연속된 구간)의 총 개수를 반환한다. 같은 문자열이라도 위치가 다르면 별개로 센다.

```text
예시) "abc" → 3   ("a", "b", "c")
      "aaa" → 6   ("a"×3, "aa"×2, "aaa"×1)
```

## 2. 접근 아이디어

[516번(Longest Palindromic Subsequence)](../516-longest-palindromic-subsequence/Solution.md)에서 썼던 구간 DP와 같은 틀을 쓰되, 이번엔 "최장 길이"가 아니라 **"이 구간이 팰린드롬인가(참/거짓)"**만 저장한다.

- `dp[l][r]`: `s[l..r]` 구간이 팰린드롬이면 `1`, 아니면 `0`.
- **구간 길이 1** (`l == r`): 항상 팰린드롬. `dp[l][l] = 1`.
- **구간 길이 2** (`r == l+1`): 양 끝 두 글자가 같으면 팰린드롬. 안쪽에 확인할 게 없으므로 `c[l] == c[r]`이면 바로 `1`.
- **구간 길이 3 이상**: 양 끝 글자가 같고, **그 안쪽 구간(`l+1, r-1`)도 팰린드롬**이어야 전체가 팰린드롬이다.
- 구간 길이가 짧은 것부터 순서대로 채워야, 긴 구간을 판정할 때 필요한 안쪽 구간 결과가 미리 준비되어 있다.
- 다 채운 뒤, `dp` 테이블에서 `1`인 칸의 개수를 모두 더하면 그게 곧 팰린드롬 부분 문자열의 총 개수다 — 서로 다른 `(l, r)` 쌍 하나하나가 서로 다른 부분 문자열(위치 기준)에 대응하기 때문이다.

### 손으로 시뮬레이션 — `s = "aaa"`

인덱스: `a`0 `a`1 `a`2

**길이 1** (`i=0`): `dp[0][0]=1`, `dp[1][1]=1`, `dp[2][2]=1` → 팰린드롬 3개

**길이 2** (`i=1`):
- `dp[0][1]`: `c[0]='a'==c[1]='a'` → `1`
- `dp[1][2]`: `c[1]='a'==c[2]='a'` → `1`
→ 팰린드롬 2개 추가

**길이 3** (`i=2`):
- `dp[0][2]`: `c[0]='a'==c[2]='a'`이고, 안쪽 `dp[1][1]==1` → `1`
→ 팰린드롬 1개 추가

총 `3 + 2 + 1 = 6`개 — 정답과 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    public int countSubstrings(String s) {
        char[] c = s.toCharArray();
        int n = s.length();
        int[][] dp = new int[n][n]; // dp[l][r]: s[l..r]가 팰린드롬이면 1

        for (int i = 0; i < n; i++) { // i: 구간 길이 - 1 (짧은 구간부터)
            for (int j = 0; j < n - i; j++) { // j: 시작 인덱스, j+i: 끝 인덱스
                if (c[j] == c[j + i]) {
                    // 길이 1(j==j+i)은 자기 자신과 비교라 항상 참, 길이 2(i==1)는 안쪽을 볼 필요 없음,
                    // 길이 3 이상은 안쪽 구간(dp[j+1][j+i-1])도 팰린드롬이어야 함
                    if (j == j + i || i == 1 || dp[j + 1][j + i - 1] == 1) dp[j][j + i]++;
                }
            }
        }

        int res = 0;
        for (int[] row : dp) {
            for (int v : row) res += v; // dp가 1인 칸의 총 개수 = 팰린드롬 부분 문자열 개수
        }
        return res;
    }
}
```

### 코드 설명

- `i`는 구간 길이에서 1을 뺀 값(`= r - l`)이며, 짧은 구간부터 채우기 위한 바깥 루프다. `j`는 구간의 시작 인덱스다.
- `if (c[j] == c[j + i])` 하나로 세 가지 길이를 전부 처리한다. `j == j + i`(길이 1)일 때는 `c[j]`를 자기 자신과 비교하는 셈이라 이 바깥 조건이 항상 참이 되므로, 별도 분기 없이 자연스럽게 안으로 들어온다.
- 안쪽 `if (j == j + i || i == 1 || dp[j + 1][j + i - 1] == 1)`가 세 가지 경우를 하나로 묶는다: **길이 1**은 그 자체로 팰린드롬, **길이 2**(`i == 1`)는 양 끝만 같으면 확정, **길이 3 이상**은 안쪽 구간(`dp[j+1][j+i-1]`)까지 팰린드롬이어야 확정된다. 셋 중 하나만 참이어도 `dp[j][j+i]++`.
- 마지막에 `dp` 테이블 전체를 순회하며 `1`인 칸(=팰린드롬인 구간)의 개수를 더해 반환한다. 이 2차원 배열의 각 칸이 정확히 하나의 "부분 문자열(위치 포함)"에 대응하므로, 단순 합산이 곧 "몇 개의 팰린드롬 부분 문자열이 있는가"의 답이 된다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n²)` — 구간의 개수가 `O(n²)`개이고, 각 구간은 상수 시간에 판정된다. 마지막 합산도 `O(n²)`.
- **공간복잡도**: `O(n²)` — `dp` 2차원 배열.

`s.length ≤ 1000`에서 `O(n²)` ≈ `10^6`으로 충분히 빠르다. 실제로 길이 1000짜리 문자열(`"a"` 반복)로 테스트해도 5ms 안에 끝난다.

## 5. 엣지 케이스

- **길이 1인 문자열**: `dp[0][0]=1`, 결과는 `1`.
- **전체가 같은 문자로 이루어진 경우** (`"aaa"`, 길이 1000짜리 `"a"` 반복): 모든 `(l, r)` 쌍이 팰린드롬이 되어, 결과가 `n(n+1)/2`(등차수열 합)와 일치한다 — 1000자일 때 `500500`으로 정확히 확인했다.
- **팰린드롬이 하나도 겹치지 않는 경우** (`"abc"`): 길이 1인 것들만 팰린드롬이라, 결과는 항상 `n`(문자열 길이).
- **양쪽 대칭이 중첩되는 경우** (`"racecar"`, `"abba"`): 안쪽 구간의 판정 결과(`dp[j+1][j+i-1]`)를 재사용하므로, 여러 겹으로 중첩된 팰린드롬도 정확히 카운트된다.
