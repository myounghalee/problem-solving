# [LeetCode 2487] Remove Nodes From Linked List — 단조 스택으로 "오른쪽에 더 큰 값"을 온라인으로 판정하기

- 문제 번호: 2487
- 링크: https://leetcode.com/problems/remove-nodes-from-linked-list/
- 난이도: Medium
- 태그: Linked List, Stack, Recursion, Monotonic Stack
- 사용 자료구조/알고리즘: **단조 감소 스택(Monotonic Decreasing Stack)**

## 1. 문제 요약

연결 리스트에서 **자기 오른쪽 어딘가에 자기보다 엄격히 큰 값을 가진 노드가 있는 노드**를 전부 제거하고, 남은 리스트의 `head`를 반환한다.

```text
예시) [5,2,13,3,8] → [13,8]
      5: 오른쪽에 13 있음 → 제거
      2: 오른쪽에 13 있음 → 제거
      13: 오른쪽(3,8)에 13보다 큰 값 없음 → 유지
      3: 오른쪽에 8 있음 → 제거
      8: 오른쪽에 아무것도 없음 → 유지
```

같은 값은 제거 사유가 아니다(`[1,1,1,1]`은 그대로 남는다). "오른쪽 어딘가"는 바로 다음 노드가 아니라 **뒤쪽 전체**를 뜻한다.

## 2. 접근 아이디어

### 왜 바로 다음 노드만 봐서는 안 되는가

인접한 두 노드만 비교하면 `[5,2,13,...]`에서 `5`가 `2`보다 크니 살아남는다고 착각하기 쉽다. 하지만 `5`의 오른쪽에는 `13`이 있으므로 `5`는 제거되어야 한다. **"오른쪽 전체 중 최댓값"과 비교**해야 하는 문제다.

가장 단순하게 풀면 각 노드마다 오른쪽 전체를 다시 훑어 `O(n^2)`이 된다. 노드가 최대 `10^5`개이므로 이 방식은 시간 초과다.

### 핵심 관찰 — 정답은 "오른쪽 끝에서부터의 누적 최댓값" 문제다

리스트를 오른쪽에서 왼쪽으로 훑는다고 생각해 보면, "지금까지(오른쪽으로) 본 값들의 최댓값"을 하나만 들고 있으면 된다. 지금 노드의 값이 그 최댓값보다 크거나 같으면 살아남고, 작으면 제거된다. 이건 **한 번의 순회로 `O(n)`에 풀린다.**

문제는 연결 리스트라 오른쪽에서 왼쪽으로 도는 게 자연스럽지 않다는 점이다(리스트를 뒤집거나, 배열에 옮기거나, 재귀를 쓰면 가능하다). 이 풀이는 **왼쪽에서 오른쪽으로 스캔하면서도 같은 효과를 내는** 방법을 쓴다.

### 왼쪽에서 오른쪽으로 스캔하며 단조 스택 유지하기

지금까지 "생존 후보"로 남은 노드들을 스택에 쌓아 둔다. 새 노드 `to`를 볼 때마다, **스택 맨 위(가장 최근에 넣은 노드)가 `to`보다 작으면 그 노드는 이제 확정적으로 제거 대상**이다 — `to`가 바로 그 노드의 "오른쪽에 있는 더 큰 값"이기 때문이다. 작은 노드를 꺼내는 걸 `to`보다 크거나 같은 노드가 나올 때까지(또는 스택이 빌 때까지) 반복한 뒤, `to`를 스택에 넣는다.

이 과정을 끝까지 반복하면 스택에는 **값이 오른쪽으로 갈수록 감소하지 않는 원소만 남지 않고, 정확히 "자기보다 오른쪽에 더 큰 값이 없는" 노드들만** 남는다. 스택 바닥부터 보면 값이 감소하지 않는(비내림차순이 아니라, 큰 값이 작은 값들을 이미 밀어냈으므로) 순서가 된다 — 그래서 "단조 스택"이라 부른다.

한 번 스택에서 빠진 노드는 그 이유(자신보다 큰 값이 오른쪽에 있다는 사실)가 이후에도 절대 바뀌지 않으므로, **미리 제거해도 안전**하다. 이게 오른쪽에서 왼쪽으로 도는 것과 결과가 같은 이유다 — 어떤 노드를 밀어낸 원소 자신이 나중에 또 밀려나더라도, 이미 확정된 "누군가에게 밀려났다"는 사실은 유효하다.

### 손으로 시뮬레이션 — `[5,2,13,3,8]`

| `to` | 스택에서 꺼내는 것 | 처리 | 스택 (아래→위) |
|---|---|---|---|
| 시작 | — | `5` 삽입 | `[5]` |
| `2` | 없음 (`5 >= 2`) | `2` 삽입 | `[5, 2]` |
| `13` | `2` 제거 (`2 < 13`), `5` 제거 (`5 < 13`) | `13` 삽입 | `[13]` |
| `3` | 없음 (`13 >= 3`) | `3` 삽입 | `[13, 3]` |
| `8` | `3` 제거 (`3 < 8`) | `8` 삽입 (`13 >= 8`) | `[13, 8]` |

최종 스택 `[13, 8]`이 답이다. `13`이 `2`와 `5`를 밀어낸 시점에서 그 둘의 운명은 확정되고, 이후 `3`이나 `8`이 무엇이든 다시 살아나지 않는다.

## 3. 코드 (Java)

```java
import java.util.*;

class ListNode {
    int val;
    ListNode next;
    ListNode() {}
    ListNode(int val) { this.val = val; }
    ListNode(int val, ListNode next) { this.val = val; this.next = next; }
}

class Solution {

    public ListNode removeNodes(ListNode head) {

        Deque<ListNode> d = new ArrayDeque<>(); // 스택으로 사용. 바닥→꼭대기가 값 감소 순서를 유지
        d.add(head);

        ListNode to = head.next;
        while (to != null) {
            while (!d.isEmpty()) {
                if (d.peekLast().val >= to.val) {
                    d.add(to); // to보다 작지 않은 노드를 만나면 to를 그 위에 쌓고 종료
                    break;
                }
                d.removeLast(); // 꼭대기가 to보다 작다 → to가 그 노드의 "오른쪽 더 큰 값"이므로 확정 제거
            }
            if (d.isEmpty()) d.add(to); // 전부 제거되어 스택이 비었으면 to 자신이 새 바닥
            to = to.next;
        }

        if (d.isEmpty()) return null;
        head = d.poll(); // 스택 바닥이 새 head (원래 순서를 그대로 유지)
        ListNode cur = head;
        while (!d.isEmpty()) {
            ListNode next = d.poll();
            cur.next = next;
            cur = next;
        }

        return head;
    }
}
```

### 코드 설명

- `Deque<ListNode>`를 스택처럼 쓴다. `d.add`/`d.removeLast`가 꼭대기에 넣고 빼는 연산이고, `d.poll`은 반대쪽(바닥, 먼저 넣은 쪽)부터 꺼낸다. `ArrayDeque`는 양 끝 모두 `O(1)`이라 이 두 용도에 그대로 맞는다.
- **내부 `while`이 진짜 반복이다.** `to` 하나가 들어올 때 스택에서 여러 노드가 한꺼번에 밀려날 수 있다(위 시뮬레이션의 `13` 차례에서 둘이 한 번에 제거됐다). `if`가 아니라 `while`이어야 하는 이유가 여기 있다.
- **비교가 `>=`인 이유**는 "엄격히 큰 값만 제거 사유"라는 문제 조건 때문이다. 스택 꼭대기가 `to`와 **같으면** 밀어내지 않고 그대로 둔 채 `to`를 그 위에 쌓는다. `[1,1,1,1]`이 하나도 제거되지 않는 이유가 이 부등호에 있다.
- **스택을 다시 리스트로 잇는 순서**가 중요하다. 스택에는 "먼저 들어온 것이 바닥, 나중에 들어온 것이 꼭대기"로 쌓여 있는데, 이는 원본 리스트의 순서와 그대로 일치한다(왼쪽에서 오른쪽으로 스캔하며 쌓았으므로). 그래서 바닥부터(`poll`) 순서대로 이으면 원래 순서가 보존된다.
- 노드 자체를 재사용해 `cur.next`만 다시 연결한다. 새 노드를 만들지 않는다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 겉보기엔 이중 `while`이지만, 각 노드는 스택에 **정확히 한 번** 들어가고 **최대 한 번** 나온다. 그래서 `removeLast` 호출의 총 횟수는 전체 실행을 통틀어 최대 `n`번이다. 스택을 다시 잇는 두 번째 `while`도 노드마다 한 번씩만 돈다. 합쳐서 `O(n)`.
- **공간복잡도**: `O(n)` — 최악의 경우(리스트가 오름차순, 예: `[1,3,5,7,9]`) 스택에 모든 노드가 한 번씩은 들어간다. 답 자체를 저장하는 공간이므로 이 이상 줄일 수 없다.

실측: 노드 10만 개(오름차순, 결과가 1개로 줄어드는 최악 형태)에서 1ms, 무작위 값 10만 개에서 3ms.

## 5. 엣지 케이스

- **노드 하나**: 오른쪽에 아무것도 없으므로 그대로 유지.
- **완전 내림차순** (`[9,7,5,3,1]`): 각 노드가 스택 꼭대기보다 작거나 같은 적이 없으므로 아무것도 제거되지 않고 전부 남는다.
- **완전 오름차순** (`[1,3,5,7,9]`): 새 노드가 들어올 때마다 스택이 통째로 비워지고 그 노드만 남는다. 최종적으로 마지막(최댓값) 노드 하나만 생존 — 스택이 가장 크게 요동치는 최악의 경우다.
- **모든 값이 같음** (`[1,1,1,1]`): `>=` 비교 덕분에 아무것도 밀려나지 않고 전부 유지된다.
- **최댓값이 맨 뒤에 있는 경우** (`[2,4,3,10]`): `10`이 들어오는 순간 스택에 남아있던 것들이 전부 쓸려나가고 `10`만 남는다.
- **전부 제거되어 스택이 비는 경우**: `head` 자신도 나중에 온 더 큰 값에 밀려날 수 있다. `d.isEmpty()`일 때 `head = null`을 반환하도록 처리되어 있다(다만 이 문제의 제약상 최댓값을 가진 노드는 항상 하나 이상 살아남으므로 결과가 완전히 빈 리스트가 되는 입력은 존재하지 않는다).

검증: 무작위 200,000건(값 범위를 좁혀 동점 케이스를 자주 만듦)을 "각 노드마다 오른쪽 전체를 훑는" 브루트포스와 교차 비교해 전부 일치했다.

## 6. 이런 방법도 있다 — 리스트를 뒤집어서 풀기

2절에서 말한 "오른쪽 끝에서부터의 누적 최댓값"을 **문자 그대로** 구현하는 방법이다. 리스트를 뒤집으면 "오른쪽에서 왼쪽으로"가 "왼쪽에서 오른쪽으로"가 되므로, 한 번의 순회로 최댓값을 갱신하며 남길 노드를 고르고, 다시 뒤집어 원래 순서로 되돌린다.

```java
class Solution {
    public ListNode removeNodes(ListNode head) {
        ListNode reversed = reverse(head);

        ListNode dummy = new ListNode();
        ListNode tail = dummy;
        int maxSoFar = 0;
        for (ListNode cur = reversed; cur != null; cur = cur.next) {
            if (cur.val >= maxSoFar) {       // 지금까지(원래 기준 오른쪽) 본 값 중 최댓값 이상이면 생존
                maxSoFar = cur.val;
                tail.next = cur;
                tail = cur;
            }
        }
        tail.next = null;                    // 끊어내지 않으면 마지막 노드가 이전 연결을 그대로 물고 있다

        return reverse(dummy.next);
    }

    private ListNode reverse(ListNode head) {
        ListNode prev = null;
        while (head != null) {
            ListNode next = head.next;
            head.next = prev;
            prev = head;
            head = next;
        }
        return prev;
    }
}
```

`tail.next = null;`을 빠뜨리면, 뒤집힌 리스트를 훑으며 재사용한 노드가 뒤집기 전의 `next`를 그대로 물고 있어 리스트가 이상한 곳으로 이어지거나 순환이 생길 수 있다.

**비교:**

| | 단조 스택 (위 3.의 코드) | 리스트 두 번 뒤집기 |
|---|---|---|
| 리스트 순회 횟수 | 1번(스캔) + 1번(재연결) | 뒤집기 2번 + 스캔 1번 = 3번 |
| 추가 자료구조 | `Deque` (최악 `O(n)` 공간) | 없음 — `int` 하나(`maxSoFar`)만 사용 |
| 원본 리스트 변형 | 없음(노드만 재배치) | 두 번 뒤집으므로 최종 순서는 같지만 중간에 전체가 뒤집힘 |
| 이해 난이도 | "단조 스택"이라는 패턴을 알아야 함 | "최댓값 하나만 추적"이라 직관적 |

둘 다 `O(n)` 시간이지만 공간에서 갈린다. 리스트 뒤집기 방식은 **`O(1)` 추가 공간**(연결 리스트 자체는 답을 담는 필수 공간이므로 제외)으로 끝나는 반면, 단조 스택 방식은 스택에 최악의 경우 노드 전부가 들어갈 수 있어 `O(n)` 추가 공간이 든다. 메모리가 빠듯한 환경이라면 뒤집기 방식이 유리하고, "단조 스택으로 다음/이전 더 큰 원소를 찾는다"는 패턴 자체를 연습하려면 3절 코드가 더 전형적이다.
