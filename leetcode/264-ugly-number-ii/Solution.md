# [LeetCode 264] Ugly Number II — 세 포인터로 어글리 넘버 수열을 직접 생성하는 DP

- 문제 번호: 264
- 링크: https://leetcode.com/problems/ugly-number-ii/
- 난이도: Medium
- 태그: Hash Table, Math, Dynamic Programming, Heap (Priority Queue)
- 사용 자료구조/알고리즘: **세 포인터(2, 3, 5) DP — 정렬된 수열을 이미 만든 결과에서 곱해서 생성**

## 1. 문제 요약

소인수가 `2`, `3`, `5`로만 이루어진 양의 정수를 "어글리 넘버(ugly number)"라 한다. 정수 `n`이 주어질 때 `n`번째 어글리 넘버를 반환한다. 처음 몇 개는 `[1, 2, 3, 4, 5, 6, 8, 9, 10, 12, ...]`이다(`7`은 소인수에 `7`이 있으므로 제외).

## 2. 접근 아이디어

모든 수를 하나씩 검사하며 소인수분해로 어글리 여부를 판정하면 느리다. 대신 **이미 만든 어글리 넘버들에 2, 3, 5를 곱하면 다음 어글리 넘버 후보가 나온다**는 성질을 이용해 수열을 직접 만들어 나간다.

- 지금까지 만든 어글리 넘버를 오름차순으로 `list`에 저장한다 (`list[0] = 1`부터 시작).
- 각 배수(2배, 3배, 5배) 계열마다 "다음에 곱할 원본이 `list`의 몇 번째 원소인지"를 가리키는 포인터 `i2, i3, i5`를 둔다.
- 매 단계에서 세 후보 `2*list[i2]`, `3*list[i3]`, `5*list[i5]` 중 **최솟값**이 다음 어글리 넘버다. 이 값을 `list`에 추가하고, 그 값을 만드는 데 쓰인 포인터(들)를 한 칸씩 전진시킨다.
  - 후보값이 같아서 여러 포인터가 동시에 그 최솟값을 만들었다면(예: `2*3 = 3*2 = 6`), **모두 전진**시켜야 중복 없이 다음 값을 만들 수 있다.
- 이렇게 `n`번째까지 반복하면 `list`의 마지막 원소가 답이다.

각 계열(`2*list[...]`, `3*list[...]`, `5*list[...]`)은 그 자체로 이미 정렬된 수열이므로, 이 문제는 **"정렬된 세 개의 수열을 병합하면서 매번 가장 작은 값을 꺼내는"** 다중 포인터(k-way merge) 패턴의 변형이다. 다만 세 수열이 미리 주어져 있는 게 아니라 `list` 자체에서 즉석으로 만들어진다는 점이 다르다.

### 손으로 시뮬레이션 — `n = 10`

`list = [1]`에서 시작해서 매 단계 후보를 계산한다.

| 단계 | i2, i3, i5 (곱할 원본) | 후보 (2배, 3배, 5배) | 최솟값 → list에 추가 | 전진하는 포인터 |
|---|---|---|---|---|
| 1 | 1, 1, 1 | 2, 3, 5 | **2** | i2 |
| 2 | 2, 1, 1 | 4, 3, 5 | **3** | i3 |
| 3 | 2, 2, 1 | 4, 6, 5 | **4** | i2 |
| 4 | 3, 2, 1 | 6, 6, 5 | **5** | i5 |
| 5 | 3, 2, 2 | 6, 6, 10 | **6** | i2, i3 (둘 다 6) |
| 6 | 4, 3, 2 | 8, 9, 10 | **8** | i2 |
| 7 | 5, 3, 2 | 10, 9, 10 | **9** | i3 |
| 8 | 5, 4, 2 | 10, 12, 10 | **10** | i2, i5 (둘 다 10) |
| 9 | 6, 4, 3 | 12, 12, 15 | **12** | i2, i3 |

`list = [1, 2, 3, 4, 5, 6, 8, 9, 10, 12]` — 10번째 원소는 `12`. 예상 출력과 일치한다.

5단계와 8단계처럼 후보값이 겹치는 경우(`6 = 2*3 = 3*2`, `10 = 2*5 = 5*2`) 관련된 포인터를 모두 전진시켜야, 다음 단계에서 `6`이나 `10`이 다시 후보로 나와 중복되는 것을 막을 수 있다.

## 3. 코드 (Java)

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public int nthUglyNumber(int n) {
        int x = 1, x2 = 0, x3 = 0, x5 = 0; // x: 이번 단계에서 새로 만든 어글리 넘버
        int i = 1, i2 = 0, i3 = 0, i5 = 0; // i2/i3/i5: list에서 각각 2, 3, 5를 곱할 다음 원소의 인덱스
        List<Integer> list = new ArrayList<>();
        list.add(1); // 첫 번째 어글리 넘버

        while (i <= n) {
            if (i == n) return x;

            x2 = 2 * list.get(i2);
            x3 = 3 * list.get(i3);
            x5 = 5 * list.get(i5);

            x = Math.min(x2, Math.min(x3, x5)); // 세 후보 중 최솟값이 다음 어글리 넘버
            list.add(x);

            if (x2 == x) i2++; // 이번 값을 만드는 데 쓰인 포인터는 모두 전진 (동시에 여러 개일 수 있음)
            if (x3 == x) i3++;
            if (x5 == x) i5++;
            i++;
        }

        return 1;
    }
}
```

### 코드 설명

- `list`는 지금까지 만든 어글리 넘버를 오름차순으로 담는다. 새 값은 항상 `list`의 마지막에 추가되므로 정렬 상태가 그대로 유지된다.
- `i2, i3, i5`는 "각 배수 계열에서 다음으로 곱할 원본이 `list`의 몇 번째인지"를 가리킨다. 예를 들어 `i2`가 가리키는 원소에 `2`를 곱한 값이 아직 `list`에 등장하지 않은, 2배 계열의 다음 후보다.
- `if (x2 == x) i2++;` 세 줄을 개별 `if`로 쓴 이유는, 여러 계열이 동시에 같은 값을 만들어낼 수 있기 때문이다(예: `6 = 2*3 = 3*2`). `else if`로 쓰면 한쪽 포인터만 전진해서 같은 값이 중복으로 다시 나오게 된다.
- `while (i <= n)` 안에서 `i == n`일 때 바로 반환하는 이유는, `i`번째 어글리 넘버를 만든 직후 `list`에 추가하기 전에 이미 `x`에 값이 들어 있는 상태이기 때문이다 — 매 반복의 시작에서 "이전 반복에서 막 계산한 `x`가 몇 번째 값인지"를 `i`로 확인하는 구조다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 반복문이 `n`번 돌고, 매 반복마다 상수 시간(`list.get`, 비교, 포인터 증가)만 수행한다.
- **공간복잡도**: `O(n)` — 어글리 넘버 `n`개를 모두 `list`에 저장한다.

## 5. 엣지 케이스

- **`n = 1`**: `list = [1]`로 시작한 상태에서 `i = 1 == n`이 바로 성립해 루프 첫 반복에서 `x = 1`을 반환한다.
- **후보값이 겹치는 경우** (`6`, `10`, `12`, ...): 관련된 모든 포인터를 전진시키지 않으면 같은 값이 중복 생성된다 — 위 3절에서 `if`를 세 개 모두 개별로 검사하는 이유.
- **`n`이 제약의 최댓값(`1690`)에 가까운 경우**: `O(n)`으로 동작하므로 성능 문제는 없다.

## 6. 관련 문제

정렬된 여러 수열(계열)을 매 단계 최솟값 기준으로 병합해 나가는 다중 포인터(k-way merge) 계열.

- [Merge k Sorted Lists (LeetCode 23)](../23-merge-k-sorted-lists/Solution.md) — 이미 정렬된 `k`개의 연결 리스트를 힙/분할정복으로 병합한다는 점에서 "여러 정렬된 흐름 중 최솟값을 꺼내 하나로 합친다"는 아이디어가 같지만, 이 문제는 병합할 수열이 미리 주어지지 않고 `2, 3, 5`를 곱해 그때그때 만들어진다는 점이 다르다.
