# [LeetCode 198] House Robber — "턴다/안 턴다"를 이전 두 상태로 압축하는 선형 DP

- 문제 번호: 198
- 링크: https://leetcode.com/problems/house-robber/
- 난이도: Medium
- 태그: Array, Dynamic Programming
- 사용 자료구조/알고리즘: **1차원 다이나믹 프로그래밍**

## 1. 문제 요약

한 줄로 늘어선 집 `nums[i]`에서, **바로 이웃한 두 집을 연달아 털 수 없다**는 조건 아래 훔칠 수 있는 최댓값을 구한다.

```text
예시) [1,2,3,1] → 4   (0번 집 1 + 2번 집 3)
      [2,7,9,3,1] → 12  (0번 집 2 + 2번 집 9 + 4번 집 1)
```

## 2. 접근 아이디어

### 각 집에서의 선택은 두 가지뿐이다

`i`번째 집 앞에 서면 선택지는 "턴다" 또는 "안 턴다" 둘뿐이다.

- **턴다**: `nums[i]`를 받는 대신, 바로 전 집(`i-1`)은 반드시 포기해야 한다. 그러니 `i-2`까지의 최댓값에 `nums[i]`를 더한 것이 이 선택의 값이다.
- **안 턴다**: `i-1`까지의 최댓값을 그대로 이어받는다.

이 두 값 중 큰 쪽이 `i`번째 집까지 왔을 때의 정답이다. `dp[i]`를 "0번째부터 `i`번째 집까지만 있다고 할 때 얻을 수 있는 최댓값"으로 정의하면:

```text
dp[i] = max(dp[i-1], dp[i-2] + nums[i])
```

**같은 부분 문제가 반복된다는 것**이 이 점화식이 성립하는 이유다. `i`번째 집의 답을 구하는 데 필요한 건 "`i-1`까지의 답"과 "`i-2`까지의 답" 두 개뿐이고, 이 둘은 각각 그 이전 집들의 최선의 선택이 무엇이었는지를 이미 압축해서 담고 있다. `i`번째에서 다시 그 이전 집들의 조합을 하나하나 따질 필요가 없다.

### 손으로 시뮬레이션 — `[2, 7, 9, 3, 1]`

| `i` | `nums[i]` | `dp[i-2] + nums[i]` | `dp[i-1]` | `dp[i]` = 큰 쪽 |
|---|---|---|---|---|
| 0 | 2 | — | — | `dp[0] = 2` |
| 1 | 7 | — | — | `dp[1] = max(2,7) = 7` |
| 2 | 9 | `dp[0]+9 = 11` | `dp[1] = 7` | `dp[2] = 11` |
| 3 | 3 | `dp[1]+3 = 10` | `dp[2] = 11` | `dp[3] = 11` |
| 4 | 1 | `dp[2]+1 = 12` | `dp[3] = 11` | `dp[4] = 12` |

`i=3`에서는 "3번 집을 터는 것"(`10`)보다 "안 터는 것"(`11`)이 낫다. 대신 `i=4`에서는 다시 "터는 것"(`12`)이 이긴다 — 매 단계마다 독립적으로 두 선택을 비교하기 때문에, "턴 집들이 연속으로 몇 번 이어지는가" 같은 패턴을 따로 추적할 필요 없이 자연스럽게 최적의 조합(`0,2,4`번 집)이 나온다.

## 3. 코드 (Java)

```java
class Solution {
    public int rob(int[] nums) {

        int[] dp = new int[nums.length]; // dp[i] = 0~i번째 집만 있을 때의 최댓값
        dp[0] = nums[0];
        if (nums.length == 1) return nums[0];

        dp[1] = Math.max(nums[0], nums[1]); // 집이 둘뿐이면 더 큰 쪽 하나만
        for (int i = 2; i < nums.length; i++) {
            dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i]);
        }

        return dp[nums.length - 1];
    }
}
```

### 코드 설명

- `dp[0]`과 `dp[1]`을 별도로 초기화하는 이유는 점화식이 `dp[i-2]`를 참조하는데 `i=0`이나 `i=1`에서는 그 인덱스가 존재하지 않기 때문이다. `dp[0] = nums[0]`(집이 하나면 그냥 그 집을 턴다), `dp[1] = max(nums[0], nums[1])`(집이 둘이면 둘 다는 못 터니 큰 쪽 하나만)로 경계를 직접 채운다.
- `if (nums.length == 1) return nums[0];`가 `dp[1]` 계산보다 먼저 있어야 한다. 집이 하나뿐인데 `dp[1] = Math.max(nums[0], nums[1])`을 실행하면 `nums[1]`에서 `ArrayIndexOutOfBoundsException`이 난다.
- 반복문은 `i=2`부터 시작해 이미 채워둔 `dp[0]`, `dp[1]`을 그대로 재사용한다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 한 번만 훑는다.
- **공간복잡도**: `O(n)` — `dp` 배열 전체를 저장한다. 다만 각 단계에서 실제로 참조하는 건 바로 이전 두 값(`dp[i-1]`, `dp[i-2]`)뿐이므로, 변수 두 개로 `O(1)`까지 줄일 수 있다(6절).

실측: 제약 상한 `n=100`에서 2μs.

## 5. 엣지 케이스

- **집이 하나**: 그 집을 턴다.
- **집이 둘**: 이웃이라 동시에 못 턴다. 둘 중 큰 값 하나만 가져간다(`[2,1] → 2`).
- **앞뒤 집이 크고 중간이 작은 경우** (`[100,1,1,100]`): 직관적으로는 앞의 두 집(`100+1=101`)을 고를 것 같지만, 인접하지 않은 조합 중 최댓값은 양 끝(`100+100=200`)이다. "이웃하지 않게 고른다"는 조건이 그리디한 직관과 어긋날 수 있다는 걸 보여주는 사례다.
- **모든 값이 0**: 뭘 털어도 이득이 없으니 `0`.

검증: 무작위 25,000건(작은 크기 2만 건 + `n≤50` 5천 건)을 재귀 브루트포스(메모이제이션 포함)와 교차 비교해 전부 일치했다.

## 6. 이런 방법도 있다 — 배열 없이 변수 두 개로

3절의 `dp` 배열은 매 단계 `dp[i-1]`과 `dp[i-2]`만 참조하고, 그보다 이전 값은 다시 쓰이지 않는다. 그렇다면 배열 전체를 들고 있을 이유가 없다 — 딱 두 칸만 기억하면 충분하다.

```java
class Solution {
    public int rob(int[] nums) {
        int prev2 = 0, prev1 = 0; // prev2 = dp[i-2], prev1 = dp[i-1] (아직 집이 없을 때는 0)
        for (int num : nums) {
            int cur = Math.max(prev1, prev2 + num);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}
```

`prev2`, `prev1`을 "집이 하나도 없을 때의 최댓값 = 0"으로 시작하면, 3절에서 `dp[0]`/`dp[1]`을 따로 채워야 했던 경계 처리가 필요 없어진다. 첫 반복(`num = nums[0]`)에서 `cur = max(0, 0+nums[0]) = nums[0]`이 자연스럽게 나오기 때문이다.

**비교:**

| | 배열 DP (3절) | 변수 두 개 (6절) |
|---|---|---|
| 공간복잡도 | `O(n)` | `O(1)` |
| 경계 처리 | `dp[0]`, `dp[1]`을 직접 채워야 함 | `prev2=prev1=0`으로 통일 |
| `nums.length==1` 가드 | 필요 | 불필요 (루프가 자연스럽게 처리) |

이 문제는 `n ≤ 100`이라 실측 차이는 없지만, "매 단계에서 정말 필요한 과거 상태가 몇 개인가"를 따져 배열을 변수로 줄이는 건 선형 DP에서 흔한 최적화다. 다만 `dp[i]` 자체를 나중에 다시 조회해야 하는 문제(예: 경로를 역추적해야 하는 경우)라면 배열을 그대로 남겨야 한다.

## 7. 관련 문제

이 저장소에서 **"이전 몇 개의 상태만 참조하는" 선형 DP**의 첫 문제다. 기존에 푼 DP 문제들과는 결이 다르다 — [Longest Palindromic Subsequence (LeetCode 516)](../516-longest-palindromic-subsequence/Solution.md)·[Palindromic Substrings (LeetCode 647)](../647-palindromic-substrings/Solution.md)은 구간 `[i,j]`를 상태로 삼는 2차원 구간 DP이고, [Ugly Number II (LeetCode 264)](../264-ugly-number-ii/Solution.md)는 힙으로 다음 값을 생성하는 방식이라 이 문제의 "직전 상태 재사용" 패턴과는 다르다.

- [Coin Change (LeetCode 322)](../322-coin-change/Solution.md) — 같은 1차원 DP지만 전이의 폭이 다르다. 이 문제는 직전 두 상태(`dp[i-1]`,`dp[i-2]`)만 보는 고정된 전이인 반면, 322번은 `dp[amount]`가 동전 종류 수만큼의 후보 중 최선을 고르는 더 넓은 전이다.
- [Triangle (LeetCode 120)](../120-triangle/Solution.md) — 상태가 1차원이 아니라 "줄 번호 + 칸 번호" 2차원인 DP. 후보가 항상 정확히 둘(왼쪽 아래/오른쪽 아래)뿐이라는 점은 이 문제들보다 단순하지만, 차원이 하나 늘어난다는 차이가 있다.
