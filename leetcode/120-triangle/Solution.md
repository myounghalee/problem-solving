# [LeetCode 120] Triangle — 아래에서 위로 채우는 2차원 DP

- 문제 번호: 120
- 링크: https://leetcode.com/problems/triangle/
- 난이도: Medium
- 태그: Array, Dynamic Programming
- 사용 자료구조/알고리즘: **2차원 다이나믹 프로그래밍**

## 1. 문제 요약

삼각형으로 배열된 숫자에서, 맨 위부터 맨 아래까지 **한 줄 아래로 내려갈 때마다 바로 아래(같은 인덱스) 또는 오른쪽 아래(인덱스+1) 중 하나로만** 이동하며 지나간 값의 합이 최소가 되는 경로를 찾는다.

```text
     2
    3 4
   6 5 7
  4 1 8 3
```

`2→3→5→1`(합 `11`)이 최소 경로다.

## 2. 접근 아이디어

### 왜 그리디(매번 더 작은 값으로)가 안 통하는가

"내려갈 때마다 두 후보 중 더 작은 값을 고르면 되지 않을까"라는 직관이 먼저 떠오르지만, 이건 틀린다. 반례는 이렇다.

```text
     0
    1 2
100 100 -100
```

- **그리디**: `0 → 1`(`1 < 2`라서 왼쪽) `→ 100` = `101`
- **최적**: `0 → 2`(당장은 `1`보다 손해) `→ -100` = `-98`

당장 눈앞의 이득만 보고 `1`을 고르면, 그 아래 두 값(`100, 100`)이 전부 크다는 걸 알 도리가 없다. 반대로 `2`를 고르면 손해처럼 보여도 그 아래에 `-100`이라는 훨씬 좋은 값이 기다리고 있다. **미래에 무엇이 있는지 모르고 당장의 선택만 보는 그리디는, 뒤에 숨어 있는 정보를 놓친다.** 그래서 모든 경로를 체계적으로 고려하는 DP가 필요하다.

### 상태 정의와 점화식

`dp[i][j]`를 **"맨 위에서 출발해 `i`번째 줄의 `j`번째 칸까지 왔을 때의 최소 합"**으로 정의한다.

`(i, j)` 칸에는 바로 위 줄에서 `(i-1, j-1)` 또는 `(i-1, j)`를 거쳐서만 올 수 있다(삼각형의 인덱싱 규칙 — `i`번째 줄의 `j`번째 칸은 `i-1`번째 줄의 `j-1`번째와 `j`번째 칸 양쪽에서 도달 가능하다). 그래서:

```text
dp[i][j] = min(dp[i-1][j-1], dp[i-1][j]) + triangle[i][j]
```

단, 줄의 **양 끝**은 한쪽에서만 올 수 있어서 예외로 처리해야 한다.

- `j == 0`(줄의 맨 왼쪽): `(i-1, -1)` 같은 칸은 없으므로 `dp[i-1][0]`에서만 온다.
- `j == i`(줄의 맨 오른쪽, 그 줄의 마지막 칸): `(i-1, i)` 같은 칸은 없으므로 `dp[i-1][i-1]`에서만 온다.
- `i == 0`(첫 줄): 위가 없으므로 `dp[0][0] = triangle[0][0]`.

### 손으로 시뮬레이션 — `[[2],[3,4],[6,5,7],[4,1,8,3]]`

| 줄 | `dp` 값 |
|---|---|
| 0 | `[2]` |
| 1 | `[2+3, 2+4] = [5, 6]` |
| 2 | `[5+6, min(5,6)+5, 6+7] = [11, 10, 13]` |
| 3 | `[11+4, min(11,10)+1, min(10,13)+8, 13+3] = [15, 11, 18, 16]` |

마지막 줄의 최솟값은 `11` — 정답과 일치한다. `dp[3][1]=11`이 `2→3→5→1`(위 예시의 최적 경로)에 해당한다.

## 3. 코드 (Java)

```java
import java.util.List;

class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {

        int[][] dp = new int[triangle.size()][triangle.getLast().size()];

        for (int i = 0; i < triangle.size(); i++) {
            for (int j = 0; j < triangle.get(i).size(); j++) {
                int value = triangle.get(i).get(j);
                if (i == 0) {
                    dp[i][j] = value;
                } else if (j == 0) {
                    dp[i][j] = dp[i - 1][j] + value;
                } else if (j == triangle.get(i).size() - 1) {
                    dp[i][j] = dp[i - 1][j - 1] + value;
                } else {
                    dp[i][j] = Math.min(dp[i - 1][j - 1], dp[i - 1][j]) + value;
                }
            }
        }

        int min = Integer.MAX_VALUE;
        for (int i : dp[dp.length - 1]) {
            min = Math.min(min, i);
        }
        return min;
    }
}
```

### 코드 설명

- `dp` 배열의 열 크기를 `triangle.getLast().size()`(마지막 줄의 길이, 곧 이 삼각형에서 가장 긴 줄)로 잡아, 어느 줄이든 `dp[i][j]`에 그대로 대응시킨다. 삼각형이 왼쪽 정렬이라 `j` 인덱스가 각 줄의 실제 인덱스와 그대로 일치한다.
- `i == 0`, `j == 0`, `j == 마지막`을 순서대로 검사한다. `i == 0`이면서 동시에 `j == 0`인 경우(맨 위 꼭짓점)는 첫 번째 분기에서 이미 처리되어 이후 분기와 겹치지 않는다.
- 마지막 줄(`dp[dp.length-1]`)을 전부 훑어 최솟값을 찾는다. 어느 칸에서 끝나든 상관없으므로, "맨 아래 줄의 어떤 칸이든 도착점이 될 수 있다"는 이 문제의 조건이 여기서 반영된다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n²)` — `n`은 삼각형의 줄 수. 칸의 총개수가 `1+2+...+n = O(n²)`이고 각 칸은 상수 시간에 계산된다.
- **공간복잡도**: `O(n²)` — `dp` 배열이 `n × n` 크기다. Follow-up이 요구하는 `O(n)`보다 크다(6절 참고).

실측: 제약 상한 `n=200`에서 2ms.

## 5. 엣지 케이스

- **줄이 하나뿐**: 그 값 자체가 답 (`[[-10]] → -10`).
- **줄이 둘뿐**: 두 후보 중 작은 쪽 (`[[-1],[2,3]] → -1+2 = 1`).
- **음수가 큰 값 뒤에 숨어 있는 경우** (`[[0],[1,2],[100,100,-100]]`): 2절에서 다룬 그리디 반례. 당장 손해인 선택이 최적일 수 있다.
- **모든 값이 음수**: 부호와 무관하게 알고리즘은 동일하게 동작한다(`Math.min`은 부호를 가리지 않는다).

검증: 무작위 5,000건(줄 수 최대 12, 값 범위 -100~100)을 메모이제이션 브루트포스와 교차 비교해 전부 일치했다.

## 6. Follow-up — `O(n)` 공간으로 줄이기: 아래에서 위로

이 문제는 `O(n)`(삼각형 전체 크기가 아니라 **줄 수**만큼의) 추가 공간으로도 풀 수 있냐고 명시적으로 묻는다. 3절의 `dp[i][j]`는 사실 **바로 이전 줄만** 참조한다 — 두 줄 이상 떨어진 값은 다시 쓰이지 않는다. 그렇다면 2차원 배열 전체를 들고 있을 이유가 없다.

핵심은 **방향을 뒤집는 것**이다. 위에서 아래로 채우면 양 끝에서 예외 처리가 필요했지만(2절), **아래에서 위로 채우면 그 예외가 전부 사라진다** — 맨 아래 줄을 제외한 모든 칸은 항상 "바로 아래 줄의 인접한 두 칸"을 가지기 때문이다.

`dp[j]`를 **"현재 처리 중인 줄의 `j`번째 칸에서 맨 아래까지 내려가는 최소 합"**으로 재정의한다.

```java
class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();
        int[] dp = new int[n + 1]; // 맨 아래 줄보다 한 칸 더 — 초기값 0이 "이 아래로는 더할 게 없다"는 뜻
        for (int i = n - 1; i >= 0; i--) {
            for (int j = 0; j <= i; j++) {
                dp[j] = Math.min(dp[j], dp[j + 1]) + triangle.get(i).get(j);
            }
        }
        return dp[0];
    }
}
```

맨 아래 줄(`i = n-1`)부터 시작해서, `dp[j]`(바로 아래 줄의 같은 인덱스, 아직 갱신 전이라 "한 줄 아래" 값)와 `dp[j+1]`(바로 아래 줄의 다음 인덱스) 중 작은 쪽에 현재 칸의 값을 더해 **제자리에서 덮어쓴다.** `i`가 한 줄씩 올라갈 때마다 `dp[0..i]`가 "그 줄에서 맨 아래까지의 최소 합"으로 갱신되고, 마지막에 `dp[0]`이 곧 전체 답이다.

**같은 배열을 왼쪽에서 오른쪽으로 덮어써도 되는 이유**: `dp[j]`를 갱신할 때 필요한 `dp[j]`와 `dp[j+1]`은 **모두 한 줄 아래(아직 이번 순회에서 안 건드린) 값**이다. `j`를 작은 값부터 순서대로 갱신해도, `dp[j+1]`은 이번 줄 갱신에서 아직 손대지 않은 "이전 줄의 값"이 맞다(왜냐하면 `j+1 > j`라서 아직 그 칸의 차례가 안 왔다). 그래서 별도의 임시 배열 없이 안전하게 제자리 갱신이 된다.

**비교:**

| | 위→아래, 2차원 (3절) | 아래→위, 1차원 (6절) |
|---|---|---|
| 공간복잡도 | `O(n²)` | `O(n)` |
| 경계 처리 | `j==0`, `j==마지막` 예외 필요 | 불필요 (모든 칸이 항상 아래 두 칸을 가짐) |
| 코드 길이 | 분기 4개 | 분기 없음, 한 줄 |

경계 처리가 사라지는 게 우연이 아니다. 삼각형을 아래에서 위로 보면, "이 줄의 각 칸은 항상 다음 줄의 인접한 두 칸을 갖는다"는 게 **예외 없이 성립**한다. 반대로 위에서 아래로 보면 "이 줄의 각 칸이 이전 줄의 두 칸을 갖는다"는 게 양 끝에서 깨진다. 같은 문제라도 어느 방향에서 보느냐에 따라 예외의 유무가 갈린다는 걸 보여주는 사례다.

## 7. 관련 문제

같은 DP 계열이지만 상태의 모양이 다르다.

- [House Robber (LeetCode 198)](../198-house-robber/Solution.md) — `dp[i]`가 직전 두 상태만 참조하는 1차원 DP. 이 문제는 상태가 "줄 번호 + 칸 번호" 두 축을 가지는 2차원이라는 점이 다르다.
- [Coin Change (LeetCode 322)](../322-coin-change/Solution.md) — `dp[amount]`가 "동전 종류 수만큼의 후보" 중 최선을 고르는 1차원 DP. 이 문제는 후보가 항상 정확히 둘(왼쪽 아래/오른쪽 아래)뿐이라는 점에서 더 단순하지만, 상태 자체가 2차원이라는 점이 다르다.

이 저장소에서 **격자/경로 위를 이동하는 2차원 DP**의 첫 문제이기도 하다.
