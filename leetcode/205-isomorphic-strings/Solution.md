# [LeetCode 205] Isomorphic Strings — 양방향 매핑으로 일대일 대응 확인하기

- 문제 번호: 205
- 링크: https://leetcode.com/problems/isomorphic-strings/
- 난이도: Easy
- 태그: Hash Table, String
- 사용 자료구조/알고리즘: **해시맵 두 개(양방향 매핑)**

## 1. 문제 요약

두 문자열 `s`, `t`가 주어질 때, `s`의 각 문자를 규칙에 따라 치환해서 `t`를 만들 수 있으면 "동형(isomorphic)"이라고 한다. 이때 치환은 **일대일 대응**이어야 한다 — 같은 문자는 항상 같은 문자로 바뀌어야 하고, 서로 다른 문자가 같은 문자로 합쳐지면 안 된다.

```text
예시) s = "egg", t = "add" → true   (e→a, g→d)
      s = "foo", t = "bar" → false  (o가 a와 r 두 곳으로 갈라짐)
      s = "paper", t = "title" → true (p→t, a→i, e→l, r→e)
```

## 2. 접근 아이디어

처음엔 "`s→t` 매핑 하나 + 이미 등장한 문자 집합 두 개(Set)"로 풀었는데, 새로운 문자를 볼 때마다 Set 두 개를 서로 비교하는 조건식이 장황하고 읽기 어려웠다. 더 깔끔한 방법은 **매핑을 양방향으로 각각 하나씩** 두는 것이다.

- `mapST`: `s`의 문자 → `t`의 문자 (정방향 매핑)
- `mapTS`: `t`의 문자 → `s`의 문자 (역방향 매핑)

일대일 대응이 되려면 두 조건이 동시에 성립해야 한다.

1. **정방향 일관성**: 같은 `s` 문자는 항상 같은 `t` 문자에 대응해야 한다 → `mapST`로 확인.
2. **역방향 일관성**: 같은 `t` 문자는 항상 같은 `s` 문자에서 왔어야 한다(서로 다른 `s` 문자가 같은 `t` 문자로 합쳐지면 안 됨) → `mapTS`로 확인.

두 매핑을 각각 검사하면 "Set에 들어있는지 아닌지"를 따지는 분기 없이도, 매핑이 이미 있는데 값이 다르면 바로 실패로 처리할 수 있어 로직이 단순해진다.

문자열을 한 번만 순회하면서, 각 위치 `i`에서 `s.charAt(i)`(`c1`), `t.charAt(i)`(`c2`)에 대해:

- `mapST`에 `c1`이 이미 있는데 그 값이 `c2`가 아니면 → 정방향 일관성 위반, `false`.
- `mapTS`에 `c2`가 이미 있는데 그 값이 `c1`이 아니면 → 역방향 일관성 위반, `false`.
- 두 검사를 통과하면 `mapST.put(c1, c2)`, `mapTS.put(c2, c1)`로 매핑을 (다시) 기록한다. 이미 같은 값으로 매핑돼 있던 경우엔 같은 값을 덮어쓸 뿐이라 문제 없다.

### 손으로 시뮬레이션 — `s = "paper"`, `t = "title"`

| i | c1 (s) | c2 (t) | mapST[c1] 확인 | mapTS[c2] 확인 | 통과 후 매핑 |
|---|---|---|---|---|---|
| 0 | p | t | 없음 | 없음 | mapST{p→t}, mapTS{t→p} |
| 1 | a | i | 없음 | 없음 | mapST{p→t,a→i}, mapTS{t→p,i→a} |
| 2 | p | t | 있음, `t`와 일치 | 있음, `p`와 일치 | 변화 없음(덮어쓰기만) |
| 3 | e | l | 없음 | 없음 | mapST{...,e→l}, mapTS{...,l→e} |
| 4 | r | e | 없음 | 없음 | mapST{...,r→e}, mapTS{...,e→r} |

끝까지 두 조건 중 하나도 위반되지 않았으므로 `true` — 정답과 일치한다.

### 위반이 걸리는 경우 — `s = "foo"`, `t = "bar"`

| i | c1 (s) | c2 (t) | mapST[c1] 확인 | mapTS[c2] 확인 | 결과 |
|---|---|---|---|---|---|
| 0 | f | b | 없음 | 없음 | 통과, mapST{f→b}, mapTS{b→f} |
| 1 | o | a | 없음 | 없음 | 통과, mapST{f→b,o→a}, mapTS{b→f,a→o} |
| 2 | o | r | 있음, 값 `a` ≠ `r` | - | **여기서 `false`로 중단** |

`o`가 이미 `a`로 매핑돼 있는데 이번엔 `r`로 매핑하려 하니 정방향 일관성이 깨진다.

## 3. 코드 (Java)

```java
class Solution {
    public boolean isIsomorphic(String s, String t) {
        Map<Character, Character> mapST = new HashMap<>(); // s의 문자 -> t의 문자
        Map<Character, Character> mapTS = new HashMap<>(); // t의 문자 -> s의 문자
        for (int i = 0; i < s.length(); i++) {
            char c1 = s.charAt(i);
            char c2 = t.charAt(i);
            if (mapST.containsKey(c1) && mapST.get(c1) != c2) return false; // 정방향 불일치
            if (mapTS.containsKey(c2) && mapTS.get(c2) != c1) return false; // 역방향 불일치
            mapST.put(c1, c2);
            mapTS.put(c2, c1);
        }
        return true;
    }
}
```

### 코드 설명

- `mapST`, `mapTS`는 각각 "지금까지 관찰된 대응 관계"를 담는다. 두 맵은 항상 서로의 역함수 관계를 유지하도록 함께 갱신된다.
- 두 `if`문은 각각 정방향/역방향 일관성만 검사하면 되므로, Set을 따로 두고 "포함 여부가 서로 다른가"를 비교하던 이전 방식보다 조건이 단순하다.
- 이미 올바르게 매핑된 문자를 다시 만나도 `mapST.put`/`mapTS.put`은 같은 값을 덮어쓸 뿐이라 안전하다 — 굳이 "새로 등장한 문자인지" 분기할 필요가 없다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — `n = s.length()`. 문자열을 한 번만 순회하며 각 위치에서 `O(1)` 해시맵 연산만 수행한다.
- **공간복잡도**: `O(k)` — `k`는 `s`(또는 `t`)에 등장하는 서로 다른 문자 종류 수. 문제에서 ASCII 문자를 다루므로 최악의 경우에도 `O(1)`에 가깝다(최대 256종).

## 5. 엣지 케이스

- **`s`와 `t`의 길이가 다른 경우**: 문제 제약상 `t.length() == s.length()`가 항상 보장되므로 별도로 검사하지 않아도 된다.
- **문자열 길이 1**: 루프가 한 번만 돌고, 매핑이 없던 상태에서 바로 등록되므로 항상 `true`.
- **모든 문자가 같은 경우**(`"aaa"`, `"bbb"`): 매번 같은 `c1→c2`를 확인/덮어쓰기만 하므로 `true`.
- **다대일 매핑**(`s = "badc"`, `t = "baba"`): `d`를 `b`로 매핑하려 할 때 `mapTS`에 이미 `b→b`가 있어 `d`와 충돌 → `false`로 정확히 걸러진다.
