# [LeetCode 55] Jump Game — 도달 가능한 가장 먼 지점만 추적하기

- 문제 번호: 55
- 링크: https://leetcode.com/problems/jump-game/
- 난이도: Medium
- 태그: Array, Dynamic Programming, Greedy
- 사용 자료구조/알고리즘: **한 번의 순회(단일 패스) + 그리디**

## 1. 문제 요약

인덱스 `0`에서 출발해서, 각 인덱스 `i`에서 최대 `nums[i]`칸까지 앞으로 이동할 수 있을 때, 마지막 인덱스(`nums.length - 1`)에 도달할 수 있는지 판별한다.

```text
예시) nums = [2,3,1,1,4]   → true   (0 → 1 → 4 경로로 도달 가능)
      nums = [3,2,1,0,4]   → false  (인덱스 3에서 값이 0이라 더 못 나아감)
```

> 처음엔 각 인덱스에서 도달 가능한 모든 인덱스를 큐에 넣어 탐색하는 BFS로 풀었는데, 인덱스 하나를 방문할 때마다 `nums[i]`개의 이웃을 전부 순회하다 보니, 이웃 확인 횟수의 총합이 `nums[i]` 값들의 합만큼 커져서(최악의 경우 `10^4 * 10^5` 수준) 너무 느렸다. 아래는 도달 가능한 인덱스를 하나하나 추적하지 않고 "가장 멀리 갈 수 있는 지점"만 기억하는 `O(n)` 풀이다.

## 2. 접근 아이디어

어느 경로로 마지막 인덱스에 도달하는지는 중요하지 않고, **도달 가능한지 여부만** 알면 된다. 그래서 각 인덱스마다 도달 가능한 모든 위치를 따로 추적할 필요 없이, 지금까지 확인한 범위 안에서 **가장 멀리까지 갈 수 있는 지점(`index`)** 하나만 계속 갱신하면 충분하다.

배열을 앞에서부터 한 번 순회하면서, 각 인덱스 `i`에서

1. **지금 `i`에 도달할 수 있는가?**: 지금까지 갱신해온 최대 도달 지점(`index`)이 `i`보다 작다면, 애초에 `i`까지 올 방법이 없었다는 뜻이다. 이 시점에서 더 진행해봤자 의미가 없으므로 바로 `false`를 반환한다.
2. **`i`에서 갈 수 있는 가장 먼 지점으로 갱신**: `i + nums[i]`(오늘 위치에서 최대로 뛴 지점)와 지금까지의 `index` 중 더 큰 값으로 `index`를 갱신한다.
3. **목표에 이미 도달했는가?**: `index`가 마지막 인덱스 이상이 되면, 더 순회할 필요 없이 바로 `true`를 반환한다.

이렇게 하면 각 인덱스를 정확히 한 번씩만 확인하므로, 개별 이웃을 일일이 나열하던 BFS보다 훨씬 빠르다.

### 손으로 시뮬레이션 — `nums = [2,3,1,1,4]`

`len = 5`, 시작 `index = 0`

| i | index < i ? | index = max(i+nums[i], index) | index >= len-1(4) ? |
|---|---|---|---|
| 0 | 0 < 0 → 아니오 | max(0+2, 0) = 2 | 2 >= 4 → 아니오 |
| 1 | 2 < 1 → 아니오 | max(1+3, 2) = 4 | 4 >= 4 → **예, `true` 반환** |

인덱스 `1`까지만 확인하고도 `index`가 이미 마지막 인덱스에 도달해서 `true`로 끝난다 — 정답과 일치한다.

### 갇히는 경우 — `nums = [3,2,1,0,4]`

`len = 5`, 시작 `index = 0`

| i | index < i ? | index = max(i+nums[i], index) | index >= len-1(4) ? |
|---|---|---|---|
| 0 | 0 < 0 → 아니오 | max(0+3, 0) = 3 | 3 >= 4 → 아니오 |
| 1 | 3 < 1 → 아니오 | max(1+2, 3) = 3 | 3 >= 4 → 아니오 |
| 2 | 3 < 2 → 아니오 | max(2+1, 3) = 3 | 3 >= 4 → 아니오 |
| 3 | 3 < 3 → 아니오 | max(3+0, 3) = 3 | 3 >= 4 → 아니오 |
| 4 | **3 < 4 → 예, `false` 반환** | - | - |

인덱스 `3`(값 0)까지 도달한 뒤로는 `index`가 더 이상 늘지 않아, 인덱스 `4`를 확인하는 순간 `index(3) < i(4)`가 성립해 `false`로 끝난다.

## 3. 코드 (Java)

```java
class Solution {
    public boolean canJump(int[] nums) {
        int len = nums.length;
        int index = 0; // 지금까지 도달 가능한 가장 먼 인덱스
        for (int i = 0; i < len; i++) {
            if (index < i) return false;              // i까지 올 방법이 없었음
            index = Math.max(i + nums[i], index);      // i에서 갈 수 있는 가장 먼 지점으로 갱신
            if (index >= len - 1) return true;         // 이미 마지막 인덱스 도달 가능
        }
        return false;
    }
}
```

### 코드 설명

- `index`는 "지금까지 확인한 인덱스들 중 어느 하나에서든 도달할 수 있는 가장 먼 위치"를 의미한다. 매 반복마다 갱신만 될 뿐 절대 줄어들지 않는다.
- `if (index < i) return false;`는 순회 중인 `i`에 애초에 도달할 수 없었다는 뜻이므로, 그 뒤를 더 볼 필요 없이 바로 실패로 처리한다. 이 검사를 `index` 갱신보다 먼저 해야, 도달 불가능한 인덱스의 `nums[i]` 값을 엉뚱하게 반영하는 일을 막을 수 있다.
- `index >= len - 1`이 되는 순간 바로 반환하는 것은 필수는 아니지만(끝까지 순회해도 결과는 같다), 불필요한 반복을 줄여준다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 한 번만 순회하며, 각 인덱스에서 `O(1)` 연산만 수행한다.
- **공간복잡도**: `O(1)` — `index` 변수 하나만 사용한다.

이전 BFS 풀이는 큐와 방문 집합(`Set`)에 `O(n)` 공간을 썼고, 시간복잡도도 각 인덱스에서 이웃을 나열하는 비용까지 더해져 최악의 경우 `O(n * max(nums[i]))`까지 늘어날 수 있었다. "도달 가능한 지점을 전부 나열하지 않고, 가장 먼 지점 하나만 추적한다"는 관점 전환으로 `O(n)`까지 줄인 것이 이 풀이의 핵심이다.

## 5. 엣지 케이스

- **배열 길이가 1**(`[0]`): 루프 첫 반복에서 `index = max(0+0, 0) = 0`이 되고, 이는 이미 `len-1(0)` 이상이므로 즉시 `true` — 출발점이 곧 마지막 인덱스인 경우다.
- **첫 칸에서부터 못 움직이는 경우**(`[0, 1]`): `index`가 `0`에서 갱신되지 않은 채로, `i=1`에서 `index(0) < i(1)`이 성립해 `false`.
- **중간에 갇히는 경우**(`[1,0,1,0]`): 인덱스 `1`(값 0)에서 `index`가 `1`에 고정되고, `i=2`에서 `index(1) < i(2)`가 성립해 `false` — 인덱스 `1` 이후의 `1`(인덱스 2에 있는 값)은 애초에 도달 불가능해 반영되지 않는다.
- **모든 칸에서 1칸씩만 이동 가능**(`[1,1,1,...,1]`): 매번 `index`가 정확히 1씩만 늘어 결국 끝까지 도달, `true`. `n=10000`처럼 큰 입력에서도 `O(n)`이라 빠르게 처리된다.
