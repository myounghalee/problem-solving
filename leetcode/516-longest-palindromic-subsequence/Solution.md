# [LeetCode 516] Longest Palindromic Subsequence — 구간 DP로 풀기

- 문제 번호: 516
- 링크: https://leetcode.com/problems/longest-palindromic-subsequence/
- 난이도: Medium
- 태그: String, Dynamic Programming
- 사용 자료구조/알고리즘: **구간 DP(Interval DP)**

## 1. 문제 요약

문자열 `s`가 주어질 때, 가장 긴 팰린드롬 **부분 수열**(연속하지 않아도 됨)의 길이를 반환한다.

```text
예시) "bbbab" → 4  ("bbbb"처럼 골라낼 수 있음)
      "cbbd"  → 2  ("bb")
```

[5번(Longest Palindromic Substring)](../5-longest-palindromic-substring/Solution.md)에서 썼던 "중심에서 확장" 방식은 **연속된 구간**이라서 가능했던 접근이다. 이번엔 부분 수열이라 문자를 중간중간 건너뛸 수 있으므로, 그 방식을 그대로 쓸 수 없고 **구간 DP**로 접근한다.

## 2. 접근 아이디어

`dp[l][r]` = **`s`의 인덱스 `l`부터 `r`까지의 구간 안에서, 가장 긴 팰린드롬 부분 수열의 길이**로 정의한다. 최종 답은 `dp[0][n-1]`.

- **기본값**: `dp[i][i] = 1` (글자 하나는 항상 팰린드롬).
- **양 끝 글자가 같을 때**: 그 두 글자를 팰린드롬의 양 끝으로 그대로 쓸 수 있다. 남은 건 "그 안쪽 구간(`l+1`부터 `r-1`까지)의 최선"이므로, 거기에 `+2`를 더한다.
  ```
  dp[l][r] = dp[l+1][r-1] + 2
  ```
- **양 끝 글자가 다를 때**: 둘을 동시에 쓸 수 없으니, 왼쪽을 버리거나 오른쪽을 버리거나 둘 중 더 나은 쪽을 택한다.
  ```
  dp[l][r] = max(dp[l+1][r], dp[l][r-1])
  ```
- **채우는 순서**: `dp[l][r]`을 구하려면 그보다 짧은 구간(`dp[l+1][r-1]`, `dp[l+1][r]`, `dp[l][r-1]`)이 먼저 계산되어 있어야 한다. 그래서 **구간 길이가 짧은 것부터** 순서대로 채운다. 코드에서는 "구간 길이 - 1"에 해당하는 `i`(= `r - l`)를 바깥 루프로 삼아 `1`부터 늘려가고, 그 안에서 시작 위치 `j`(= `l`)를 훑으며 `dp[j][j+i]`를 채운다.

### 손으로 시뮬레이션 — `s = "bbbab"`

인덱스: `b`0 `b`1 `b`2 `a`3 `b`4

**길이 1**: `dp[i][i] = 1` (전부)

**길이 2**

| 구간 | 글자 | 양끝 | 계산 | 값 |
|---|---|---|---|---|
| `[0,1]` | `bb` | 같음 | `dp[1][0](빈 구간,0) + 2` | `2` |
| `[1,2]` | `bb` | 같음 | `dp[2][1](빈 구간,0) + 2` | `2` |
| `[2,3]` | `ba` | 다름 | `max(dp[3][3], dp[2][2]) = max(1,1)` | `1` |
| `[3,4]` | `ab` | 다름 | `max(dp[4][4], dp[3][3]) = max(1,1)` | `1` |

**길이 3**

| 구간 | 글자 | 양끝 | 계산 | 값 |
|---|---|---|---|---|
| `[0,2]` | `bbb` | 같음 | `dp[1][1](=1) + 2` | `3` |
| `[1,3]` | `bba` | 다름 | `max(dp[2][3], dp[1][2]) = max(1,2)` | `2` |
| `[2,4]` | `bab` | 같음 | `dp[3][3](=1) + 2` | `3` |

**길이 4**

| 구간 | 글자 | 양끝 | 계산 | 값 |
|---|---|---|---|---|
| `[0,3]` | `bbba` | 다름 | `max(dp[1][3], dp[0][2]) = max(2,3)` | `3` |
| `[1,4]` | `bbab` | 같음 | `dp[2][3](=1) + 2` | `3` |

**길이 5(전체)**

| 구간 | 글자 | 양끝 | 계산 | 값 |
|---|---|---|---|---|
| `[0,4]` | `bbbab` | 같음 | `dp[1][3](=2) + 2` | **`4`** |

최종 답 `dp[0][4] = 4` — 정답과 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    public int longestPalindromeSubseq(String s) {
        char[] c = s.toCharArray();
        int[][] dp = new int[c.length][c.length]; // dp[l][r]: s[l..r] 구간의 최장 팰린드롬 부분 수열 길이
        for (int i = 0; i < c.length; i++) dp[i][i] = 1; // 글자 하나는 항상 팰린드롬

        for (int i = 1; i < c.length; i++) { // i: 구간 길이 - 1 (짧은 구간부터 채움)
            for (int j = 0; j < c.length - i; j++) { // j: 구간 시작 인덱스, j+i: 끝 인덱스
                if (c[j] == c[j + i]) dp[j][j + i] = dp[j + 1][j + i - 1] + 2; // 양 끝 같음: 안쪽 구간 + 2
                else dp[j][j + i] = Math.max(dp[j][j + i - 1], dp[j + 1][j + i]); // 양 끝 다름: 한쪽 버리고 더 나은 값
            }
        }

        return dp[0][c.length - 1];
    }
}
```

### 코드 설명

- `i`는 구간의 길이에서 1을 뺀 값(= `r - l`)이다. `i`를 1부터 늘려가며 바깥 루프를 돌리는 게, "더 짧은 구간부터 채운다"는 순서를 보장하는 방법이다.
- `j`는 구간의 시작 인덱스, `j + i`가 끝 인덱스다. 안쪽 루프는 시작 인덱스를 왼쪽부터 오른쪽으로 훑는다.
- 양 끝 문자가 같을 때 참조하는 `dp[j+1][j+i-1]`은, `i == 1`(구간 길이 2)일 때는 `dp[j+1][j]`가 되는데 `j+1 > j`라 "빈 구간"을 뜻한다. 이 값은 배열의 기본값 `0`으로 자연스럽게 처리되므로 별도 예외 처리가 필요 없다(`dp[l][r] = 0 + 2 = 2`가 정확히 나온다).
- 최종 답은 전체 구간을 나타내는 `dp[0][c.length - 1]`이다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n²)` — 구간의 개수가 `O(n²)`개이고, 각 구간은 상수 시간에 계산된다.
- **공간복잡도**: `O(n²)` — `dp` 2차원 배열.

`s.length ≤ 1000`이므로 `O(n²)` ≈ `10^6`으로 충분히 빠르다.

## 5. 엣지 케이스

- **길이 1인 문자열**: `dp[0][0] = 1`이 곧바로 답.
- **전체가 같은 문자로 이루어진 경우** (`"cccc"`): 모든 구간에서 양 끝이 항상 같으므로, 안쪽 구간에 계속 `+2`가 누적되어 전체 길이가 그대로 답이 된다.
- **문자열 전체가 이미 팰린드롬인 경우** (`"racecar"`): `dp[0][n-1]`이 `n` 그대로 나와야 하며, 재귀적으로 안쪽 구간들도 전부 팰린드롬이라 `+2`가 계속 누적된다.
- **애너그램이든 아니든 상관없이 애초에 팰린드롬 부분 수열이 하나도 안 겹치는 경우** (`"abcde"`처럼 모든 문자가 다른 경우): 답은 항상 `1`(아무 문자 하나).

## 6. 겪었던 실수 (디버깅 기록)

**양 끝이 같을 때의 점화식을 잘못 세웠음**: 처음엔 양 끝이 같든 다르든 일단 `max(dp[j][j+i-1], dp[j+1][j+i])`를 구하고, 같으면 그 값에 `+1`만 했다.

```java
// 잘못된 버전
dp[j][j + i] = Math.max(dp[j][j + i - 1], dp[j + 1][j + i]);
if (c[j] == c[j + i]) dp[j][j + i]++;
```

이러면 `"bab"`(양 끝 `b`가 같음)에서 `max(dp[0][1], dp[1][2])`(둘 다 `1`) `+ 1 = 2`가 나오는데, 실제 정답은 `3`(`"bab"` 자체가 팰린드롬)이다. `"racecar"`(전체가 팰린드롬, 길이 7)에서도 `4`밖에 못 찾았다.

**원인**: 양 끝이 같을 때는 "한쪽 끝만 뺀 두 값 중 최댓값"이 아니라, **양쪽 끝을 동시에 뺀 진짜 안쪽 구간**(`dp[j+1][j+i-1]`)을 기준으로 `+2`를 해야 한다. "한쪽만 빼고 다른 쪽은 그대로 둔 값"에는 애초에 반대쪽 끝 문자가 이미 포함되어 있어서, 양 끝을 동시에 팰린드롬에 편입시키는 경우를 제대로 반영하지 못한다.

**수정**: 양 끝이 같은 경우와 다른 경우를 아예 다른 식으로 분리했다(`if/else`로, 위 "3. 코드" 참고).
