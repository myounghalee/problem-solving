# [LeetCode 5] Longest Palindromic Substring — 중심에서 양쪽으로 확장하기 (Expand Around Center)

- 문제 번호: 5
- 링크: https://leetcode.com/problems/longest-palindromic-substring/
- 난이도: Medium
- 태그: Two Pointers, String, Dynamic Programming, Manacher
- 사용 자료구조/알고리즘: **중심 확장(Expand Around Center)**

## 1. 문제 요약

문자열 `s`가 주어질 때, 그 안에서 가장 긴 팰린드롬(회문) 부분 문자열을 반환한다.

```text
예시) "babad" → "bab" (또는 "aba", 둘 다 정답)
      "cbbd"  → "bb"
```

브루트포스로 모든 시작-끝 쌍(`O(n²)`개)마다 팰린드롬 여부를 확인(`O(n)`)하면 전체 `O(n³)`이라 `s.length ≤ 1000`에서도 느려질 수 있다.

## 2. 접근 아이디어

팰린드롬은 **가운데를 기준으로 좌우 대칭**이라는 성질을 이용한다. "어디가 팰린드롬인지"를 처음부터 찾는 대신, **모든 가능한 중심 후보에서 출발해 좌우로 한 칸씩 넓혀가며, 대칭이 깨질 때까지 계속 늘려본다.**

- 중심 후보는 두 종류가 필요하다:
  - **문자 하나 위**(홀수 길이 팰린드롬용, 예: `"aba"`의 중심은 `'b'`) — `n`개
  - **문자와 문자 사이**(짝수 길이 팰린드롬용, 예: `"bb"`의 중심은 두 `'b'` 사이) — `n-1`개
- 모든 인덱스 `i`에 대해 이 두 종류를 다 시도한다. 문자열의 특정 부분(앞/뒤/중간 어디든)에 팰린드롬이 있든, 그 팰린드롬 자신의 중심이 되는 위치는 반드시 이 후보들 중 하나이므로 놓치지 않는다.
- 각 중심에서 좌우로 넓혀가다가 **문자가 달라지는 순간 즉시 멈춘다.** 멈추지 않고 계속 넓히면, 중간에 대칭이 깨졌는데도 더 바깥쪽에서 우연히 같은 문자가 나와 잘못된 팰린드롬으로 오판할 수 있다.
- 매번 새로 찾은 후보의 길이가 **지금까지 찾은 최댓값보다 길 때만** 정답을 갱신한다.

### 손으로 시뮬레이션 — `s = "cbbd"`

| 중심 | 시도 | 결과 |
|---|---|---|
| `i=0`(`'c'`, 문자 하나) | 확장 불가(범위 밖) | - |
| `i=0`(`'c'`와 `'b'` 사이) | `c[0]='c'` vs `c[1]='b'` → 다름 | 즉시 멈춤 |
| `i=1`(`'b'`, 문자 하나) | `l=0,r=2`: `'c'` vs `'b'` → 다름 | 즉시 멈춤 |
| `i=1`(`'b'`와 `'b'` 사이) | `l=1,r=2`: `'b'`==`'b'` → 매칭! 길이 2, 최댓값 갱신 → `l=0,r=3`: `'c'` vs `'d'` → 다름 | 멈춤, 결과 `"bb"` |
| `i=2`, `i=3` | 더 긴 팰린드롬 없음 | - |

최종 결과: `"bb"` — 정답과 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    public String longestPalindrome(String s) {
        int[] res = new int[2]; // 지금까지 찾은 최장 팰린드롬의 [시작, 끝] 인덱스
        char[] c = s.toCharArray();
        for (int i = 0; i < c.length; i++) {
            res = solve(res, c, i - 1, i + 1); // 홀수 길이: 문자 하나(i)가 중심
            res = solve(res, c, i, i + 1);     // 짝수 길이: i와 i+1 사이가 중심
        }

        StringBuilder result = new StringBuilder();
        for (int i = res[0]; i <= res[1]; i++) result.append(c[i]);
        return result.toString();
    }

    // l, r에서 시작해 바깥쪽으로 계속 넓히며, 지금까지의 최장 기록(res)을 갱신
    private int[] solve(int[] res, char[] c, int l, int r) {
        while (l >= 0 && r < c.length) {
            if (c[l] == c[r]) {
                if (res[1] - res[0] < r - l) res = new int[]{l, r}; // 더 길 때만 갱신
            } else break; // 대칭이 깨지면 즉시 멈춤
            l--;
            r++;
        }
        return res;
    }
}
```

### 코드 설명

- `solve(res, c, l, r)`는 홀수/짝수 두 경우 모두에 재사용되는 헬퍼다. 홀수 길이는 `(i-1, i+1)`에서, 짝수 길이는 `(i, i+1)`에서 시작해 바깥으로 넓혀간다는 점만 다르다.
- `while` 루프 안에서 `c[l] == c[r]`이 거짓이 되는 순간 `else break`로 즉시 멈춘다 — 대칭이 깨진 뒤로도 계속 비교하면, 우연히 더 바깥에서 문자가 같아졌을 때 실제로는 이어지지 않은(중간이 끊긴) 구간을 팰린드롬으로 잘못 인정하게 된다.
- `if (res[1] - res[0] < r - l) res = new int[]{l, r};`가 "지금까지의 최장 기록보다 길 때만 갱신"하는 부분이다. `r - l`이 지금 후보의 길이(정확히는 길이-1)이고, `res[1] - res[0]`이 지금까지 기록된 최장 길이(-1)다. 이 비교가 없으면, 나중에 찾은 더 짧은 팰린드롬이 앞서 찾은 긴 팰린드롬을 덮어써버리는 문제가 생긴다.
- 최종적으로 `res`에 남은 `[시작, 끝]` 인덱스로 원본 문자열의 해당 구간을 잘라 반환한다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n²)` — 중심 후보가 `O(n)`개이고, 각 중심에서 확장하는 데 최악의 경우 `O(n)`(예: 전체가 같은 문자로 이루어진 경우).
- **공간복잡도**: `O(1)` — 결과 인덱스 두 개만 유지한다(결과 문자열 생성 제외).

`s.length ≤ 1000` 제한에서 `O(n²)` ≈ `10^6`으로 충분히 빠르다. 더 빠른 `O(n)` 방법(Manacher's Algorithm)도 있지만, 이 제약 크기에서는 필요하지 않다.

## 5. 엣지 케이스

- **길이 1인 문자열**: 항상 자기 자신이 정답(모든 한 글자는 팰린드롬).
- **전체가 같은 문자로 이루어진 경우** (`"aaaa"`): 각 중심에서의 확장이 문자열 끝까지 이어지므로, 매번 갱신되며 최종적으로 전체 문자열이 정답이 된다.
- **팰린드롬이 문자열 여러 군데 흩어져 있고, 더 짧은 것이 나중 위치에 있는 경우**: 반드시 "더 길 때만 갱신"하는 조건이 있어야 앞서 찾은 긴 팰린드롬이 뒤늦게 짧은 것으로 덮어써지지 않는다.
- **정답이 여러 개인 경우** (`"babad"`의 `"bab"`/`"aba"`): 어느 쪽이 먼저 발견되어 최종 정답이 되든 문제에서 둘 다 정답으로 인정한다.

## 6. 겪었던 실수 (디버깅 기록)

1. **홀수 길이 확장 루프에 `break`가 없었음**: 처음엔 짝수 길이 루프에만 `else break`가 있고, 홀수 길이 루프엔 없었다. 그래서 중간에 대칭이 깨져도 계속 넓혀가다가, 우연히 더 바깥에서 문자가 같아지면 그걸 팰린드롬으로 잘못 기록했다 — `"ZPMCMQZ"`(실제로는 팰린드롬이 아님)를 그대로 답으로 반환하는 사례로 확인했다. → 두 경우를 하나의 `solve` 헬퍼로 합치면서 `break` 로직도 통일해 해결.
2. **최장 갱신 조건이 `res[1]-res[0] < r-1`이었음**: 새 후보의 실제 길이(`r-l`)가 아니라 `r-1`이라는, `l`이 반영되지 않은 값과 비교하고 있었다. 그래서 `"aaaa"`처럼 단순한 입력에서도 실제로 더 긴 팰린드롬을 찾았는데 조건이 우연히 안 맞아 갱신이 안 되는 경우가 있었다(`"aaaa"` → `"aaa"`로 짧게 반환됨). → `r - l`로 비교하도록 수정.
3. **(더 근본적으로) 애초에 길이 비교 자체가 없었음**: 가장 처음 버전은 매칭될 때마다 무조건 `res`를 덮어써서, 앞서 찾은 긴 팰린드롬(`"racecar"`)이 나중에 찾은 짧은 팰린드롬(`"ybby"`)으로 덮어써지는 문제가 있었다. → 길이 비교 조건을 추가하면서 해결.
