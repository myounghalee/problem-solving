# [LeetCode 121] Best Time to Buy and Sell Stock — 지금까지의 최저가만 기억하며 한 번에 훑기

- 문제 번호: 121
- 링크: https://leetcode.com/problems/best-time-to-buy-and-sell-stock/
- 난이도: Easy
- 태그: Array, Dynamic Programming
- 사용 자료구조/알고리즘: **한 번의 순회(단일 패스) + 최저가 추적**

## 1. 문제 요약

`prices[i]`가 `i`번째 날의 주가일 때, **딱 한 번** 사고 **한 번**(사는 날보다 나중에) 팔아서 얻을 수 있는 **최대 이익**을 구한다. 이익을 낼 수 없으면 `0`을 반환한다.

```text
예시) prices = [7,1,5,3,6,4] → 5   (1일차 가격 1에 사서 4일차(인덱스 기준) 가격 6에 팔면 5)
      prices = [7,6,4,3,1]   → 0   (계속 떨어지기만 해서 이익을 낼 수 없음)
```

> 처음엔 모든 `(사는 날, 파는 날)` 쌍을 다 검사하는 이중 루프로 풀었는데, `prices.length`가 최대 `10^5`라 최악의 경우 `10^10`번 연산이 나와 **Time Limit Exceeded**가 났다. 아래는 한 번의 순회로 끝내는 `O(n)` 풀이다.

## 2. 접근 아이디어

"모든 쌍을 비교"하는 대신, 매 순간 "지금까지 나온 가격 중 제일 쌌던 날에 샀다면 오늘 팔았을 때 얼마 버는가"만 계산하면 충분하다.

- `min`: 지금까지 본 가격 중 최솟값(가장 유리한 매수 시점의 가격).
- `ans`: 지금까지 계산해본 것 중 최대 이익.

배열을 앞에서부터 한 번 훑으면서, 각 날짜 `i`에서

1. **오늘 판다면**: `prices[i] - min`이 지금까지의 최대 이익보다 크면 `ans`를 갱신한다. (반드시 `min`이 갱신되기 *전에* 먼저 계산해야 한다 — 오늘 가격으로 오늘 사고파는 게 아니라, *그전에 있던* 최저가에 사서 오늘 파는 경우를 봐야 하기 때문이다.)
2. **오늘의 가격이 지금까지의 최저가보다 낮다면**: `min`을 오늘 가격으로 갱신한다 — 앞으로는 오늘이 최적의 매수 시점 후보가 된다.

미래의 가격을 미리 알 필요 없이, 과거의 최저가만 계속 들고 다니면 각 날짜에서 낼 수 있는 최선의 이익을 즉시 계산할 수 있다.

### 손으로 시뮬레이션 — `prices = [7,1,5,3,6,4]`

시작: `min = prices[0] = 7`, `ans = 0`

| i | prices[i] | ans = max(ans, prices[i]-min) | min = min(min, prices[i]) |
|---|---|---|---|
| 1 | 1 | max(0, 1-7=-6) = 0 | min(7,1) = 1 |
| 2 | 5 | max(0, 5-1=4) = 4 | min(1,5) = 1 |
| 3 | 3 | max(4, 3-1=2) = 4 | min(1,3) = 1 |
| 4 | 6 | max(4, 6-1=5) = 5 | min(1,6) = 1 |
| 5 | 4 | max(5, 4-1=3) = 5 | min(1,4) = 1 |

최종 `ans = 5` — 정답과 일치한다. (1일차의 최저가 `1`에 사서, 4일차의 `6`에 팔았을 때가 최선이었다.)

## 3. 코드 (Java)

```java
class Solution {
    public int maxProfit(int[] prices) {
        int min = prices[0]; // 지금까지 본 가격 중 최솟값 (매수 시점 후보)
        int ans = 0;          // 지금까지의 최대 이익
        for (int i = 1; i < prices.length; i++) {
            ans = Math.max(ans, prices[i] - min); // 오늘 팔았을 때의 이익과 비교
            min = Math.min(min, prices[i]);        // 최저가 갱신
        }
        return ans;
    }
}
```

### 코드 설명

- `min`은 항상 "인덱스 `i` 이전 날짜들 중" 최저가를 담고 있다. `i`번째 반복에서 `ans`를 먼저 계산한 뒤에 `min`을 갱신하므로, `prices[i] - min`은 절대 "오늘 사서 오늘 파는" 경우를 계산하지 않는다.
- `ans`는 이익이 나지 않는 경우(계속 하락)에도 초기값 `0`에서 한 번도 갱신되지 않아 자연스럽게 `0`을 반환한다 — 별도의 조건문이 필요 없다.
- 이중 루프도, 별도 배열도, 정렬도 없이 변수 두 개만으로 배열을 한 번만 순회한다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 배열을 한 번만 순회한다.
- **공간복잡도**: `O(1)` — `min`, `ans` 두 변수만 사용한다.

이전 브루트포스(모든 `(i,j)` 쌍 비교 + 정렬)는 `O(n^2)` 시간(정렬까지 포함하면 `O(n^2 + n log n)`)이 걸려 `n=10^5` 근처에서 TLE가 났다. "미래를 미리 계산해두지 않고 과거의 최적값만 들고 다닌다"는 관점 전환으로 `O(n)`까지 줄인 것이 이 풀이의 핵심이다.

## 5. 엣지 케이스

- **배열 길이가 1**: 루프가 한 번도 안 돌아 `ans = 0`을 그대로 반환한다 — 사고팔 날이 하루뿐이면 이익을 낼 수 없으므로 옳다.
- **계속 하락하는 경우**(`[7,6,4,3,1]`): 매번 `prices[i] - min`이 음수이거나 0이라 `ans`가 갱신되지 않고 `0`이 유지된다.
- **계속 상승하는 경우**(`[1,2,3,4,5]`): `min`이 `prices[0]`에 고정된 채 갱신되지 않고, `ans`가 매번 늘어나 최종적으로 `prices[n-1] - prices[0]`이 된다.
- **모든 가격이 동일**(`[3,3,3,3]`): `prices[i] - min`이 항상 `0`이라 `ans = 0`.
