# [LeetCode 13] Roman to Integer — 오른쪽부터 훑으며 "다음이 더 크면 뺀다"

- 문제 번호: 13
- 링크: https://leetcode.com/problems/roman-to-integer/
- 난이도: Easy
- 태그: Hash Table, Math, String
- 사용 자료구조/알고리즘: **해시맵 조회 + 오른쪽에서 왼쪽으로 스캔**

## 1. 문제 요약

로마 숫자 문자열 `s`(길이 1~15)를 정수로 변환한다. [12번(Integer to Roman)](../12-integer-to-roman/Solution.md)의 정반대 방향이다.

```text
예시) "III"     → 3
      "LVIII"   → 58   (L=50, V=5, III=3)
      "MCMXCIV" → 1994 (M=1000, CM=900, XC=90, IV=4)
```

기본적으로는 기호 값을 왼쪽부터 더하면 되지만, 작은 기호가 큰 기호 **앞**에 오면 빼야 한다(`IV`=4, `IX`=9 등 6가지).

## 2. 접근 아이디어

문자열을 **오른쪽(끝)에서 왼쪽으로** 훑는 게 핵심이다. LeetCode 힌트에도 나와 있는 방식인데, 이렇게 하면 "이 기호가 감산 표기법의 앞부분인지"를 매우 간단한 규칙으로 판단할 수 있다.

- 오른쪽부터 보면, 방금 처리한(즉 지금 보는 기호보다 오른쪽에 있는) 기호의 값을 `temp`에 기억해둔다.
- 지금 보는 기호의 값이 `temp`보다 **작으면**, 그 기호는 감산 표기법의 앞부분이라는 뜻이다(`IV`에서 `I`는 오른쪽 `V`보다 작음) → **빼야** 한다.
- 그렇지 않으면(같거나 크면) 그냥 **더한다**.
- 왼쪽에서 오른쪽으로 훑으면 "다음 문자를 미리 봐야(lookahead)" 판단할 수 있는데, 오른쪽에서 왼쪽으로 훑으면 "방금 처리한 값과 비교"만으로 충분해서 코드가 더 단순해진다.

이 규칙 하나로 `IV`, `IX`, `XL`, `XC`, `CD`, `CM` 6가지 감산 표기법과 일반적인 덧셈 표기법(`III`, `LVIII` 등)이 전부 자연스럽게 처리된다 — 표기법별로 따로 분기할 필요가 없다.

### 손으로 시뮬레이션 — `s = "MCMXCIV"`

오른쪽부터 순서대로: `V C I X C M C M`이 아니라 실제로는 `V, I, C, X, C, M, M`(`s`의 인덱스를 끝에서부터, 즉 `V→I→C→X→C→M→M`)... 정확히는 문자열이 `M C M X C I V`이므로 끝에서부터 `V, I, C, X, M, C, M` 순서로 본다.

| 처리 문자 | 값 | `temp`(오른쪽 이웃의 값) | 비교 | 연산 | 누적 `res` |
|---|---|---|---|---|---|
| `V` | 5 | 0 (없음) | `0 > 5`? 아니오 | `+5` | 5 |
| `I` | 1 | 5 | `5 > 1`? 예 | `-1` | 4 |
| `C` | 100 | 1 | `1 > 100`? 아니오 | `+100` | 104 |
| `X` | 10 | 100 | `100 > 10`? 예 | `-10` | 94 |
| `M` | 1000 | 10 | `10 > 1000`? 아니오 | `+1000` | 1094 |
| `C` | 100 | 1000 | `1000 > 100`? 예 | `-100` | 994 |
| `M` | 1000 | 100 | `100 > 1000`? 아니오 | `+1000` | 1994 |

`X`(90의 앞부분, `XC`)와 `C`(900의 앞부분, `CM`)가 각각 오른쪽 이웃(`C`, `M`)보다 작아서 자동으로 빼졌고, 최종 결과는 **1994** — 정답과 일치한다.

## 3. 코드 (Java)

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int romanToInt(String s) {
        Map<Character, Integer> map = new HashMap<>(); // 로마 숫자 기호 -> 값
        map.put('I', 1);
        map.put('V', 5);
        map.put('X', 10);
        map.put('L', 50);
        map.put('C', 100);
        map.put('D', 500);
        map.put('M', 1000);

        char[] arr = s.toCharArray();
        int res = 0;
        int temp = 0; // 방금 처리한(오른쪽 이웃) 기호의 값
        for (int i = arr.length - 1; i >= 0; i--) {
            int no = map.get(arr[i]);
            if (temp > no) no *= -1; // 오른쪽 이웃이 더 크면 이 기호는 빼야 함 (감산 표기법)
            temp = map.get(arr[i]);
            res += no;
        }
        return res;
    }
}
```

### 코드 설명

- `map`은 기호 하나를 값으로 바꾸는 단순 조회 테이블이다.
- `temp`는 "바로 직전에(오른쪽에서) 처리한 기호의 값"을 기억한다. 루프가 오른쪽에서 왼쪽으로 진행되므로, `temp`는 항상 지금 보는 기호의 **오른쪽 이웃** 값이다.
- `if (temp > no) no *= -1;`가 핵심 로직 전부다. 오른쪽 이웃이 지금 기호보다 크면(`IV`에서 `I`를 볼 때 오른쪽 이웃 `V`가 더 큼) 이 기호를 빼야 한다는 뜻이므로 부호를 뒤집는다.
- `temp = map.get(arr[i]);`를 **부호를 뒤집기 전이 아니라 원래 값 기준으로** 갱신하는 것이 중요하다 — 다음(왼쪽) 반복에서 비교할 때는 "이 기호가 원래 얼마짜리인지"가 필요하지, 부호가 뒤집힌 값이 필요한 게 아니기 때문이다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 문자열을 한 번만 순회한다 (`n`은 `s`의 길이, 최대 15).
- **공간복잡도**: `O(1)` — 해시맵 크기가 7개 기호로 고정되어 있어 입력 크기와 무관.

## 5. 엣지 케이스

- **감산 표기법이 연속으로 나오는 경우** (`MCMXCIV`처럼 `CM`, `XC`, `IV`가 한 문자열에 여러 번): 매 위치마다 "바로 오른쪽 이웃"만 비교하므로 서로 영향을 주지 않고 독립적으로 정확히 처리된다.
- **길이 1인 문자열** (`"I"`, `"M"` 등): `temp`가 초기값 `0`이라 항상 `0 > no`가 거짓 → 그대로 더해져서 올바르게 처리된다.
- **감산이 전혀 없는 경우** (`"III"`, `"LVIII"`): 모든 기호가 오른쪽 이웃보다 크거나 같으므로 전부 더하기만 수행된다.
