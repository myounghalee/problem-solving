# [LeetCode 2] Add Two Numbers — 자리올림을 들고 다니며 새 리스트를 만들기

- 문제 번호: 2
- 링크: https://leetcode.com/problems/add-two-numbers/
- 난이도: Medium
- 태그: Linked List, Math, Recursion
- 사용 자료구조/알고리즘: **더미 헤드 + 자리올림(carry) 변수**

## 1. 문제 요약

두 정수가 각각 **자리수가 역순**으로 저장된 연결 리스트로 주어질 때, 두 수를 더한 결과를 같은 방식(역순 연결 리스트)으로 반환한다.

```text
예시) [2,4,3] + [5,6,4] → [7,0,8]   (342 + 465 = 807)
```

## 2. 왜 숫자로 변환해서 풀면 안 되는가

가장 먼저 떠오르는 방법은 리스트를 문자열/숫자로 합친 뒤 더하고, 다시 리스트로 쪼개는 것이다. 하지만 이 문제가 **연결 리스트**로 숫자를 표현한 이유가 바로 여기 있다 — 노드가 최대 100개, 즉 **최대 100자리 숫자**까지 다뤄야 한다는 뜻이고, 이는 `long`(최대 19자리)의 범위를 훌쩍 넘는다.

```text
20자리 숫자 하나만 파싱해도: NumberFormatException
19자리 두 개를 더한 합이 19자리를 넘으면: long 오버플로로 음수가 되어 조용히 깨짐
```

작은 예제로는 절대 드러나지 않고, 제약사항이 명시한 큰 입력에서만 실패한다. 그래서 **자리수 하나하나를 직접 계산**해야 한다 — 마치 손으로 덧셈을 할 때처럼, 1의 자리부터 순서대로 더하고 자리올림을 다음 자리로 넘긴다.

## 3. 접근 아이디어

두 리스트를 **동시에** 한 칸씩 내려가며, 각 자리의 합을 계산한다.

```text
그 자리의 합 = l1의 값(없으면 0) + l2의 값(없으면 0) + 이전 자리에서 넘어온 자리올림
```

- 그 합의 **1의 자리**(`sum % 10`)가 이번 자리의 결과값이다.
- 그 합의 **10의 자리**(`sum / 10`, 항상 0 또는 1)가 다음 자리로 넘길 자리올림이다.

두 리스트의 길이가 다를 수 있으므로, 짧은 쪽이 끝나면 그 자리는 `0`을 더하는 것으로 취급한다. 그리고 **두 리스트가 모두 끝났어도 자리올림이 남아 있으면 한 자리 더** 만들어야 한다(`while` 조건에 `carry != 0`이 포함되는 이유).

### 손으로 시뮬레이션 — `[9,9,9,9,9,9,9] + [9,9,9,9]`

`9999999 + 9999 = 10009998`, 역순으로 `[8,9,9,9,0,0,0,1]`.

| 자리 | l1 | l2 | carry(들어옴) | 합 | 결과 자리 | carry(나감) |
|---|---|---|---|---|---|---|
| 1 | 9 | 9 | 0 | 18 | 8 | 1 |
| 2 | 9 | 9 | 1 | 19 | 9 | 1 |
| 3 | 9 | 9 | 1 | 19 | 9 | 1 |
| 4 | 9 | 9 | 1 | 19 | 9 | 1 |
| 5 | 9 | (없음→0) | 1 | 10 | 0 | 1 |
| 6 | 9 | — | 1 | 10 | 0 | 1 |
| 7 | 9 | — | 1 | 10 | 0 | 1 |
| 8 | (없음→0) | — | 1 | 1 | 1 | 0 |

8번째 자리는 두 리스트 모두 끝났지만 `carry=1`이 남아 있어서 만들어졌다. 결과 `[8,9,9,9,0,0,0,1]` — 정답과 일치한다.

## 4. 코드 (Java)

```java
class ListNode {
    int val;
    ListNode next;
    ListNode() {}
    ListNode(int val) { this.val = val; }
    ListNode(int val, ListNode next) { this.val = val; this.next = next; }
}

class Solution {
    public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode();
        ListNode cur = dummy;
        int carry = 0;

        while (l1 != null || l2 != null || carry != 0) {
            int sum = carry + (l1 != null ? l1.val : 0) + (l2 != null ? l2.val : 0);
            carry = sum / 10;
            cur.next = new ListNode(sum % 10);
            cur = cur.next;
            if (l1 != null) l1 = l1.next;
            if (l2 != null) l2 = l2.next;
        }

        return dummy.next;
    }
}
```

### 코드 설명

- **더미 헤드(`dummy`)**를 두어 "첫 노드를 특별 취급"하는 분기를 없앤다. `cur`는 항상 "지금까지 만든 결과의 마지막 노드"를 가리키고, 매 반복마다 `cur.next`에 새 노드를 붙인 뒤 `cur`를 그리로 옮긴다. 최종 결과는 `dummy.next`(더미 자신은 버림).
- **`while` 조건에 `carry != 0`이 포함된다.** 두 리스트가 모두 끝나도 자리올림이 남아 있으면 한 바퀴 더 돌아야 하기 때문이다(위 시뮬레이션의 8번째 자리).
- **매번 새 `ListNode`를 만들고, 입력 리스트는 건드리지 않는다.** `l1`, `l2`는 읽기만 하고 값을 바꾸지 않으므로, 호출한 쪽이 원본 리스트를 그대로 재사용할 수 있다.
- `l1 != null ? l1.val : 0`으로 리스트가 먼저 끝난 쪽은 `0`을 더하는 것으로 자연스럽게 처리한다.

## 5. 복잡도 분석

- **시간복잡도**: `O(max(m, n))` — `m`, `n`은 두 리스트의 길이. 더 긴 쪽을 다 지나갈 때까지(그리고 자리올림이 남으면 한 칸 더) 순회한다.
- **공간복잡도**: `O(max(m, n))` — 결과로 새로 만드는 노드 수(입력 재사용 없이 전부 새로 만들므로).

## 6. 엣지 케이스

- **`0 + 0`**: 첫 반복에서 `sum=0`, 결과 `[0]`.
- **길이가 다름**: 짧은 쪽이 끝난 뒤에도 긴 쪽과 자리올림이 남아 있으면 계속 진행한다(`[1] + [9,9] → [0,0,1]`).
- **자리올림이 마지막까지 이어짐**: 두 리스트가 모두 끝났는데 `carry=1`이면 자리 하나가 추가로 생긴다.
- **제약 상한(100자리)**: `9`가 100개인 수에 `1`을 더하면 자리올림이 전부 이어져 101자리 결과가 나온다. 실제로 확인해보니 결과 노드 수가 정확히 101개다.

검증: 무작위 20,000건을 `BigInteger` 기준 구현과 교차 비교해 전부 일치했다. 100자리 극단 케이스, 그리고 입력 리스트가 변형되지 않는지도 확인했다.

## 7. 겪었던 시행착오 — 숫자로 변환하는 접근이 왜 실패하는가

처음 시도한 방법은 각 리스트를 순회하며 자리수를 이어붙여 문자열을 만들고, `Long.parseLong`으로 파싱해 더한 뒤 다시 문자열로 쪼개 리스트를 만드는 것이었다.

```java
String num1 = "";
while (l1 != null) { num1 = l1.val + num1; l1 = l1.next; }
// ... num2도 동일하게 만든 뒤
Long num = Long.parseLong(num1) + Long.parseLong(num2);
```

문제의 예시(최대 7자리)에서는 잘 작동했지만, 제약사항이 허용하는 **100자리** 입력에서 실제로 실패한다.

```text
20자리 숫자 하나만 넣어도:
  NumberFormatException: For input string: "99999999999999999999"

19자리씩인 두 수를 더했더니 합이 19자리를 넘는 경우:
  실제 정답: 18446744073709551614
  코드 결과: NumberFormatException: For input string: "-"
           (long 덧셈이 오버플로되어 음수가 되고, 그 부호 문자를 숫자로 파싱하려다 예외)
```

두 번째 경우가 특히 위험하다. 각 숫자는 `long` 범위 안이라 **파싱 자체는 성공**하고, 오직 **더한 결과**만 넘친다. 오버플로된 `long`은 예외 없이 조용히 음수가 되므로, 발견하기가 더 어렵다.

**교훈: 어떤 자료구조로 값을 표현했는지는 대개 그 문제가 다루는 값의 범위에 대한 힌트다.** 이 문제가 정수를 연결 리스트로 표현한 것 자체가 "기본 정수 타입 범위를 넘는 값을 다뤄야 한다"는 신호였다. 숫자로 변환해서 계산하는 접근은, 문제가 원래 방어하려던 바로 그 지점(큰 수)에서 무너진다.

## 8. 관련 문제

같은 **연결 리스트 조작** 계열이지만, 이 문제는 노드 값 자체를 계산에 쓴다는 점이 다르다.

- [Merge Two Sorted Lists (LeetCode 21)](../21-merge-two-sorted-lists/Solution.md) — 같은 "더미 헤드 + `cur` 포인터로 새 리스트를 만든다"는 패턴을 쓴다. 그쪽은 값을 비교해 순서대로 잇는 것이 목적이고, 이 문제는 값을 더해 자리올림을 계산하는 것이 목적이라는 차이가 있다.
- [Remove Nodes From Linked List (LeetCode 2487)](../2487-remove-nodes-from-linked-list/Solution.md) — 리스트를 새로 만드는 대신 기존 노드를 재배치한다는 점이 대비된다. 이 문제는 정확히 반대로, 입력을 건드리지 않고 전부 새 노드로 결과를 만든다.
