# [LeetCode 273] Integer to English Words — 3자리씩 끊어서 리스트에 모으고 join하기

- 문제 번호: 273
- 링크: https://leetcode.com/problems/integer-to-english-words/
- 난이도: Hard
- 태그: Math, String, Recursion
- 사용 자료구조/알고리즘: **자릿수 분해(모듈러 연산) + `List<String>` + `String.join` 패턴**

## 1. 문제 요약

0 이상의 정수 `num`(최대 `2^31 - 1`)이 주어지면, 이를 영어로 풀어쓴 단어 표현으로 변환한다.

```text
예시) 123      → "One Hundred Twenty Three"
      12345    → "Twelve Thousand Three Hundred Forty Five"
      1234567  → "One Million Two Hundred Thirty Four Thousand Five Hundred Sixty Seven"
```

로직 자체(숫자 → 영어 단어 매핑)는 단순하지만, **엣지 케이스가 많고 그때마다 공백/단위를 잘못 넣기 쉬운 문제**다. 특히 중간 자릿수가 0인 경우(`1000010` → `"One Million Ten"`, `Thousand`가 나오면 안 됨), 정확히 100·10의 배수인 경우(`100`, `20000`)가 대표적인 함정이다.

## 2. 접근 아이디어

숫자를 뒤에서부터 **3자리씩(천 단위로) 끊어서** 처리한다. 각 3자리 덩어리는 "0~999를 영어로 바꾸는" 하나의 작은 문제로 쪼개지고, 거기에 자릿수에 맞는 단위(`Thousand`, `Million`, `Billion`)만 붙이면 된다.

- **덩어리 분해**: `num % 1000`으로 가장 낮은 3자리를 뽑고, `num /= 1000`으로 다음 덩어리로 넘어간다. 문자열로 변환해서 콤마로 쪼개는 방식보다 산술 연산이 더 직접적이고, 자릿수 인덱스(`u`)도 반복마다 정확히 하나씩만 증가시키면 되므로 관리가 쉽다.
- **덩어리가 0이면 통째로 건너뛴다**: 숫자도, 단위(`Thousand` 등)도 전혀 출력하지 않아야 한다. 이때도 자릿수 인덱스 `u`는 반드시 증가시켜야, 그다음 0이 아닌 덩어리가 올바른 단위를 받는다.
- **공백을 손으로 관리하지 않는다**: 각 덩어리를 문자열로 만든 뒤 `List<String>`에 담아두고, 마지막에 한 번에 이어붙인다. 덩어리 하나를 만드는 로직과, 덩어리들 사이에 공백을 넣는 로직을 분리하면 "공백이 빠지거나 두 번 들어가는" 실수를 구조적으로 줄일 수 있다.
- 덩어리는 **낮은 자릿수부터** 만들어지므로(1의 자리 덩어리가 리스트에 먼저 들어감), 최종 문자열을 만들 때는 리스트를 **뒤에서부터** 순회해야 큰 단위가 앞에 오는 올바른 순서가 된다.

### 손으로 시뮬레이션 — `num = 1000010`

| 반복 | `no` (덩어리) | 처리 | `list` 상태 |
|---|---|---|---|
| 1 | `10` (1000010 % 1000) | `no < 20` → `"Ten"`, 단위는 `u=0`이라 없음 | `["Ten"]` |
| 2 | `0` (1000 % 1000) | `no == 0` → 건너뜀 (숫자도 단위도 없음), `u`만 증가 | `["Ten"]` |
| 3 | `1` (1 % 1000) | `"One"` + 단위 `u=2` → `"Million"` → `"One Million"` | `["Ten", "One Million"]` |

리스트를 뒤에서부터(`i = list.size()-1 → 0`) 이어붙이면 `"One Million" + " " + "Ten"` = **`"One Million Ten"`**. 가운데 0인 덩어리가 완전히 무시되면서도, 그 뒤(낮은 자리)의 `"Ten"`은 올바르게 단위 없이 살아남는다.

## 3. 코드 (Java)

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public String numberToWords(int num) {
        if (num == 0) return "Zero";

        String[] one = {"", "One", "Two", "Three", "Four", "Five", "Six", "Seven", "Eight", "Nine",
                "Ten", "Eleven", "Twelve", "Thirteen", "Fourteen", "Fifteen", "Sixteen", "Seventeen", "Eighteen", "Nineteen"};
        String[] ten = {"", "", "Twenty", "Thirty", "Forty", "Fifty", "Sixty", "Seventy", "Eighty", "Ninety"};
        String[] unit = {"", "Thousand", "Million", "Billion"}; // num 최댓값(2^31-1)까지는 Billion으로 충분
        List<String> list = new ArrayList<>(); // 낮은 자리 덩어리부터 순서대로 쌓임

        int u = 0; // 지금 처리 중인 덩어리의 자릿수 인덱스 (0=일, 1=천, 2=백만, 3=십억)
        while (num > 0) {
            int no = num % 1000; // 가장 낮은 3자리
            num = num / 1000;

            if (no == 0) {
                u++; // 덩어리가 비어도 자릿수 인덱스는 반드시 넘어가야 함
                continue;
            }

            StringBuilder sb = new StringBuilder();
            if (no >= 100) {
                sb.append(one[no / 100]).append(" Hundred");
                no = no % 100;
                if (no > 0) sb.append(" ");
            }

            if (no < 20) {
                sb.append(one[no]);
            } else {
                sb.append(ten[no / 10]);
                if (no % 10 > 0) sb.append(" ").append(one[no % 10]); // 일의 자리가 0이면 아예 안 붙임
            }

            if (!sb.isEmpty() && !unit[u].isEmpty()) sb.append(" ").append(unit[u]);
            u++;
            list.add(sb.toString());
        }

        StringBuilder sb = new StringBuilder();
        for (int i = list.size() - 1; i >= 0; i--) { // 큰 자리부터 나오도록 역순 순회
            sb.append(list.get(i));
            if (i != 0) sb.append(" ");
        }
        return sb.toString();
    }
}
```

### 코드 설명

- `one`, `ten`은 각각 0~19, 20의 배수(20/30/.../90)를 담은 조회 테이블이다. `unit`은 3자리 덩어리의 자릿수 이름이다.
- `u`는 지금 처리 중인 덩어리가 몇 번째 천 단위인지를 나타낸다. **덩어리가 0이어서 건너뛰는 경우에도 `u++`는 반드시 실행**되어야 하는데, 그렇지 않으면 그다음 덩어리가 실제보다 한 단계 낮은(혹은 높은) 단위를 잘못 받는다.
- 백의 자리 처리에서 `no >= 100`(단순 `>`가 아님)이어야, `no`가 정확히 100/200/.../900인 경우도 놓치지 않는다. `no % 100 == 0`이면 나머지 부분에 아무것도 안 붙는다.
- 십의 자리 처리에서 `no % 10 > 0`일 때만 일의 자리 단어를 붙인다 — 20, 30처럼 일의 자리가 없는 경우 공백만 남는 실수를 이 조건으로 막는다.
- `unit[u]`가 빈 문자열(가장 낮은 덩어리, `u == 0`)이면 단위를 아예 붙이지 않는다 — 안 그러면 문자열 끝에 의미 없는 공백이 남는다.
- 마지막으로 `list`를 역순으로 순회하며 공백으로 이어붙인다. 덩어리 내부의 공백과 덩어리 사이의 공백을 서로 다른 코드가 책임지도록 분리했기 때문에, 공백이 겹치거나 빠지는 문제가 구조적으로 발생하지 않는다.

## 4. 복잡도 분석

- **시간복잡도**: `O(log num)` — `num`을 1000으로 계속 나누므로, 반복 횟수는 `num`의 자릿수(최대 4개 덩어리: 십억/백만/천/일)에 비례한다. 각 반복은 상수 시간.
- **공간복잡도**: `O(1)`(입력 크기와 무관하게 최대 4개 덩어리) — 결과 문자열 길이도 자릿수에 비례하는 상수 수준.

## 5. 엣지 케이스

- **`num == 0`**: 별도로 `"Zero"`를 즉시 반환한다 (메인 로직은 0을 만나면 그냥 아무것도 안 만들기 때문에 별도 처리 필요).
- **중간 덩어리가 0인 경우** (`1000010`, `1000000` 등): 그 덩어리는 숫자도 단위도 전혀 출력되지 않아야 하며, 자릿수 인덱스만 정확히 넘어가야 한다.
- **정확히 100의 배수인 덩어리** (`100`, `100000`): 백의 자리만 있고 나머지가 없는 경우.
- **정확히 10의 배수인 덩어리** (`20`, `120`, `20000`): 십의 자리만 있고 일의 자리가 없는 경우.
- **`Integer.MAX_VALUE`(`2147483647`)**: 4개 덩어리(십억/백만/천/일)가 전부 채워지는 최댓값 케이스.

## 6. 겪었던 실수 (디버깅 기록)

풀이 과정에서 실제로 순서대로 마주쳤던 버그들을 기록해둔다 — "숫자를 자연어로 풀어쓰는" 유형 문제에서 공통적으로 겪기 쉬운 실수들이다.

1. **덩어리 사이에 공백이 안 들어감**: 처음엔 단위를 붙일 때 앞에만 공백을 넣고 뒤에는 안 넣어서, 다음 덩어리가 이어 붙을 때 `"...ThousandThree..."`처럼 붙어버렸다. → 덩어리를 개별 문자열로 만들어 리스트에 모았다가 마지막에 `" "`로 합치는 방식으로 바꿔서 해결.
2. **0인 덩어리를 건너뛰면서 자릿수 인덱스도 같이 건너뜀**: `continue`로 빈 덩어리를 건너뛸 때 자릿수 인덱스 증가 코드도 같이 스킵되어, 그다음 덩어리가 실제보다 한 단계 높은 단위를 잘못 받았다(`1000010` → `"One Million Ten Thousand"`처럼 `Thousand`가 잘못 붙음). → 인덱스 증가를 `continue` 여부와 무관하게 항상 실행되도록 위치를 옮겨서 해결.
3. **`no > 100` vs `no >= 100`**: 덩어리가 정확히 100의 배수일 때 백의 자리 조건을 놓쳐서, 나머지 처리 로직이 `ten[10]`(배열 범위 밖)을 참조해 `ArrayIndexOutOfBoundsException`이 발생했다. → 조건을 `>=`로 수정.
4. **일의 자리가 없는데 빈 문자열 앞에 공백을 붙임**: `unit[u]`가 빈 문자열인데도 무조건 `" " + unit[u]`를 붙여서 문자열 끝에 의미 없는 공백이 남았다. 같은 패턴이 십의 자리 처리(`ten[no/10] + " " + one[no%10]`)에도 있어서, `20`처럼 일의 자리가 없는 경우 중간에 공백이 두 번 들어갔다(`"Twenty  Thousand"`). → 두 군데 모두 "붙일 내용이 실제로 있을 때만 공백+내용을 붙이는" 조건을 추가해서 해결. 같은 버그 패턴이 두 군데(단위, 십의 자리)에 독립적으로 있었다는 게 포인트 — 하나 고쳤다고 다른 곳도 저절로 고쳐지지 않았다.
