# [프로그래머스 42884] 단속카메라 — 정렬 + 그리디로 최소 구간 커버

- 문제 번호: 42884
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42884
- 분류: 탐욕법(Greedy)
- 사용 자료구조/알고리즘: **정렬 + 탐욕법**
- 난이도 체감: Lv.3 (그리디의 정당성을 증명하는 부분이 핵심)

## 1. 문제 요약

각 차량의 이동 구간(`routes[i] = [진입, 진출]`)이 주어질 때, **모든 구간에 최소 한 점씩은 포함되도록** 하는 카메라(점)의 최소 개수를 구한다. 전형적인 "구간 점 커버(Interval Point Cover)" 문제다.

```text
routes=[[-20,-15],[-14,-5],[-18,-13],[-5,-3]]
→ -15에 카메라 하나(1,3번째 차량 커버), -5에 카메라 하나(2,4번째 차량 커버) → 2대
```

**제한사항**: 차량 1~10,000대, 좌표 -30,000~30,000.

## 2. 접근 아이디어 — 진출 지점 기준 정렬 후, 못 커버된 구간의 끝에 카메라

구간들을 **진출 지점(끝점) 기준 오름차순**으로 정렬한다. 그 다음 앞에서부터 순회하며, 지금까지 설치한 마지막 카메라 위치(`last`)가 현재 구간을 못 커버하면(`last < 구간의 시작`), **이 구간의 끝점**에 새 카메라를 설치한다.

### 왜 "끝점에" 설치하는 게 최적인가

지금 처리 중인 구간을 커버할 카메라를 놓아야 하는데, 그 카메라는 **앞으로 나올 다른 구간들도 최대한 많이 겹쳐서 커버**할수록 이득이다. 구간들이 진출 지점 기준으로 정렬돼 있으므로, 지금 구간의 끝점은 **이 구간을 커버하는 위치 중 가장 오른쪽(뒤쪽)** 지점이다. 가장 뒤쪽에 카메라를 놓아야, 이후에 나올(끝점이 더 크거나 같은) 다른 구간들과 겹칠 가능성이 가장 커진다. 만약 이 구간의 끝점보다 앞쪽에 카메라를 놓으면, 뒤에 나올 구간들을 놓칠 수 있는 손해만 있고 얻는 게 없다 — 그래서 "이 구간의 끝점"이 항상 최선의 선택이다.

### 왜 "이미 커버된 구간은 건너뛰어도" 되는가

`last`(마지막 카메라 위치)가 현재 구간의 시작점 이상이라면(`last >= r[0]`), 정렬 순서상 `last <= 현재 구간의 끝점`도 항상 보장된다(현재 구간의 끝점이 지금까지 본 것 중 가장 크므로). 즉 `last`가 이미 `[r[0], r[1]]` 안에 들어있다는 뜻이라 별도 처리 없이 통과시켜도 된다.

### 손으로 시뮬레이션 — `routes=[[-20,-15],[-14,-5],[-18,-13],[-5,-3]]`

끝점 기준 정렬: `[-20,-15], [-18,-13], [-14,-5], [-5,-3]`

| 구간 | last(현재 카메라) | 커버됨? | 처리 |
|---|---|---|---|
| [-20,-15] | (없음) | 아니오 | -15에 카메라 설치, `last=-15`, 카메라 1대 |
| [-18,-13] | -15 | 예 (`-15 ∈ [-18,-13]`) | 건너뜀 |
| [-14,-5] | -15 | 아니오 (`-15 < -14`) | -5에 카메라 설치, `last=-5`, 카메라 2대 |
| [-5,-3] | -5 | 예 (`-5 ∈ [-5,-3]`) | 건너뜀 |

최종 카메라 2대. 정답과 일치.

## 3. 코드 (Java)

```java
import java.util.Arrays;
import java.util.Comparator;

class Solution {
    public int solution(int[][] routes) {
        Arrays.sort(routes, Comparator.comparingInt(r -> r[1])); // 진출 지점 기준 정렬

        int answer = 0;
        int last = Integer.MIN_VALUE; // 아직 카메라 없음

        for (int[] r : routes) {
            if (last < r[0]) {       // 현재 카메라로 이 구간을 못 커버함
                last = r[1];          // 이 구간의 끝점에 새 카메라 설치
                answer++;
            }
        }

        return answer;
    }
}
```

### 코드 설명

- `Comparator.comparingInt(r -> r[1])`로 진출 지점 기준 오름차순 정렬.
- `last`는 "지금까지 설치한 카메라 중 가장 최근(가장 뒤쪽) 위치"를 나타낸다.
- `last < r[0]`이면 현재 카메라가 이 구간의 시작보다도 앞에 있다는 뜻 — 즉 이 구간을 전혀 커버하지 못하므로 새 카메라가 필요하다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n log n)` — 정렬이 지배적. 이후 순회는 `O(n)`.
- **공간복잡도**: `O(1)` 추가 공간 (정렬 자체의 내부 비용 제외).

실측(`n = 10,000`, 무작위 데이터): **약 3.3ms**.

## 5. 검증

작은 `n`(최대 6)에서, **후보 지점들의 모든 조합을 늘려가며 실제로 커버 가능한 최소 개수를 찾는 완전탐색 브루트포스**와 300회 무작위 데이터로 대조해서 전부 일치함을 확인했다. 공식 예시도 통과한다.

## 6. 엣지 케이스

- 진입점과 진출점이 같은 구간(`[5,5]`, 그 지점에 카메라가 있으면 만난 것으로 간주): 정상적으로 하나의 점으로 처리된다.
- 모든 구간이 서로 겹치는 경우: 가장 먼저(끝점 기준 가장 작은) 처리되는 구간의 끝점 하나로 전부 커버되어 카메라 1대.
- 모든 구간이 전혀 안 겹치는 경우: 구간 수만큼 카메라가 필요.
