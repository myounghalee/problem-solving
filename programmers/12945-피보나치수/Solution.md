# [프로그래머스 12945] 피보나치 수 — DP로 지수 시간 재귀를 O(n)으로

- 문제 번호: 12945
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12945
- 분류: 연습문제
- 사용 자료구조/알고리즘: **DP (동적 계획법)**, 점화식
- 난이도 체감: Lv.1~2 ([멀리 뛰기(12914)](../12914-멀리뛰기/Solution.md)와 사실상 동일한 문제)

## 1. 문제 요약

`F(0) = 0`, `F(1) = 1`, `F(n) = F(n-1) + F(n-2)` (n ≥ 2)로 정의되는 피보나치 수열에서, `n`번째 값을 `1234567`로 나눈 나머지를 구한다.

**제한사항**: `n`은 2 이상 100,000 이하의 자연수.

## 2. 접근 아이디어

점화식이 문제에 그대로 나와 있으므로 딱히 새로 유도할 게 없다. 관건은 **이 점화식을 어떻게 구현하느냐**다.

### 순수 재귀로 짜면 왜 안 되는가

[멀리 뛰기(12914)](../12914-멀리뛰기/Solution.md)에서 실측한 것과 똑같은 문제가 발생한다. `F(n) = F(n-1) + F(n-2)`를 그대로 재귀로 옮기면:

```java
// 시간 초과 나는 버전 — 이대로 제출 금지
public int solution(int n) {
    if (n <= 1) return n;
    return solution(n - 1) + solution(n - 2);
}
```

같은 부분 문제(`F(3)`, `F(4)`, ...)를 지수적으로 중복 계산해서 `O(φⁿ)` (φ≈1.618) 시간이 든다. 12914에서 실측한 표를 그대로 대입하면 `n=40`에서 이미 2억 번 호출에 189ms — 그런데 이 문제는 제한이 `n ≤ 100,000`이다. 12914(`n≤2,000`)보다도 상한이 50배 더 크므로, 재귀로는 절대 불가능하다는 게 더 명백하다.

추가로, 나머지 연산(`% 1234567`) 없이 그대로 더하면 `int`/`long` 오버플로우까지 겹쳐서 설령 기다린다 해도 값 자체가 틀어진다 — 이 부분도 12914와 동일한 함정이다.

### 해결책: 바텀업 DP + 공간 최적화

작은 인덱스부터 순서대로 값을 채워 올라가면서, **직전 두 값만 변수로 유지**한다. `F(i)`를 구하는 데 `F(i-1)`, `F(i-2)`만 있으면 충분하므로, 배열 전체를 저장할 필요가 없다 (`O(n)` 공간 → `O(1)` 공간).

### 손으로 시뮬레이션 — `n = 5`

`prev2 = F(0) = 0`, `prev1 = F(1) = 1`에서 시작해 `i = 2`부터 `n`까지 밀어 올린다.

| i | 계산 | prev2 (F(i-2)) | prev1 (F(i-1) → F(i)) |
|---|---|---|---|
| 시작 | - | 0 (`F(0)`) | 1 (`F(1)`) |
| 2 | `(1+0) % MOD = 1` | 1 | 1 (`F(2)`) |
| 3 | `(1+1) % MOD = 2` | 1 | 2 (`F(3)`) |
| 4 | `(2+1) % MOD = 3` | 2 | 3 (`F(4)`) |
| 5 | `(3+2) % MOD = 5` | 3 | 5 (`F(5)`) |

`prev1 = 5`. 문제 예시(`n=5 → 5`)와 일치한다.

## 3. 코드 (Java)

```java
class Solution {
    private static final int MOD = 1234567;

    public int solution(int n) {
        int prev2 = 0; // F(0)
        int prev1 = 1; // F(1)

        for (int i = 2; i <= n; i++) {
            int current = (prev1 + prev2) % MOD;
            prev2 = prev1;
            prev1 = current;
        }

        return prev1;
    }
}
```

### 코드 설명

- `prev2`/`prev1`을 `F(0)`, `F(1)`로 초기화하고, `i=2`부터 `n`까지 한 칸씩 밀어 올린다. 루프가 끝났을 때 `prev1`이 정확히 `F(n)`이 된다.
- 매 단계 `% MOD`를 적용해서, [멀리 뛰기(12914)](../12914-멀리뛰기/Solution.md)에서 설명한 것과 같은 이유로 오버플로우를 막는다 — 나머지를 매 단계 취해도 최종 나머지 값은 수학적으로 동일하다 (모듈러 연산의 분배 법칙).
- 반환 타입이 `int`인 이유: 프로그래머스가 제공하는 함수 시그니처 자체가 `int solution(int n)`이고, 모듈러 연산 결과(`< 1,234,567`)는 항상 `int` 범위 안에 들어오므로 `long`이 필요 없다. (참고: 12914는 시그니처가 `long`이라 그쪽은 `long`을 썼다.)

## 4. 복잡도 분석

- **시간복잡도**: `O(n)` — 반복문 한 번. `n ≤ 100,000`이므로 여유롭게 통과.
- **공간복잡도**: `O(1)` — 변수 2개만 사용.

## 5. 엣지 케이스

- `n = 2` (최솟값): 루프가 한 번만 돌아 `F(2) = 1`을 바로 반환.
- `n = 100,000` (최댓값): 실측 결과 `0ms`대로 즉시 처리됨.

## 6. 관련 문제

- [멀리 뛰기 (12914)](../12914-멀리뛰기/Solution.md) — **점화식이 완전히 동일**한 문제(`f(n) = f(n-1) + f(n-2)`). 이 문제의 `F(n)`과 12914의 `f(n)`은 `f(n) = F(n+1)` 관계다 (인덱스만 하나 밀려 있음). 같은 코드에 기저 조건과 반환 타입만 맞추면 바로 재사용 가능.
- [괄호 변환 (60058)](../60058-괄호변환/Solution.md) — 재귀가 불가피했던 문제. 이 문제와 대조하면 "언제 재귀를 반복문으로 바꿔야 하는지" 감을 잡기 좋다.
- [땅따먹기 (12913)](../12913-땅따먹기/Solution.md) — 같은 "직전 상태만 기억하는 DP" 계열이지만, 상태가 값 하나가 아니라 열 4개짜리 배열로 확장된 형태.
