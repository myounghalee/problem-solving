# [프로그래머스 42626] 더 맵게 — 최소 힙으로 "가장 작은 두 개"를 반복해서 섞기

- 문제 번호: 42626
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42626
- 분류: 힙(Heap)
- 사용 자료구조/알고리즘: **최소 힙(PriorityQueue) + 탐욕법**
- 난이도 체감: Lv.2 (아이디어는 직관적, 종료 조건 순서만 조심하면 됨)

## 1. 문제 요약

`scoville` 배열에서 **가장 작은 두 값**을 반복해서 `min1 + min2*2` 공식으로 섞어 하나로 합친다. **모든 음식의 스코빌 지수가 K 이상**이 될 때까지 걸리는 최소 섞기 횟수를 구한다. 불가능하면 `-1`.

```text
scoville=[1,2,3,9,10,12], K=7
1,2 섞음 → 5   → [5,3,9,10,12]
3,5 섞음 → 13  → [13,9,10,12]
최솟값 9 ≥ 7 → 2회 만에 완료
```

**제한사항**: 길이 2~1,000,000, `K` 0~1,000,000,000, 원소 0~1,000,000.

## 2. 접근 아이디어 — 왜 "가장 작은 두 개"를 먼저 섞는 그리디가 최적인가

직관적으로, **가장 작은 값들이 K 미만으로 남아있는 게 가장 큰 걸림돌**이다. 그 작은 값들을 그대로 두면 계속 K 미만으로 남으니, 매번 가장 작은 두 개를 먼저 처리해서 값을 키워주는 게 "K 미만인 값의 개수를 가장 빠르게 줄이는" 방향이다.

조금 더 엄밀하게 보면: 어차피 모든 음식을 섞어서 K 이상으로 만들어야 하는데, 섞는 횟수를 최소화하려면 **한 번 섞을 때 최대한 많은 "작은 값들"을 빠르게 처리**해야 한다. 큰 값을 작은 값과 섞으면 그 큰 값도 "소모"되어버려 아깝다 — 작은 값끼리 먼저 처리해서 큰 값들은 그대로 아껴두는 편이 전체 섞기 횟수를 최소로 만든다 (이미 K 이상인 값은 건드릴 필요가 없다는 것과 같은 맥락).

**매번 "가장 작은 두 값"을 빠르게 찾아야 하므로 최소 힙**이 적합하다 — [야근 지수(12927)](../12927-야근지수/Solution.md)에서 "매번 가장 큰 값"을 찾기 위해 최대 힙을 썼던 것과 정확히 대칭이다.

### 손으로 시뮬레이션 — `scoville=[1,2,3,9,10,12], K=7`

최소 힙 `[1,2,3,9,10,12]`에서 시작.

| 단계 | 힙에서 꺼낸 두 값 | 새로 만든 값 | 힙 상태 | 최솟값 ≥ K? |
|---|---|---|---|---|
| 1 | 1, 2 | `1+2*2=5` | [3,5,9,10,12] | 최솟값 3, 아직 아님 |
| 2 | 3, 5 | `3+5*2=13` | [9,10,12,13] | 최솟값 9 ≥ 7 → **종료** |

2회 만에 완료. 정답과 일치.

## 3. 코드 (Java)

```java
import java.util.PriorityQueue;
import java.util.Queue;

class Solution {
    public int solution(int[] scoville, int K) {
        int answer = 0;
        Queue<Integer> heap = new PriorityQueue<>(); // 기본이 최소 힙
        for (int s : scoville) heap.offer(s);

        while (!heap.isEmpty()) {
            if (heap.peek() >= K) return answer;   // 이미 전부 K 이상이면 종료
            if (heap.size() < 2) break;              // 더 섞을 짝이 없으면 실패

            int first = heap.poll();
            int second = heap.poll();
            heap.add(first + second * 2);
            answer++;
        }

        return -1; // 끝까지 K 이상을 못 만든 경우
    }
}
```

### 코드 설명

- `PriorityQueue<>()`는 기본이 **최소 힙**이라 별도 설정 없이 그대로 쓴다 (12927처럼 최댓값이 필요할 때만 `Collections.reverseOrder()`가 필요했다).
- **종료 조건 순서가 중요하다**: 매 반복마다 `heap.peek() >= K`(성공 여부)를 **먼저** 확인하고, 그다음 `heap.size() < 2`(더 이상 섞을 수 없음)를 확인한다. 이 순서 덕분에 "마지막 남은 하나가 이미 K 이상인 경우"와 "마지막 남은 하나가 K 미만이라 실패하는 경우"가 정확히 구분된다.
- 섞을 때마다 `answer++`로 횟수를 센다. 루프를 정상적으로 빠져나오지 못하고(`break`) 그대로 아래로 내려오면 `-1`을 반환한다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n log n)` — 최초 `n`개를 힙에 넣는 데 `O(n log n)`, 이후 최악 `n-1`번의 섞기 각각 `O(log n)`(poll 2번 + add 1번).
- **공간복잡도**: `O(n)` — 힙 크기.

실측(`n = 1,000,000`, 무작위 데이터):
- `K`를 매우 크게 잡아 거의 끝까지 섞어야 하는 최악에 가까운 경우: **약 317ms**
- 현실적인 `K`(100만): **약 210ms**

둘 다 일반적인 시간 제한(1초 안팎) 안에 들어온다.

## 5. 검증

공식 예시 통과. 추가로 다음 케이스들을 확인했다.

- 불가능한 경우(`-1`): `[1,1,1]`, `K=10억` → `-1`
- `K=0`: 모든 값이 이미 `0 ≥ 0`이라 즉시 `0`회
- 이미 전부 `K` 이상인 경우: 섞지 않고 즉시 `0`회
- 정확히 마지막 한 번의 섞기로 `K`에 딱 도달하는 경우(`[1,2], K=5` → `1+2*2=5`): `1`회

## 6. 엣지 케이스

- 원소가 정확히 2개뿐인 배열: 섞기가 최대 1번만 가능 — 그걸로 `K`를 못 넘기면 바로 `-1`.
- `K = 0`: 스코빌 지수가 0인 음식도 `0 ≥ 0`이라 이미 조건을 만족한다 — 별도 처리 없이 `peek() >= K` 체크만으로 자연스럽게 처리됨.
- `scoville`의 모든 원소가 같은 값인 경우: 계속 같은 방식으로 섞이며 값이 커지므로, 언젠가 K를 넘거나(성공) 원소가 1개로 줄어들 때까지(실패 가능) 반복된다.
