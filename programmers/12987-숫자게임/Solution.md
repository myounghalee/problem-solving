# [프로그래머스 12987] 숫자 게임 — 정렬 + 그리디로 "버려도 되는 패" 골라내기

- 문제 번호: 12987
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12987
- 분류: Summer/Winter Coding(~2018)
- 사용 자료구조/알고리즘: **정렬 + 탐욕법(Greedy)**
- 난이도 체감: Lv.3 (그리디가 왜 최적인지 증명하는 부분이 핵심)

## 1. 문제 요약

A팀의 출전 순서(배열 `A`)는 이미 공개되어 있고, B팀은 자신들의 숫자(배열 `B`)를 원하는 순서로 배치할 수 있다. `A[i] < B[j]`로 짝지어지는 쌍마다 B팀이 1승을 얻는다. B팀이 얻을 수 있는 **최대 승수**를 구한다.

```text
A=[5,1,3,7], B=[2,2,6,8] → 3
(8이 5를 이기고, 6이 3을 이기고, 2가 1을 이겨서 3승. 7은 아무 B로도 못 이김)
```

**제한사항**: `A`, `B` 길이 동일, 1~100,000, 각 원소 1~1,000,000,000.

## 2. 접근 아이디어 — 순서는 상관없다, 매칭 문제로 바꿔서 생각하기

A의 "출전 순서"는 사실 승패 계산에 영향이 없다 — B가 순서를 완전히 자유롭게 정할 수 있으므로, 결국 이 문제는 **"A의 원소들과 B의 원소들을 1:1로 짝지을 때, `B값 > A값`인 쌍이 최대 몇 개가 되도록 짝지을 수 있는가"**라는 매칭 문제와 동일하다.

### 왜 정렬 후 그리디가 최적인가

`A`, `B`를 각각 오름차순 정렬한다. **가장 작은 `A`부터** 순서대로, 지금 남아있는 `B` 중 아직 안 쓴 것들을 앞에서부터 확인하며 **자신을 이길 수 있는 첫 번째 `B`**를 찾는다.

- 그 `B`를 만나면: 승리로 확정하고, 그 `B`는 소모한다.
- 그 전에 만난 `B`들(자신보다 작거나 같은 값들)은 버린다(다시는 쓰지 않음).

**"버린 `B`를 다시는 쓰지 않아도 되는 이유"**: 지금 처리 중인 `A`값을 `a`라 하고, 그보다 작거나 같아서 버려진 `B`값을 `b`라 하자(`b ≤ a`). 이후에 처리할 `A`값들은 정렬돼 있으므로 전부 `a` 이상이다. 즉 앞으로 만날 어떤 `a'`에 대해서도 `b ≤ a ≤ a'`이 성립하므로, `b`는 `a'`도 절대 이길 수 없다. **한 번 버려진 `B`는 그 어떤 남은 `A`도 이길 수 없다는 게 수학적으로 보장**되므로, 안심하고 영구히 버려도 된다.

### 손으로 시뮬레이션 — `A=[5,1,3,7], B=[2,2,6,8]`

정렬: `A=[1,3,5,7]`, `B=[2,2,6,8]`

| 처리 중인 A | B 포인터가 훑는 값 | 판정 | 결과 |
|---|---|---|---|
| 1 | B[0]=2 | `1<2` → 승리 | 1승, B 포인터 1로 이동 |
| 3 | B[1]=2 | `3<2`? 아니오 → 버림, 다음 확인 | B 포인터 2로 이동 |
| 3 (계속) | B[2]=6 | `3<6` → 승리 | 2승, B 포인터 3으로 이동 |
| 5 | B[3]=8 | `5<8` → 승리 | 3승, B 포인터 4로 이동 |
| 7 | (B 소진) | 더 볼 게 없음 | 매칭 실패 |

최종 3승. 정답과 일치. (문제 설명의 "8,2,6,2 순서로 3점"과는 배치 방식이 다르지만, 최댓값 자체는 동일하게 나온다.)

## 3. 코드 (Java)

```java
import java.util.Arrays;

class Solution {
    public int solution(int[] A, int[] B) {
        Arrays.sort(A);
        Arrays.sort(B);

        int answer = 0;
        int i = 0; // B를 훑는 포인터

        for (int a : A) {
            while (i < B.length) {
                int b = B[i];
                i++;
                if (a < b) {
                    answer++;
                    break; // 이 a는 이겼으니 다음 a로
                }
                // a >= b인 경우: 이 b는 버리고 다음 b를 계속 확인
            }
        }

        return answer;
    }
}
```

### 코드 설명

- `A`, `B`를 각각 오름차순 정렬한다.
- 바깥 `for`는 정렬된 `A`를 작은 값부터 순회한다.
- 안쪽 `while`은 `B` 포인터 `i`를 계속 전진시키면서, 지금 `a`를 이기는 첫 `b`를 찾는다. 찾으면 승수를 늘리고 `break`로 다음 `a`로 넘어간다. 이기지 못하는 `b`는 그냥 지나치며(`i++`) 버려진다 — 위에서 증명했듯 이렇게 버려도 손해가 없다.
- `i`는 바깥 루프를 넘나들며 **한 번도 되돌아가지 않는다** — 즉 `B`의 각 원소는 전체 실행에서 딱 한 번씩만 검사된다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n log n)` — 정렬이 지배적. 이후 매칭 과정은 `i`가 `0`에서 `n`까지 단조 증가만 하므로 `O(n)`.
- **공간복잡도**: `O(1)` 추가 공간 (정렬은 in-place 또는 `O(log n)`).

실측(`n = 100,000`, 무작위 데이터, 원소값 최대 `10억`): **약 22.3ms**.

## 5. 검증

작은 `n`(최대 6)에서 **B팀의 모든 배치 순열을 전수조사**하는 브루트포스와 3,000회 무작위 데이터로 대조해서 전부 일치함을 확인했다. 공식 예시 2개도 모두 통과한다.

## 6. 엣지 케이스

- `A`, `B`가 완전히 동일한 배열(예#2, `[2,2,2,2]` vs `[1,1,1,1]`): 아무리 배치해도 이길 수 없는 경우 → 0승.
- `A`의 모든 값이 `B`의 모든 값보다 작은 경우: `B`가 전부 이겨서 `n`승.
- 값이 같은 경우(`a == b`)는 **무승부(누구도 승점 없음)**이므로, 코드에서도 `a < b`(엄격한 부등호)만 승리로 센다 — `a == b`는 자연스럽게 "버려지는" 쪽으로 처리된다.
