# [프로그래머스 42747] H-Index — 정의를 풀어서 이해하고 정렬로 풀기

- 문제 번호: 42747
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42747
- 분류: 정렬 (Sorting)
- 사용 자료구조/알고리즘: **정렬**
- 난이도 체감: Lv.2 (알고리즘보다 **정의를 이해하는 게** 더 어려운 문제)

## 1. 문제 요약 — 정의부터 풀어서 이해하기

문제 원문: "h번 이상 인용된 논문이 h편 이상이고 나머지 논문이 h번 이하 인용되었다면 h의 최댓값이 H-Index"

이 문장이 헷갈리는 이유는 **h가 두 가지 역할(기준 인용 수, 그리고 논문 편수)을 동시에** 하기 때문이다. 쉬운 말로 다시 쓰면:

> "인용 횟수가 `h` 이상인 논문이 **최소 `h`편**은 있어야 한다" — 이걸 만족하는 **가장 큰 `h`**를 찾는 문제.

`h`는 "기준 인용 횟수"이면서 동시에 "그 기준을 넘는 논문이 몇 편 있어야 하는가"의 숫자이기도 해서, 마치 자기 자신과 비교하는 것 같은 느낌을 준다 — 이게 직관적으로 와닿지 않는 이유다.

### 예시로 감 잡기 — `citations = [3, 0, 6, 1, 5]`

`h = 3`이 답인 이유를 하나씩 확인해보면:
- 인용 횟수가 `3` 이상인 논문: `6, 5, 3` → **3편** (`h=3`편 이상 조건 만족)
- 나머지 논문: `1, 0` → 둘 다 `3` 이하 인용 (`h=3`번 이하 조건도 만족)

`h=4`는 왜 안 되는가?
- 인용 횟수가 `4` 이상인 논문: `6, 5` → **2편뿐** (`4`편이 안 됨 → 조건 실패)

즉 `h`를 계속 키워보다가, "그 기준을 넘는 논문 수"가 `h`보다 작아지는 순간 멈추면 된다.

**제한사항**: 논문 수 1~1,000편, 인용 횟수 0~10,000회.

## 2. 접근 아이디어 — 내림차순 정렬하면 한 번에 보인다

인용 횟수를 **내림차순**으로 정렬하면, `i`번째(0-indexed) 논문까지 본 시점에서 "지금까지 몇 편을 봤는가(`i+1`편)"와 "그 논문의 인용 수(`citations[i]`)"를 나란히 비교할 수 있다.

`citations[i] >= i+1`이 성립한다는 건 "인용 수 상위 `i+1`편 전부가 적어도 `i+1`번 이상 인용됐다"는 뜻이므로, `h = i+1`이 조건을 만족하는 후보가 된다. 이 조건이 **처음으로 깨지는 지점 직전까지**가 정답이다.

### 왜 "한 번 깨지면 그 뒤로 계속 깨지는지" (그래서 세는 방식이든 break든 상관없는 이유)

내림차순으로 정렬했으므로 `citations[i]`는 `i`가 커질수록 **줄어들거나 같고**, 반대로 `i+1`은 `i`가 커질수록 **항상 늘어난다**. 그래서 한 번이라도 `citations[i] < i+1`이 되면, 그 이후의 `j(>i)`에 대해서도 `citations[j] ≤ citations[i] < i+1 < j+1`이 항상 성립해 — **다시는 조건을 만족할 수 없다.** 그래서 조건을 만족하는 인덱스들은 항상 배열 앞쪽에 몰린 "구간(prefix)"을 이루고, 그 구간의 길이가 곧 H-Index다.

### 손으로 시뮬레이션 — `citations = [3, 0, 6, 1, 5]`

내림차순 정렬: `[6, 5, 3, 1, 0]`

| i (0-indexed) | citations[i] | i+1 | citations[i] ≥ i+1 ? |
|---|---|---|---|
| 0 | 6 | 1 | ✅ |
| 1 | 5 | 2 | ✅ |
| 2 | 3 | 3 | ✅ |
| 3 | 1 | 4 | ❌ (여기서부터 계속 실패) |
| 4 | 0 | 5 | ❌ |

조건을 만족한 개수 = **3** → H-Index = 3.

## 3. 코드 (Java)

```java
import java.util.Arrays;

class Solution {
    public int solution(int[] citations) {
        Arrays.sort(citations); // 오름차순 정렬

        int n = citations.length;
        int answer = 0;

        for (int i = 0; i < n; i++) {
            int citation = citations[n - 1 - i]; // 뒤에서부터 읽어서 내림차순처럼 사용
            if (citation >= i + 1) {
                answer++;
            }
        }

        return answer;
    }
}
```

### 코드 설명

- `Arrays.sort(citations)`는 **오름차순**으로만 정렬해준다. 내림차순이 필요하므로 `citations[n - 1 - i]`처럼 **뒤에서부터 읽는 방식**으로 내림차순 효과를 낸다 (배열을 따로 뒤집어 만들지 않아도 됨).
- `citations[i] >= i+1`을 만족할 때마다 `answer`를 1씩 늘린다. 앞서 설명했듯 조건을 만족하는 인덱스는 항상 배열 앞쪽에 몰려 있으므로, 실패하는 순간 `break`를 걸어도 되고 안 걸어도 결과는 같다 — 이 코드는 `break` 없이 끝까지 순회하며 세는 방식을 택했다 (`n ≤ 1,000`이라 성능 차이도 없음).
- `answer`가 곧 "조건을 만족하는 논문 편수"이자 **그대로 H-Index 값**이 된다. — 만족한 개수 `k`는 정확히 `citations[0..k-1] ≥ k`를 의미하므로 `h=k`가 유효한 최댓값이다.

## 4. 복잡도 분석

- **시간복잡도**: `O(n log n)` — 정렬이 지배적. 이후 순회는 `O(n)`.
- **공간복잡도**: `O(1)` 추가 공간 (정렬은 in-place 또는 `O(log n)`).

`n ≤ 1,000`이라 훨씬 단순한 `O(n²)` 브루트포스(모든 `h`를 `0`부터 `n`까지 시도하며 매번 전체를 세는 방식)도 통과하지만, 정렬 방식이 더 깔끔하고 일반적으로 권장된다.

## 5. 검증

문제 정의를 그대로 구현한 브루트포스 참조 코드(모든 `h`에 대해 "인용 수 ≥ h인 논문 개수 ≥ h"를 직접 확인)와 **5,000회 무작위 데이터로 대조 검증**해서 전부 일치함을 확인했다.

## 6. 엣지 케이스

- 모든 논문이 인용 0회 (`[0,0,0]`): 첫 번째 검사(`citations[i] >= 1`)부터 실패 → H-Index = 0.
- 논문이 1편이고 인용이 많은 경우 (`[100]`): `100 >= 1` 성립 → H-Index = 1 (논문 수 자체가 상한이 됨을 보여주는 예).
- 모든 논문이 서로 다른 매우 높은 인용 수를 가진 경우: 논문 수 `n`이 H-Index의 상한이 된다 (아무리 인용이 많아도 논문이 `n`편이면 H-Index는 `n`을 못 넘음).
